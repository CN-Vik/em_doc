下面给你一套**基于 STM32 MCU 的智能猫砂盆软件设计方案**。核心思想是：

> **不要把“清理、清空、复位、暂停、保护、去皮”写成一堆互相打架的 while 循环，而是做成：事件驱动 + 状态机 + 动作脚本引擎。**

这样后面加 APP、定时清理、童锁、多猫保护、电流保护，都不会乱。

---

# 1. 整体软件架构

建议分 5 层：

```c
应用业务层：
    猫如厕识别 / 自动清理 / 童锁 / APP命令 / 故障处理 / 自检

状态机层：
    待机 / 清理中 / 清空中 / 暂停 / 回退 / 故障 / 复位中

动作脚本层：
    清理动作脚本
    清空动作脚本
    抚平动作脚本
    复位动作脚本

服务层：
    按键服务 / LED服务 / 蜂鸣器服务 / 称重服务 / 电流检测 / 定时器服务 / WiFi通信服务

驱动层：
    GPIO / ADC / PWM / UART / I2C / HX711 / Flash / Motor Driver
```

推荐主循环结构：

```c
int main(void)
{
    bsp_init();          // GPIO、ADC、UART、定时器、PWM、Flash初始化
    app_init();          // 加载配置，初始化状态机
    self_check_start();  // 开机自检

    while (1)
    {
        key_service_task();       // 按键扫描，建议10~25ms调用一次
        weight_service_task();    // 称重滤波、稳定判断
        sensor_service_task();    // 热释电、垃圾桶在位、电流采样
        app_uart_task();          // 涂鸦/WiFi模块通信
        event_process_task();     // 处理按键/APP/传感器事件
        machine_fsm_task();       // 主状态机
        action_engine_task();     // 滚桶动作脚本执行
        led_buzzer_task();        // 指示灯和蜂鸣器
    }
}
```

重点：
**所有动作都不能用 delay 阻塞。**
比如“停止 3 秒”，不要写：

```c
motor_stop();
delay_ms(3000);
```

而是写成状态机里的 `WAIT_3000MS`，靠系统 tick 计时。

# 2. 主状态机设计

建议主状态分成这些：

```c
typedef enum
{
    SYS_STATE_POWER_ON = 0,       // 上电
    SYS_STATE_SELF_CHECK,         // 自检
    SYS_STATE_IDLE,               // 待机
```

# 3. 事件优先级设计

这个产品一定要有**事件优先级**，否则容易出现“正在清理时 APP 又发清空”“电流保护时又触发称重保护”的混乱。

建议优先级如下：

```text
最高优先级：
1. 严重故障停机
2. 电流保护
3. 称重保护 / 热释电保护
4. 手动暂停
5. RESET强制复位
6. APP/按键清理、清空、去皮
7. 自动如厕清理
8. 待机8小时自动清理
最低优先级：
9. 指示灯、蜂鸣器、状态上报
```

特别注意：

| 场景                                 | 处理                  |
| ---------------------------------- | ------------------- |
| 童锁开启时按 SCOOP / EMPTY / TARE / WiFi | 不执行，红灯慢闪 3 下，蜂鸣 3 下 |
| 清理过程中按 SCOOP                       | 暂停，再按继续，超过 10 秒自动继续 |
| 清理过程中按 EMPTY                       | 不响应，无声音无灯效          |
| 清空过程中按 EMPTY                       | 暂停，再按继续             |
| 清空过程中按 SCOOP                       | 不响应                 |
| 非待机状态收到去皮                          | 不响应                 |
| 垃圾桶不到位                             | 禁止清理/清空，上报故障        |
| 电流保护触发 10 次仍失败                     | 故障停机                |

# 4. 滚桶位置设计

你需求里有几个关键位置：

```text
复位位置
抚平位置
清理位置
清空位置
```

软件里建议定义成：

```c
typedef enum
{
    ROLL_POS_HOME = 0,      // 复位位置
    ROLL_POS_FLAT,          // 抚平位置
    ROLL_POS_CLEAN,         // 清理位置
    ROLL_POS_EMPTY,         // 清空位置
} roll_pos_t;
```

位置检测有三种方案：

## 方案 A：每个位置一个霍尔/光电/微动开关

最简单可靠：

```text
HOME位置传感器
FLAT位置传感器
CLEAN位置传感器
EMPTY位置传感器
```

优点：软件简单，抗累计误差。
缺点：传感器多，成本高。

## 方案 B：一个复位传感器 + 编码器计数

```text
开机先找 HOME
找到 HOME 后清零编码器
后面靠脉冲计数到达各个位置
```

例如：

```c
#define POS_HOME_COUNT    0
#define POS_FLAT_COUNT    1200
#define POS_CLEAN_COUNT   2500
#define POS_EMPTY_COUNT   3900
```

优点：成本适中。
缺点：电机打滑、堵转后位置可能偏，需要回零校准。

## 方案 C：一个复位开关 + 电机运行时间估算

不推荐量产使用。
因为猫砂多少、电机负载、电压变化都会导致位置误差。

建议量产用：

> **一个复位传感器 + 编码器计数**
> 或者
> **几个关键位置霍尔传感器**

# 5. 动作脚本引擎设计

你需求里的清理动作：

```text
复位位置 → 抚平位置 → 复位位置 → 清理位置 → 停止3秒 → 抚平位置 → 停止3秒 → 复位位置
```

不要直接写死成一串函数，而是做成“动作脚本”。

## 5.1 动作步骤类型

```c
typedef enum
{
    STEP_MOVE_TO_POS = 0,     // 运动到指定位置
    STEP_WAIT_MS,             // 等待一段时间
    STEP_TARE_WEIGHT,         // 称重去皮
    STEP_END,                 // 动作结束
} action_step_type_t;
```

## 5.2 单个动作步骤

```c
typedef struct
{
    action_step_type_t type;
    roll_pos_t target_pos;
    uint32_t wait_ms;
} action_step_t;
```

# 9. 动作引擎核心伪代码

```c
typedef enum
{
    ACTION_NONE = 0,
    ACTION_CLEAN,
    ACTION_EMPTY,
    ACTION_FLAT,
    ACTION_RESET,
} action_type_t;

typedef struct
{
    action_type_t action;
    const action_step_t *script;
    uint8_t step_index;

    uint8_t running;
    uint8_t paused;

    uint32_t step_start_time_ms;
} action_engine_t;

action_engine_t g_action;
```

启动动作：

```c
void action_start(action_type_t action)
{
    if (action == ACTION_CLEAN)
    {
        g_action.script = clean_action_script;
    }
    else if (action == ACTION_EMPTY)
    {
        g_action.script = empty_action_script;
    }
    else if (action == ACTION_FLAT)
    {
        g_action.script = flat_action_script;
    }
    else
    {
        return;
    }

    g_action.action = action;
    g_action.step_index = 0;
    g_action.running = 1;
    g_action.paused = 0;
    g_action.step_start_time_ms = get_ms();

    g_app.state = SYS_STATE_ACTION_RUNNING;

    buzzer_beep(1);
    led_set_green_on();
}
```

动作执行：

```c
void action_engine_task(void)
{
    if (!g_action.running)
        return;

    if (g_action.paused)
        return;

    const action_step_t *step = &g_action.script[g_action.step_index];

    switch (step->type)
    {
        case STEP_MOVE_TO_POS:
        {
            motor_move_to_position(step->target_pos);

            if (motor_is_arrived(step->target_pos))
            {
                motor_stop();
                g_action.step_index++;
                g_action.step_start_time_ms = get_ms();
            }
            break;
        }

        case STEP_WAIT_MS:
        {
            motor_stop();

            if (get_ms() - g_action.step_start_time_ms >= step->wait_ms)
            {
                g_action.step_index++;
                g_action.step_start_time_ms = get_ms();
            }
            break;
        }

        case STEP_TARE_WEIGHT:
        {
            weight_tare();
            g_action.step_index++;
            break;
        }

        case STEP_END:
        {
            motor_stop();
            g_action.running = 0;
            g_action.action = ACTION_NONE;
            g_app.state = SYS_STATE_IDLE;

            buzzer_beep(1);
            led_set_green_on();
            break;
        }

        default:
            break;
    }
}
```

# 10. 电机运动控制设计

```c
void motor_move_to_position(roll_pos_t target)
{
    int32_t current_pos = motor_get_position_count();
    int32_t target_pos  = motor_pos_table[target];

    if (current_pos < target_pos)
    {
        motor_forward();
    }
    else if (current_pos > target_pos)
    {
        motor_reverse();
    }
    else
    {
        motor_stop();
    }
}
```

建议每个动作都有超时保护：

```c
#define MOTOR_MOVE_TIMEOUT_MS   15000

if (get_ms() - g_motor.move_start_time > MOTOR_MOVE_TIMEOUT_MS)
{
    fault_set(FAULT_MOTOR_TIMEOUT);
}
```

否则传感器坏了，电机会一直转。

# 11. 如厕识别逻辑

需求：

```text
自动模式下
待机状态
重量增加 ≥800g 并保持 10秒以上
判定猫如厕

之后重量减轻 ≥800g
判定猫离开

猫离开后 5分钟，执行清理
```

状态设计：

```c
typedef enum
{
    TOILET_STATE_NONE = 0,
    TOILET_STATE_CAT_IN,
    TOILET_STATE_CAT_LEFT_WAIT_CLEAN,
} toilet_state_t;

typedef struct
{
    toilet_state_t state;
    int32_t base_weight_g;
    uint32_t weight_hold_start_ms;
    uint32_t cat_left_time_ms;
} toilet_detect_t;

toilet_detect_t g_toilet;
```

伪代码：

```c
void toilet_detect_task(void)
{
    if (g_app.work_mode != WORK_MODE_AUTO)
        return;

    if (g_app.state != SYS_STATE_IDLE)
        return;

    int32_t weight = weight_get_filtered();

    switch (g_toilet.state)
    {
        case TOILET_STATE_NONE:
        {
            if (weight - g_toilet.base_weight_g >= 800)
            {
                if (g_toilet.weight_hold_start_ms == 0)
                {
                    g_toilet.weight_hold_start_ms = get_ms();
                }

                if (get_ms() - g_toilet.weight_hold_start_ms >= 10000)
                {
                    g_toilet.state = TOILET_STATE_CAT_IN;
                    led_set_green_slow_flash();   // 宠物如厕：绿灯慢闪
                }
            }
            else
            {
                g_toilet.weight_hold_start_ms = 0;
            }
            break;
        }

        case TOILET_STATE_CAT_IN:
        {
            if (g_toilet.base_weight_g - weight >= 800 ||
                weight <= g_toilet.base_weight_g + 200)
            {
                g_toilet.state = TOILET_STATE_CAT_LEFT_WAIT_CLEAN;
                g_toilet.cat_left_time_ms = get_ms();
            }
            break;
        }

        case TOILET_STATE_CAT_LEFT_WAIT_CLEAN:
        {
            uint32_t delay_ms = g_config.auto_clean_delay_min * 60 * 1000;

            if (get_ms() - g_toilet.cat_left_time_ms >= delay_ms)
            {
                event_post(EVENT_AUTO_CLEAN);
                g_toilet.state = TOILET_STATE_NONE;
                g_toilet.base_weight_g = weight_get_filtered();
            }
            break;
        }

        default:
            break;
    }
}
```

注意：

```text
执行滚桶动作时，不做如厕识别。
```

因为滚桶动作会导致称重波动。

# 12. 称重保护设计

需求：

```text
滚桶运行时，2秒内重量增加 ≥500g
认为猫进入或外界干扰
滚桶暂停

滚桶停转后重量减轻 ≥500g
认为干扰解除
2秒后恢复上一状态
```

建议加一点滞回，避免重量抖动导致反复暂停/恢复。

```c
typedef struct
{
    int32_t motor_start_weight_g;
    uint32_t protect_start_ms;
    uint8_t active;
} weight_protect_t;

weight_protect_t g_weight_protect;
```

滚桶开始运动时记录基准重量：

```c
void on_motor_start(void)
{
    g_weight_protect.motor_start_weight_g = weight_get_filtered();
    g_weight_protect.protect_start_ms = get_ms();
}
```

检测逻辑：

```c
void weight_protect_task(void)
{
    if (g_app.state != SYS_STATE_ACTION_RUNNING)
        return;

    int32_t weight = weight_get_filtered();
    int32_t diff = weight - g_weight_protect.motor_start_weight_g;

    if (diff >= 500)
    {
        motor_stop();

        g_weight_protect.active = 1;
        g_app.state = SYS_STATE_PROTECT_PAUSE;

        led_set_yellow_slow_flash();

        report_fault_to_app(APP_WARN_WEIGHT_PROTECT);
    }
}
```

恢复逻辑：

```c
void weight_protect_resume_task(void)
{
    if (g_app.state != SYS_STATE_PROTECT_PAUSE)
        return;

    if (!g_weight_protect.active)
        return;

    int32_t weight = weight_get_filtered();

    if (weight <= g_weight_protect.motor_start_weight_g + 100)
    {
        if (stable_for_2s())
        {
            g_weight_protect.active = 0;
            g_app.state = SYS_STATE_ACTION_RUNNING;
            action_resume();
        }
    }
}
```

# 13. 热释电保护设计

需求：

```text
滚桶运行时，到达抚平位置，需要继续运动时
如果热释电检测到运动热源
滚桶暂停
黄灯慢闪
干扰解除 2秒后恢复
```

关键点是：

> 不是任何时候检测到 PIR 都停，而是在“抚平位置准备继续动”的时候重点判断。

可以在动作引擎里加检查：

```c
uint8_t can_continue_from_flat_position(void)
{
    if (motor_current_position() == ROLL_POS_FLAT)
    {
        if (pir_detect_motion())
        {
            motor_stop();

            g_app.state = SYS_STATE_PROTECT_PAUSE;
            g_app.pir_protect_active = 1;

            led_set_yellow_slow_flash();
            report_fault_to_app(APP_WARN_PIR_PROTECT);

            return 0;
        }
    }

    return 1;
}
```

恢复：

```c
void pir_protect_resume_task(void)
{
    if (!g_app.pir_protect_active)
        return;

    if (!pir_detect_motion())
    {
        if (stable_for_2s())
        {
            g_app.pir_protect_active = 0;
            g_app.state = SYS_STATE_ACTION_RUNNING;
            action_resume();
        }
    }
}
```

# 14. 电流保护设计

需求：

```text
滚桶运行时
电流达到保护阈值
1秒内滚桶停止
回退2秒
停顿10秒
再次尝试运行
循环10次
仍不能解除则报错停机
```

建议电流检测分两级：

```text
普通过载阈值：持续 1秒触发保护
严重堵转阈值：立即停机，例如 100~200ms 触发
```

结构体：

```c
typedef struct
{
    uint16_t current_ma;
    uint32_t over_current_start_ms;

    uint8_t retry_count;
    uint8_t active;

    uint32_t backoff_start_ms;
    uint32_t wait_start_ms;
} current_protect_t;

current_protect_t g_current_protect;
```

检测逻辑：

```c
#define MOTOR_CURRENT_LIMIT_MA      2500
#define MOTOR_CURRENT_STALL_MA      4000
#define CURRENT_PROTECT_TIME_MS     1000
#define CURRENT_BACKOFF_TIME_MS     2000
#define CURRENT_WAIT_TIME_MS        10000
#define CURRENT_RETRY_MAX           10

void current_protect_task(void)
{
    if (g_app.state != SYS_STATE_ACTION_RUNNING)
        return;

    uint16_t current = motor_current_get_ma();

    if (current >= MOTOR_CURRENT_STALL_MA)
    {
        current_protect_trigger();
        return;
    }

    if (current >= MOTOR_CURRENT_LIMIT_MA)
    {
        if (g_current_protect.over_current_start_ms == 0)
        {
            g_current_protect.over_current_start_ms = get_ms();
        }

        if (get_ms() - g_current_protect.over_current_start_ms >= CURRENT_PROTECT_TIME_MS)
        {
            current_protect_trigger();
        }
    }
    else
    {
        g_current_protect.over_current_start_ms = 0;
    }
}
```

触发保护：

```c
void current_protect_trigger(void)
{
    motor_stop();

    g_current_protect.retry_count++;

    if (g_current_protect.retry_count > CURRENT_RETRY_MAX)
    {
        motor_stop();
        fault_set(FAULT_MOTOR_OVER_CURRENT);
        return;
    }

    g_app.state = SYS_STATE_CURRENT_BACKOFF;
    g_current_protect.backoff_start_ms = get_ms();

    motor_reverse();   // 回退
}
```

回退状态：

```c
void current_backoff_task(void)
{
    if (g_app.state != SYS_STATE_CURRENT_BACKOFF)
        return;

    if (get_ms() - g_current_protect.backoff_start_ms < CURRENT_BACKOFF_TIME_MS)
    {
        motor_reverse();
        return;
    }

    motor_stop();

    if (g_current_protect.wait_start_ms == 0)
    {
        g_current_protect.wait_start_ms = get_ms();
    }

    if (get_ms() - g_current_protect.wait_start_ms >= CURRENT_WAIT_TIME_MS)
    {
        g_current_protect.wait_start_ms = 0;
        g_app.state = SYS_STATE_ACTION_RUNNING;
        action_resume();
    }
}
```

如果 10 次都失败：

```c
void fault_set(uint32_t fault)
{
    motor_stop();

    g_app.state = SYS_STATE_FAULT;
    g_app.current_fault = fault;

    led_set_red_slow_flash();
    buzzer_fault_start();

    report_fault_to_app(fault);
}
```

你备注里说“添加 5kg 猫砂抓电流数据”，这个非常重要。建议实际标定：

```text
空桶运行电流
加 2kg 猫砂运行电流
加 5kg 猫砂运行电流
模拟轻微卡砂电流
模拟严重堵转电流
```

然后设置：

```text
正常最大运行电流 = 5kg猫砂最大电流
保护阈值 = 正常最大运行电流 + 20%~30%
堵转阈值 = 明显异常电流
```

# 22. 开机自检设计

需求：

```text
每次开机后：
1. 检测所有传感器是否正常
2. 检测滚桶是否复位
3. 如果不是复位状态，自动执行复位动作
```

建议流程：

```text
上电
 ↓
初始化 MCU 外设
 ↓
读取 Flash 配置
 ↓
检查称重模块是否有数据
 ↓
检查电流 ADC 是否正常
 ↓
检查垃圾桶检测 IO
 ↓
检查热释电输入
 ↓
检查滚桶位置
 ↓
如果不在 HOME，执行复位动作
 ↓
进入待机
```

伪代码：

```c
void self_check_task(void)
{
    g_app.state = SYS_STATE_SELF_CHECK;

    if (!weight_sensor_check())
    {
        fault_set(FAULT_WEIGHT_SENSOR);
        return;
    }

    if (!current_sensor_check())
    {
        fault_set(FAULT_CURRENT_SENSOR);
        return;
    }

    if (!position_sensor_check())
    {
        fault_set(FAULT_POSITION_SENSOR);
        return;
    }

    if (!motor_is_at_home())
    {
        action_reset_to_home_start();
        return;
    }

    g_app.state = SYS_STATE_IDLE;
    led_set_green_on();
}
```

注意：

```text
普通开机复位，建议保留电流保护。
RESET键强制复位，才屏蔽压力、红外、电流保护。
```

因为如果开机时桶被卡死，完全屏蔽电流保护会有烧电机风险。

# 23. RESET 强制复位

需求：

```text
RESET键长按3秒
设备重置
滚桶复位
强制复位时屏蔽压力、红外、电流保护
未完成前再次按键不响应
开始和完成蜂鸣1下
```

可以设计：

```c
void action_force_reset_start(void)
{
    if (g_app.state == SYS_STATE_ACTION_RUNNING ||
        g_app.state == SYS_STATE_CURRENT_BACKOFF)
    {
        motor_stop();
    }

    g_force_reset.active = 1;
    g_force_reset.ignore_weight_protect = 1;
    g_force_reset.ignore_pir_protect = 1;
    g_force_reset.ignore_current_protect = 1;
```

更安全的做法：

```text

```

否则桶卡住时一直强制转，风险很大。

# 29. 最容易踩坑的地方

## 1. 不要在动作中使用阻塞 delay

错误写法：

```c
motor_stop();
delay_ms(3000);
motor_forward();
```

问题是这 3 秒内你检测不到按键、电流、称重、热释电。

正确做法：

```c
STEP_WAIT_MS, 3000
```

让动作引擎慢慢跑。

---

## 2. 电流保护不能只看一次 ADC

电机启动瞬间有冲击电流。
所以普通过流要“持续 1 秒”再触发。

但是严重堵转电流可以快速保护。

---

## 3. 称重识别必须做滤波

HX711 或压力传感器会抖。
建议：

```text
滑动平均滤波
中值滤波
稳定时间判断
滞回判断
```

例如：

```text
猫进入：增加 ≥800g 持续10秒
猫离开：重量回落到基准附近，并稳定2秒
```

---

## 4. 自动去皮要谨慎

用户加猫砂时重量变化很大。
但是猫进去也会重量变化。

所以自动去皮必须限制在：

```text
待机状态
没有如厕事件
没有滚桶动作
重量变化持续超过3分钟
```

---

## 5. 故障状态要分“可恢复”和“不可恢复”

建议：

| 故障          | 是否自动恢复       |
| ----------- | ------------ |
| 垃圾桶不到位      | 可以自动恢复       |
| 称重保护        | 可以自动恢复       |
| 热释电保护       | 可以自动恢复       |
| 电流保护 1~10 次 | 可以尝试恢复       |
| 电流保护超过 10 次 | 不自动恢复，需要用户处理 |
| 传感器损坏       | 不自动恢复        |
| 电机超时        | 不自动恢复        |

# 31. 最终核心设计总结

这套智能猫砂盆软件，建议按下面这个核心架构做：

```text
按键 / APP / 传感器
        ↓
事件系统
        ↓
主状态机
        ↓
动作脚本引擎
        ↓
电机位置控制
        ↓
保护系统实时监控
        ↓
LED / 蜂鸣器 / APP状态上报
```

核心原则：

```text
1. 清理、清空、抚平、复位全部做成动作脚本
2. 主程序不允许阻塞 delay
3. 电机运行时持续检测电流、称重、热释电
4. 所有 APP 和按键命令先进入事件系统
5. 童锁、模式、故障、WiFi 状态独立管理
6. 故障必须分类：可恢复 / 不可恢复
7. 位置控制必须有超时保护
8. 称重和电流都必须滤波和持续时间判断
```

你这个项目真正难的不是电机转，而是**各种异常情况不要互相打架**。
所以先把状态机和动作脚本搭起来，再逐个加称重、热释电、电流、APP、童锁，代码会清楚很多。

--------------
--------------
--------------
可以。我们先不急着写具体业务代码，先把**嵌入式 MCU 软件框架**搭清楚。

你这个智能猫砂盆项目，基于 STM32 MCU，典型特点是：

```text
按键多
APP 指令多
传感器多
电机动作流程复杂
保护逻辑多
状态灯和蜂鸣器交互多
异常状态多
```

所以软件框架一定不能写成：

```c
while (1)
{
    if (按键清理)
    {
        电机转到抚平位置;
        delay_ms(3000);
        电机转到清理位置;
        delay_ms(3000);
    }

    if (重量保护)
    {
        电机停止;
    }

    if (APP清空)
    {
        电机清空;
    }
}
```

这种代码前期能跑，后期一定乱。

正确思路是：

> **分层设计 + 模块化管理 + 事件驱动 + 状态机 + 非阻塞动作引擎。**

```text
└──────────────▲───────────────┘
               │
```

# 3. 最重要的原则：单向依赖

这是模块化设计的核心。

错误设计：

```text
drv_motor.c 调用 app_fault.c
app_clean.c 直接操作 GPIO
key_service.c 直接启动电机
uart_tuya.c 直接控制滚桶
```

这样会导致所有模块互相调用，最后谁也拆不开。

正确设计：

```text
APP层 可以调用 Service/Device
Service层 可以调用 Driver
Driver层 不允许反过来调用 APP
```

也就是：

```text
APP  →  Service  →  Device  →  Driver  →  HAL
```

底层不要知道上层业务。

比如电机驱动检测到过流，不要在 `drv_motor.c` 里直接写：

```c
app_fault_set(FAULT_OVER_CURRENT);
```

而是这样：

```c
drv_motor_get_current();
```

然后由上层的 `current_service.c` 或 `app_fault.c` 判断是否故障。

# 4. 主循环框架怎么写？

不使用 RTOS 的情况下，推荐用**超级循环 + 软件定时器 + 非阻塞任务**。

主循环类似这样：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();

    bsp_init();          // MCU外设初始化
    driver_init();       // 驱动初始化
    service_init();      // 服务模块初始化
    app_init();          // 业务初始化

    while (1)
    {
        service_task();  // 按键、称重、LED、蜂鸣器、事件队列
        device_task();   // 滚桶设备、传感器设备
        app_task();      // 主业务状态机
    }
}
```

展开以后：

```c
void service_task(void)
{
    key_service_task();
    weight_service_task();
    current_service_task();
    led_service_task();
    buzzer_service_task();
    event_service_task();
    timer_service_task();
    tuya_uart_service_task();
}

void device_task(void)
{
    roller_device_task();
    trashbox_device_task();
    pir_device_task();
}

void app_task(void)
{
    app_state_machine_task();
    app_action_task();
    app_fault_task();
    app_toilet_detect_task();
    app_child_lock_task();
    app_auto_clean_task();
}
```

注意一个重点：

> 每个 `xxx_task()` 都必须快速返回，不能卡住。

错误：

```c
void clean_task(void)
{
    motor_forward();
    HAL_Delay(3000);
    motor_stop();
}
```

正确：

```c
void clean_task(void)
{
    switch (clean_step)
    {
        case CLEAN_STEP_MOVE:
            motor_forward();
            if (到达位置)
            {
                clean_step = CLEAN_STEP_WAIT;
                wait_start_time = get_ms();
            }
            break;

        case CLEAN_STEP_WAIT:
            motor_stop();
            if (get_ms() - wait_start_time >= 3000)
            {
                clean_step = CLEAN_STEP_NEXT;
            }
            break;
    }
}
```

# 5. 为什么要事件驱动？

因为你的输入来源太多：

```text
按键清理
APP清理
自动清理
定时清理
如厕后清理
按键清空
APP清空
重量去皮
垃圾桶不到位
电流过载
热释电保护
童锁按键
WiFi重置
```

如果每个地方都直接操作业务，代码会乱。

应该统一变成事件：

```c
typedef enum
{
    EVENT_NONE = 0,

    EVENT_KEY_CLEAN,
    EVENT_KEY_EMPTY,
    EVENT_KEY_TARE,
    EVENT_KEY_RESET,

    EVENT_APP_CLEAN,
    EVENT_APP_EMPTY,
    EVENT_APP_TARE,
    EVENT_APP_RESET,

    EVENT_AUTO_CLEAN,
    EVENT_TOILET_CAT_IN,
    EVENT_TOILET_CAT_LEFT,

    EVENT_WEIGHT_PROTECT,
    EVENT_PIR_PROTECT,
    EVENT_CURRENT_PROTECT,

    EVENT_TRASHBOX_REMOVED,
    EVENT_TRASHBOX_INSTALLED,

    EVENT_CHILD_LOCK_ON,
    EVENT_CHILD_LOCK_OFF,

} app_event_t;
```

然后所有模块只负责投递事件：

```c
event_post(EVENT_KEY_CLEAN);
event_post(EVENT_APP_CLEAN);
event_post(EVENT_CURRENT_PROTECT);
```

主状态机统一处理事件：

```c
void app_event_process(app_event_t event)
{
    switch (event)
    {
        case EVENT_KEY_CLEAN:
        case EVENT_APP_CLEAN:
            app_request_clean();
            break;

        case EVENT_KEY_EMPTY:
        case EVENT_APP_EMPTY:
            app_request_empty();
            break;

        case EVENT_CURRENT_PROTECT:
            app_enter_current_protect();
            break;

        default:
            break;
    }
}
```

这样有个好处：

```text
按键模块不关心清理怎么做
APP模块不关心电机怎么转
保护模块不关心动作执行到哪一步
主状态机统一调度
```

# 7. 动作脚本引擎：解决清理/清空流程复杂的问题

你的动作流程是：

```text
清理：
复位位置 → 抚平位置 → 复位位置 → 清理位置 → 停3秒 → 抚平位置 → 停3秒 → 复位位置

清空：
复位位置 → 清空位置 → 停3秒 → 复位位置
```

这种非常适合做成“动作脚本”。

```c
typedef enum
{
    ACTION_STEP_MOVE_TO_POS,
    ACTION_STEP_WAIT_MS,
    ACTION_STEP_END,
} action_step_type_t;

typedef enum
{
    ROLLER_POS_HOME,
    ROLLER_POS_FLAT,
    ROLLER_POS_CLEAN,
    ROLLER_POS_EMPTY,
} roller_pos_t;

typedef struct
{
    action_step_type_t type;
    roller_pos_t target_pos;
    uint32_t wait_ms;
} action_step_t;
```

清理动作脚本：

```c
const action_step_t g_clean_script[] =
{
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_HOME,  0},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_FLAT,  0},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_HOME,  0},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_CLEAN, 0},
    {ACTION_STEP_WAIT_MS,     0,                3000},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_FLAT,  0},
    {ACTION_STEP_WAIT_MS,     0,                3000},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_HOME,  0},
    {ACTION_STEP_END,         0,                0},
};
```

清空动作脚本：

```c
const action_step_t g_empty_script[] =
{
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_HOME,  0},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_EMPTY, 0},
    {ACTION_STEP_WAIT_MS,     0,                3000},
    {ACTION_STEP_MOVE_TO_POS, ROLLER_POS_HOME,  0},
    {ACTION_STEP_END,         0,                0},
};
```

动作引擎只需要执行脚本，不关心这是清理还是清空。

```c
typedef struct
{
    const action_step_t *script;
    uint8_t step_index;
    uint8_t running;
    uint8_t paused;
    uint32_t step_start_time;
} action_engine_t;

static action_engine_t g_action;
```

执行逻辑：

```c
void action_engine_task(void)
{
    if (!g_action.running)
        return;

    if (g_action.paused)
        return;

    const action_step_t *step = &g_action.script[g_action.step_index];

    switch (step->type)
    {
        case ACTION_STEP_MOVE_TO_POS:
        {
            roller_move_to(step->target_pos);

            if (roller_is_arrived(step->target_pos))
            {
                roller_stop();
                g_action.step_index++;
                g_action.step_start_time = get_ms();
            }
            break;
        }

        case ACTION_STEP_WAIT_MS:
        {
            roller_stop();

            if (get_ms() - g_action.step_start_time >= step->wait_ms)
            {
                g_action.step_index++;
                g_action.step_start_time = get_ms();
            }
            break;
        }

        case ACTION_STEP_END:
        {
            roller_stop();
            g_action.running = 0;
            g_app.state = SYS_STATE_IDLE;
            buzzer_beep(1);
            led_set_normal();
            break;
        }

        default:
            break;
    }
}
```

这就是“非阻塞动作流程”。

```text

xxx.c：内部实现
```

比如按键模块：

```text
key_service.h
key_service.c
```

`key_service.h` 只暴露必要接口：

```c
#ifndef KEY_SERVICE_H
```

# 10. 驱动层怎么设计？

驱动层只做最基础的硬件控制。

比如电机驱动层 `drv_motor.c`：

```text
负责：
1. 设置方向 GPIO
2. 设置 PWM 占空比
3. 读取电流 ADC
4. 停止电机

不负责：
1. 清理流程
2. 清空流程
3. 电流保护重试10次
4. APP上报
5. 状态灯
```

电机驱动接口：

```c
#ifndef DRV_MOTOR_H
#define DRV_MOTOR_H

typedef enum
{
    MOTOR_DIR_FORWARD = 0,
    MOTOR_DIR_REVERSE,
} motor_dir_t;

void drv_motor_init(void);
void drv_motor_start(motor_dir_t dir, uint16_t speed);
void drv_motor_stop(void);
uint16_t drv_motor_get_current_ma(void);

#endif
```

实现：

```c
void drv_motor_start(motor_dir_t dir, uint16_t speed)
{
    if (dir == MOTOR_DIR_FORWARD)
    {
        HAL_GPIO_WritePin(MOTOR_DIR_GPIO_Port, MOTOR_DIR_Pin, GPIO_PIN_SET);
    }
    else
    {
        HAL_GPIO_WritePin(MOTOR_DIR_GPIO_Port, MOTOR_DIR_Pin, GPIO_PIN_RESET);
    }

    __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, speed);
    HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);
}

void drv_motor_stop(void)
{
    __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, 0);
}
```

这就是最底层驱动。

# 11. Device 层怎么设计？

Device 层比 Driver 高一级。

比如滚桶设备 `roller_device.c`：

```text
它知道：
1. 滚桶有 HOME / FLAT / CLEAN / EMPTY 这些位置
2. 如何转到某个位置
3. 如何判断是否到位
4. 如何处理电机运动超时

它不关心：
1. 是清理动作还是清空动作
2. APP命令从哪里来
3. 童锁是否开启
```

接口：

```c
#ifndef ROLLER_DEVICE_H
#define ROLLER_DEVICE_H

typedef enum
{
    ROLLER_POS_HOME = 0,
    ROLLER_POS_FLAT,
    ROLLER_POS_CLEAN,
    ROLLER_POS_EMPTY,
} roller_pos_t;

typedef enum
{
    ROLLER_STATE_IDLE = 0,
    ROLLER_STATE_MOVING,
    ROLLER_STATE_ARRIVED,
    ROLLER_STATE_TIMEOUT,
    ROLLER_STATE_ERROR,
} roller_state_t;

void roller_device_init(void);
void roller_device_task(void);

void roller_move_to(roller_pos_t pos);
void roller_stop(void);

uint8_t roller_is_arrived(roller_pos_t pos);
roller_state_t roller_get_state(void);

#endif
```

实现大概：

```c
typedef struct
{
    roller_pos_t target_pos;
    roller_state_t state;
    uint32_t move_start_time;
} roller_ctrl_t;

static roller_ctrl_t g_roller;
```

```c
void roller_move_to(roller_pos_t pos)
{
    g_roller.target_pos = pos;

    if (roller_is_arrived(pos))
    {
        drv_motor_stop();
        g_roller.state = ROLLER_STATE_ARRIVED;
        return;
    }

    if (need_forward_to(pos))
    {
        drv_motor_start(MOTOR_DIR_FORWARD, MOTOR_SPEED_NORMAL);
    }
    else
    {
        drv_motor_start(MOTOR_DIR_REVERSE, MOTOR_SPEED_NORMAL);
    }

    g_roller.state = ROLLER_STATE_MOVING;
    g_roller.move_start_time = get_ms();
}
```

```c
void roller_device_task(void)
{
    if (g_roller.state != ROLLER_STATE_MOVING)
        return;

    if (roller_is_arrived(g_roller.target_pos))
    {
        drv_motor_stop();
        g_roller.state = ROLLER_STATE_ARRIVED;
        return;
    }

    if (get_ms() - g_roller.move_start_time > ROLLER_MOVE_TIMEOUT_MS)
    {
        drv_motor_stop();
        g_roller.state = ROLLER_STATE_TIMEOUT;
        event_post(EVENT_ROLLER_TIMEOUT);
    }
}
```

这样，业务层只需要：

```c
roller_move_to(ROLLER_POS_CLEAN);
```

不需要关心底层 PWM、GPIO、霍尔传感器。

# 12. Service 层怎么设计？

Service 层处理通用逻辑。

比如 LED 驱动和 LED 服务的区别：

## 驱动层

```c
drv_led_set_rgb(255, 0, 0);
```

它只知道怎么点灯。

## 服务层

```c
led_set_effect(LED_EFFECT_RED_SLOW_FLASH);
```

它知道“红灯慢闪”这个灯效。

LED 服务接口：

```c
typedef enum
{
    LED_EFFECT_OFF = 0,
    LED_EFFECT_GREEN_ON,
    LED_EFFECT_GREEN_SLOW_FLASH,
    LED_EFFECT_YELLOW_ON,
    LED_EFFECT_YELLOW_SLOW_FLASH,
    LED_EFFECT_RED_SLOW_FLASH,
    LED_EFFECT_BLUE_ON,
    LED_EFFECT_BLUE_SLOW_FLASH,
} led_effect_t;

void led_service_init(void);
void led_service_task(void);
void led_set_effect(led_effect_t effect);
```

业务层调用：

```c
led_set_effect(LED_EFFECT_YELLOW_SLOW_FLASH);
```

LED 服务内部自己处理闪烁：

```c
void led_service_task(void)
{
    switch (g_led.effect)
    {
        case LED_EFFECT_RED_SLOW_FLASH:
            if (get_ms() - g_led.last_toggle_time >= 1000)
            {
                g_led.last_toggle_time = get_ms();
                g_led.toggle = !g_led.toggle;

                if (g_led.toggle)
                    drv_led_set_red();
                else
                    drv_led_off();
            }
            break;

        default:
            break;
    }
}
```

# 13. 称重模块怎么分层？

不要让业务层直接读 HX711。

推荐分三层：

```text
drv_hx711.c
    负责读原始 ADC 数值

weight_device.c
    负责把原始值转换成克

weight_service.c
    负责滤波、稳定判断、去皮、重量变化事件
```

接口：

```c
void weight_service_init(void);
void weight_service_task(void);

int32_t weight_get_current_g(void);
int32_t weight_get_filtered_g(void);

void weight_tare(void);
uint8_t weight_is_stable(void);
```

业务层只这样用：

```c
if (weight_get_filtered_g() > 800)
{
    // 认为猫进入
}
```

称重服务内部做滤波：

```c
#define WEIGHT_FILTER_SIZE  8

static int32_t weight_buf[WEIGHT_FILTER_SIZE];
static uint8_t weight_index;
static int32_t weight_filtered;
```

```c
void weight_service_task(void)
{
    int32_t raw = drv_hx711_read();

    int32_t gram = weight_raw_to_gram(raw);

    weight_buf[weight_index++] = gram;

    if (weight_index >= WEIGHT_FILTER_SIZE)
        weight_index = 0;

    weight_filtered = average_filter(weight_buf, WEIGHT_FILTER_SIZE);
}
```

# 14. 电流检测怎么设计？

电流检测也不要放在电机驱动里做复杂保护。

推荐：

```text
drv_adc.c
    负责 ADC 采样

current_service.c
    负责电流换算、滤波

app_fault.c
    判断是否达到过流保护
```

接口：

```c
void current_service_init(void);
void current_service_task(void);
uint16_t current_get_motor_ma(void);
```

保护逻辑放业务层：

```c
void app_current_protect_task(void)
{
    if (!app_is_motor_running())
        return;

    uint16_t current = current_get_motor_ma();

    if (current > MOTOR_CURRENT_LIMIT_MA)
    {
        if (over_current_start_time == 0)
            over_current_start_time = get_ms();

        if (get_ms() - over_current_start_time > 1000)
        {
            event_post(EVENT_CURRENT_PROTECT);
        }
    }
    else
    {
        over_current_start_time = 0;
    }
}
```

这样做的好处：

```text
ADC驱动不关心电机
电流服务不关心故障
故障逻辑不关心ADC怎么采样
```

# 15. 按键模块怎么设计？

# 16. WiFi / 涂鸦模块怎么设计？

涂鸦 UART 也不要直接控制业务。

应该是：

```text
tuya_uart_driver.c
    负责 UART 收发

tuya_protocol.c
    负责解析涂鸦协议帧

app_tuya.c
    负责把 DP 命令转成内部事件
```

例如 APP 发一键清理：

```text
UART收到数据
    ↓
协议解析得到 DP_CLEAN
    ↓
app_tuya.c 转成 EVENT_APP_CLEAN
    ↓
主状态机判断能不能执行
    ↓
执行清理动作
```

不要在 UART 接收回调里直接：

```c
action_start(ACTION_CLEAN);
```

因为 UART 中断或接收任务里直接操作业务，很容易出问题。

# 17. 中断里应该做什么？

中断里原则：

> **只做快速记录，不做复杂业务。**

例如 UART 接收中断：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    ring_buffer_put(&uart_rx_buf, rx_byte);
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
}
```

不要在中断里解析完整协议，更不要在中断里控制电机。

EXTI 中断也是一样：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == HOME_SENSOR_Pin)
    {
        roller_home_sensor_irq_flag = 1;
    }
}
```

然后在 `roller_device_task()` 里处理。

# 19. 故障模块怎么设计？

故障模块要统一管理，不要每个模块自己闪灯、自己蜂鸣、自己上报 APP。

故障定义：

```c
typedef enum
{
    FAULT_NONE                   = 0x00000000,
    FAULT_TRASHBOX_NOT_INSTALLED = 0x00000001,
    FAULT_WEIGHT_SENSOR_ERROR    = 0x00000002,
    FAULT_PIR_SENSOR_ERROR       = 0x00000004,
    FAULT_MOTOR_OVER_CURRENT     = 0x00000008,
    FAULT_MOTOR_TIMEOUT          = 0x00000010,
    FAULT_ROLLER_POSITION_ERROR  = 0x00000020,
} fault_code_t;
```

接口：

```c
void fault_set(uint32_t fault);
void fault_clear(uint32_t fault);
uint32_t fault_get(void);
uint8_t fault_has(uint32_t fault);
```

实现：

```c
static uint32_t g_fault_code;

void fault_set(uint32_t fault)
{
    g_fault_code |= fault;

    g_app.state = SYS_STATE_FAULT;

    roller_stop();
    led_set_effect(LED_EFFECT_RED_SLOW_FLASH);
    buzzer_fault_beep();
    app_tuya_report_fault(g_fault_code);
}

void fault_clear(uint32_t fault)
{
    g_fault_code &= ~fault;

    if (g_fault_code == FAULT_NONE)
    {
        g_app.state = SYS_STATE_IDLE;
        led_set_effect(LED_EFFECT_GREEN_ON);
    }

    app_tuya_report_fault(g_fault_code);
}
```

# 21. 框架核心总结

你这个智能猫砂盆 MCU 软件，建议这样分工：

```text
Driver 层：
    只负责硬件最基础操作

Device 层：
    把多个底层硬件组合成一个“设备”

Service 层：
    做通用服务，比如按键、灯效、蜂鸣器、称重滤波、事件队列

APP 层：
    做业务逻辑，比如清理、清空、童锁、如厕识别、故障处理

状态机：
    负责系统当前处于什么状态

事件队列：
    负责不同模块之间解耦通信

动作脚本：
    负责复杂电机流程
```

一句话总结：

> **底层只管硬件，上层只管业务，中间用事件和接口连接，所有动作非阻塞执行。**

你后面真正写代码时，可以先按这个顺序做：

```text
1. 先搭 main.c 主循环框架
2. 加 SysTick 1ms 时间基准
3. 加事件队列 event_service
4. 加 LED 和蜂鸣器服务
5. 加按键服务
6. 加电机 driver
7. 加 roller_device 位置控制
8. 加 action_engine 动作脚本
9. 加 app_state 主状态机
10. 再加称重、热释电、电流保护
11. 最后接 APP / 涂鸦协议
```

这样做出来的软件结构清楚，后面客户改需求，比如：

```text
清理动作多停 5 秒
幼猫模式下允许 APP 清理
增加杀菌灯
增加满仓检测
增加多猫模式
```

都不会大改架构，只需要局部改模块。
