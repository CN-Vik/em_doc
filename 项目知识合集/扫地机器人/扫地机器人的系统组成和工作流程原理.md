扫地机器人系统组成可以按 **“机械结构 + 电子硬件 + 嵌入式软件 + 算法逻辑 + 清洁机构 + 电源系统”** 来理解。

它本质上是一个小型移动机器人：

```text
扫地机器人系统
├── 机械结构系统
├── 运动驱动系统
├── 清扫执行系统
├── 传感器感知系统
├── 主控硬件系统
├── 电源/电池/充电系统
├── 嵌入式软件系统
├── 导航/避障/路径规划算法
└── App/通信/OTA/云端系统
```

---

# 1. 总体框图

可以先看整体结构：

```text
                          App / 云端
                              ↑
                           Wi-Fi/BLE
                              ↑
┌────────────────────────────────────────────────────┐
│                    主控系统                         │
│  MCU / SoC / RTOS / Linux / 状态机 / 导航算法        │
└────────────────────────────────────────────────────┘
       ↑             ↑              ↑             ↑
       │             │              │             │
   传感器系统     电机驱动系统     清扫系统     电源系统
       │             │              │             │
 IMU/编码器/     左轮/右轮/       风机/滚刷/    电池/BMS/
 碰撞/悬崖/      边刷/滚刷/       边刷/水泵     充电座/保护
 沿墙/雷达       风机电机
```

如果从功能角度看，扫地机器人主要做这几件事：

```text
感知环境
   ↓
判断位置和状态
   ↓
规划怎么走
   ↓
控制左右轮运动
   ↓
控制风机、滚刷、边刷清扫
   ↓
检测异常
   ↓
低电量或完成后回充
```

# 2. 机械结构系统

机械结构是整个机器人的“身体”。

常见结构包括：

```text
外壳
底盘
左右驱动轮
万向轮
边刷机构
滚刷机构
尘盒
风道
滤网
拖布组件
水箱
充电触点
保险杠
悬挂结构
```

## 2.1 底盘

底盘负责承载所有部件：

```text
电池
电机
主控板
风机
尘盒
滚刷
水箱
传感器
```

底盘设计会影响：

```text
爬坡能力
过门槛能力
防卡能力
风道效率
整机噪声
维修方便性
```

---

## 2.2 驱动轮

扫地机器人一般是两个主动轮：

```text
左轮电机
右轮电机
```

再加一个万向轮支撑。

这种结构叫：

```text
差速驱动结构
```

控制方式是：

```text
左轮 = 右轮：直走
左轮快，右轮慢：右转
左轮慢，右轮快：左转
左轮正转，右轮反转：原地旋转
```

这和很多小车机器人、平衡车、AGV 小车的底层运动原理类似。

---

# 3. 运动驱动系统

运动驱动系统主要包括：

```text
左轮电机
右轮电机
电机驱动芯片
编码器
电流采样
PWM 控制
速度闭环 PID
```

## 3.1 左右轮电机

左右轮一般使用：

```text
直流有刷电机 + 编码器
无刷电机 + 霍尔/编码器
减速电机
```

低成本扫地机多用有刷减速电机。

高端一些的可能用无刷电机。

---

## 3.2 电机驱动芯片

MCU 不能直接驱动电机，因为 MCU IO 电流太小。

所以需要电机驱动芯片，例如 H 桥驱动。

```text
MCU PWM 输出
      ↓
电机驱动芯片
      ↓
电机正转 / 反转 / 调速 / 刹车
```

常见控制信号：

```text
PWM：控制速度/功率
DIR：控制方向
EN：使能
FAULT：故障反馈
CURRENT：电流采样
```

---

## 3.3 编码器

编码器用于检测轮子转速和距离。

```text
编码器脉冲数
    ↓
轮子转了多少圈
    ↓
机器人走了多远
    ↓
估算机器人位置
```

例如：

```text
左轮走了 10cm
右轮走了 10cm
=> 机器人直走 10cm

左轮走了 5cm
右轮走了 10cm
=> 机器人发生转弯
```

编码器是无雷达扫地机器人导航的关键传感器之一。

---

# 4. 清扫执行系统

清扫系统是真正完成“清洁”的部分。

主要包括：

```text
边刷
滚刷
风机
尘盒
滤网
水箱
水泵
拖布
集尘接口
```

---

## 4.1 边刷

边刷的作用是把墙边、角落、桌腿旁边的灰尘扫到机器底部。

```text
墙边灰尘
   ↓
边刷扫到中间
   ↓
滚刷/吸口吸入
```

边刷电机一般不需要很复杂的闭环控制，常见是简单 PWM 调速。

---

## 4.2 滚刷

滚刷位于机器底部。

作用：

```text
拍打地面
卷起灰尘
卷起头发
把垃圾送到吸入口
```

滚刷容易遇到的问题：

```text
头发缠绕
电线缠绕
地毯阻力大
异物卡住
电机堵转
```

所以软件要检测滚刷电流，如果电流过大，就判断可能堵转。

---

## 4.3 风机

风机负责产生吸力。

```text
风机高速旋转
    ↓
风道形成负压
    ↓
灰尘进入尘盒
```

风机一般功率比较大，噪声也大。

软件要控制：

```text
安静档
标准档
强力档
地毯增压
堵转保护
过流保护
```

---

## 4.4 拖地系统

带拖布的扫地机器人还有：

```text
水箱
水泵
电磁阀
拖布电机
振动拖布模块
旋转拖布模块
```

嵌入式软件要控制：

```text
出水量
拖布振动频率
拖布旋转速度
水箱检测
拖布安装检测
```

# 5. 传感器感知系统

这是扫地机器人判断环境和自身状态的系统。

常见传感器如下：

| 传感器     | 作用           |
| ------- | ------------ |
| IMU     | 测角速度、姿态、碰撞震动 |
| 左右轮编码器  | 测轮速、里程       |
| 碰撞传感器   | 撞到障碍后触发      |
| 悬崖传感器   | 防止从楼梯掉下去     |
| 沿墙传感器   | 保持和墙的距离      |
| 电机电流采样  | 判断堵转、缠绕、过载   |
| 尘盒检测    | 判断尘盒是否安装     |
| 水箱检测    | 判断水箱是否安装     |
| 地毯检测    | 判断是否进入地毯区域   |
| 充电座红外接收 | 寻找充电座        |
| 激光雷达    | 建图定位         |
| 摄像头     | 视觉识别、VSLAM   |
| ToF/结构光 | 近距离避障        |

---

## 5.1 IMU

IMU 主要用于：

```text
检测机器人转了多少角度
辅助走直线
判断碰撞冲击
判断机器是否被抱起
判断倾斜/跌落异常
```

无雷达机器中，IMU 很重要，但不能单独完成可靠导航。

---

## 5.2 编码器

编码器用于：

```text
计算轮子速度
计算行驶距离
判断轮子是否打滑
做左右轮速度 PID
做里程计定位
```

对于差速轮机器人，编码器是运动控制的核心反馈。

---

## 5.3 碰撞传感器

前保险杠里面一般有：

```text
微动开关
霍尔传感器
光电开关
```

撞到东西后：

```text
触发碰撞
    ↓
停止
    ↓
后退
    ↓
转向
    ↓
继续清扫
```

---

## 5.4 悬崖传感器

底部红外传感器检测地面反射。

```text
有地面：红外反射正常
楼梯边缘：反射变弱
```

检测到悬崖后，机器人必须立即停止，否则会掉下去。

---

## 5.5 沿墙传感器

沿墙传感器一般是红外或者 ToF。

作用是保持机器人和墙之间的距离。

```text
离墙太远 -> 向墙靠
离墙太近 -> 远离墙
```

这个控制也可以用简单 PID。

---

# 6. 主控硬件系统

主控系统是扫地机器人的“大脑”。

有几种常见架构。

---

## 6.1 低成本架构：单 MCU

```text
一个 MCU 负责全部功能
```

适合：

```text
随机式扫地机
陀螺仪导航扫地机
无复杂地图功能的产品
```

MCU 负责：

```text
传感器采集
电机控制
状态机
简单避障
简单清扫路径
电池管理
按键 LED
充电控制
```

这种系统成本低，但功能有限。

---

## 6.2 中高端架构：MCU + Linux SoC

高级扫地机器人常用：

```text
MCU + Linux SoC
```

分工一般是：

```text
MCU：
    电机控制
    传感器采集
    实时保护
    电池管理
    充电控制
    底盘控制

Linux SoC：
    SLAM 建图
    路径规划
    App 通信
    地图显示
    语音
    AI 识别
    OTA
```

这种架构更适合带激光雷达、摄像头、地图功能的扫地机器人。

---

## 6.3 MCU 与 SoC 通信

MCU 和 SoC 之间常用通信方式：

```text
UART
SPI
I2C
CAN
USB
```

例如 SoC 发命令：

```text
目标线速度 = 0.2 m/s
目标角速度 = 0.5 rad/s
```

MCU 转换成左右轮速度：

```text
左轮速度 = V - W * L / 2
右轮速度 = V + W * L / 2
```

然后 MCU 做电机闭环控制。

扫地机器人一般使用锂电池包，比如：

```text

```

```text

```

---

## 7.2 电源轨

内部可能有多路电源：

```text

    ↓
12V / 16V：风机、电机
5V：传感器、红外、部分模块
3.3V：MCU、IMU、Flash、逻辑电路
1.8V：部分 SoC/DDR/摄像头
```

嵌入式开发要关注：

```text
电源上电顺序
掉电保存
低电压保护
电机启动电流冲击
风机大电流干扰
ADC 采样稳定性
EMI 干扰
```

---

## 7.3 充电系统

回充时通过充电触点连接充电座。

软件需要判断：

```text
是否接触充电座

充电电流是否正常
是否充满
是否过温
是否充电异常
```


# 11. 故障检测系统

扫地机器人故障检测非常重要。

常见故障包括：

```text
左轮堵转
右轮堵转
滚刷缠绕
边刷缠绕
风机异常
尘盒未安装
水箱未安装
拖布未安装
悬崖传感器异常
碰撞传感器异常
电池低电
充电异常
机器被困
机器被抱起
轮子悬空
主控过温
电机过流
```

软件要做：

```text
检测
判断
保护
停止
报警
记录故障码
上报 App
```

例如：

```text
滚刷电流过大
    ↓
停止滚刷
    ↓
尝试反转
    ↓
再次启动
    ↓
失败多次
    ↓
报警：请清理滚刷
```

# 14. 一个简化的扫地机器人系统结构

可以把它想成下面这个结构：

```text
                  用户/App
                     ↓
              清扫模式管理
                     ↓
              清扫状态机
                     ↓
     ┌───────────────┼───────────────┐
     ↓               ↓               ↓
```

# 2. 扫地机器人主要由哪些部分组成？

## 2.1 主控系统

里面一般有一个 MCU 或 SoC，例如：

```text

 ├── 运行路径规划算法
 ├── 读取传感器
 ├── 控制电机
 ├── 管理电池
 ├── 控制风机/滚刷/边刷
 ├── 处理地图
 └── 和 App / Wi-Fi 通信
```

低端扫地机可能是 MCU 为主。

高端扫地机可能是：

```text
MCU + Linux SoC
```

例如 MCU 做实时控制，Linux SoC 做地图、视觉、AI 避障、App 通信等。

# 3. 它怎么知道自己在哪？

这就是扫地机器人最核心的问题：

> **定位 + 建图，也就是 SLAM。**

SLAM 全称：

```text
Simultaneous Localization and Mapping
同时定位与建图
```

意思是：

```text
一边走，一边画地图；
一边画地图，一边判断自己在地图上的位置。
```

---

## 3.1 常见定位方式

### 方式一：轮速里程计

扫地机器人有两个主动轮：

```text
左轮电机 + 编码器
右轮电机 + 编码器
```

编码器可以知道轮子转了多少圈。

比如：

```text
轮子周长 = 20cm
轮子转 1 圈 ≈ 机器人前进 20cm
```

如果左右轮速度一样：

```text
左轮 = 10cm/s
右轮 = 10cm/s

机器人直线前进
```

如果左右轮速度不一样：

```text
左轮 = 5cm/s
右轮 = 10cm/s

机器人向左转弯
```

所以主控可以通过左右轮编码器估算：

```text
机器人走了多远
机器人转了多少角度
机器人当前大概在哪
```

但是轮速里程计有误差，比如：

```text
轮子打滑
地毯阻力大
轮子沾灰
碰撞造成位置偏差
```

所以它不能单独使用。

---

### 方式二：IMU 惯性传感器

IMU 里面一般有：

```text
陀螺仪：测角速度
加速度计：测加速度
```

扫地机器人用陀螺仪可以判断自己转了多少角度。

例如：

```text
机器人原地旋转
陀螺仪检测到 Z 轴角速度
积分后得到旋转角度
```

IMU 可以辅助轮速编码器，提高转向判断精度。

但是 IMU 也会漂移，所以也不能单独长期使用。

---

### 方式三：激光雷达 LDS / LiDAR

高端扫地机顶部经常有一个小圆塔：

```text
不断旋转的激光雷达
```

它会向周围发射激光，然后测量反射回来的距离。

得到类似这样的二维点云：

```text
前方 1.2m 有墙
左边 0.5m 有桌腿
右边 2.0m 是空旷区域
后方 0.8m 有障碍物
```

机器人一边转动雷达，一边扫描 360° 环境，最后得到房间轮廓。

激光雷达的优点：

```text
建图快
定位准
不太受光线影响
适合规则房间地图
```

缺点：

```text
成本高
圆塔会增加机身高度
对玻璃、镜子、黑色吸光材料可能不稳定
```

---

### 方式四：视觉摄像头 VSLAM

有些扫地机器人用摄像头看天花板、墙面、家具特征，然后判断自己移动了多少。

这种叫：

```text
Visual SLAM
视觉 SLAM
```

它通过图像特征点来定位。

优点：

```text
机身可以做得更薄
可以识别物体
成本有机会比激光低
```

缺点：

```text
受光线影响
晚上或者纯白墙面定位困难
算法复杂
```

---

# 4. 它是怎么建图的？

扫地机器人建图时，会把房间抽象成一张地图。

常见的是**栅格地图**：

```text
每一个小格子表示一个区域
```

比如：

```text
0 = 未知区域
1 = 可通行区域
2 = 障碍物
3 = 已清扫区域
```

大概像这样：

```text
未知未知未知未知未知
未知 墙 墙 墙 未知
未知 墙 空 空 墙
未知 墙 空 障碍 墙
未知 墙 墙 墙 未知
```

机器人移动时，会不断更新地图：

```text
雷达看到墙 → 标记为障碍
机器人走过 → 标记为已清扫
没探索过 → 仍然是未知
```

高级扫地机器人还会做：

```text
自动分房间
识别门口
保存多楼层地图
虚拟墙
禁区
指定房间清扫
```

---

# 5. 它怎么规划清扫路线？

扫地机器人的路径规划通常分几层。

---

## 5.1 全局路径规划

全局规划解决的是：

```text
我要从当前位置去哪个区域？
怎么绕过障碍物过去？
```

比如从客厅去卧室，中间有桌子、椅子、墙，机器人需要找一条可走路线。

常见算法有：

```text
A* 算法
Dijkstra 算法
DWA 局部避障
代价地图 Costmap
```

你可以简单理解成：

```text
地图上每个格子都有代价
空地代价低
靠近障碍物代价高
障碍物不可走

算法找一条总代价最低的路线
```

---

## 5.2 覆盖路径规划

扫地机器人最重要的不是从 A 到 B，而是：

> **如何把整个房间都扫一遍，尽量不漏扫、不重复。**

常见策略是：

### 弓字形清扫

```text
→ → → → →
        ↓
← ← ← ← ←
↓
→ → → → →
        ↓
← ← ← ← ←
```

也叫：

```text
Z 字形
弓字形
往复式覆盖
```

这种效率高，覆盖率好。

---

### 沿边清扫

扫地机器人会沿墙走一圈，把边角区域清理掉。

```text
先沿墙一圈
再中间弓字形清扫
```

因为靠墙位置、桌脚附近、角落区域容易积灰。

---

### 分区清扫

高级机器人会先把房子分成多个区域：

```text
客厅
卧室
厨房
卫生间
走廊
```

然后按区域清扫：

```text
先扫客厅 → 再扫卧室 → 再扫厨房
```

这样路径更有规律，效率更高。

---

# 6. 它是怎么运动控制的？

大多数扫地机器人是**差速轮结构**。

也就是：

```text
左轮一个电机
右轮一个电机
前面或后面一个万向轮
```

它通过控制左右轮速度实现运动。

---

## 6.1 直走

```text
左轮速度 = 右轮速度
```

机器人直线前进。

```text
左轮  ↑       ↑ 右轮
      机器人前进
```

---

## 6.2 左转

```text
左轮慢
右轮快
```

机器人向左转。

```text
左轮  慢
右轮  快
```

---

## 6.3 右转

```text
左轮快
右轮慢
```

机器人向右转。

---

## 6.4 原地旋转

```text
左轮正转
右轮反转
```

机器人原地转圈。

```text
左轮 ↑
右轮 ↓
```

这就是为什么扫地机器人可以在狭小空间里转向。

---

# 7. 清扫系统是怎么工作的？

扫地机器人的清扫不是只靠吸尘，一般是多部分配合。

```text
边刷 → 把墙边灰尘扫到中间
滚刷 → 把地面垃圾卷起来
风机 → 产生负压吸入尘盒
滤网 → 过滤灰尘
尘盒 → 收集垃圾
拖布 → 湿拖地面
```

---

## 7.1 边刷

边刷一般在机器人前侧或一侧。

作用：

```text
把墙边、角落、桌腿旁边的灰尘扫到机器人底部吸入口附近
```

因为机器人本体是圆形或 D 形，不可能完全贴到墙角。

---

## 7.2 滚刷

滚刷位于机器人底部中间。

作用：

```text
拍打地面
卷起头发、灰尘、碎屑
把垃圾送向吸入口
```

滚刷有几种：

```text
毛刷滚刷
胶刷滚刷
毛胶混合滚刷
双胶刷
```

毛刷对地毯清洁较好，但容易缠头发。

胶刷更容易清理毛发。

---

## 7.3 风机

风机高速旋转，产生负压，把灰尘吸进尘盒。

吸力通常用 Pa 表示，比如：

```text
3000Pa
5000Pa
8000Pa
10000Pa
```

但吸力不是唯一指标。

清扫效果还和这些有关：

```text
风道设计
滚刷结构
贴地密封性
算法路线
尘盒密封
滤网阻力
```

---

# 8. 它怎么避障？

扫地机器人有很多传感器一起工作。

---

## 8.1 碰撞传感器

前保险杠里面有微动开关或霍尔传感器。

当机器人撞到东西：

```text
保险杠被压下
触发碰撞信号
机器人后退
转向
重新规划路线
```

低端机器人大量依赖碰撞避障。

---

## 8.2 悬崖传感器

底部有红外传感器，用来检测楼梯、台阶。

原理大概是：

```text
红外发射 → 地面反射 → 红外接收
```

如果下面是地面，能收到反射。

如果前面是楼梯，反射突然变弱或消失。

机器人就判断：

```text
前方可能是悬崖，不能继续走
```

---

## 8.3 沿墙传感器

侧边红外或 ToF 传感器用于检测墙体距离。

机器人沿墙清扫时会保持一个距离：

```text
离墙 1cm ~ 3cm 左右
```

控制目标是：

```text
太远 → 靠近一点
太近 → 远离一点
```

这里也会用到类似 PID 的控制。

---

## 8.4 激光避障 / 视觉避障

高级机器人会识别：

```text
鞋子
袜子
电线
宠物粪便
玩具
桌腿
沙发脚
门槛
```

普通雷达主要看二维平面障碍。

AI 摄像头可以识别具体物体。

---

# 9. 它怎么判断自己被困住了？

扫地机器人会综合多个信号判断是否被困。

比如：

```text
轮子转了，但是编码器显示没怎么移动
电机电流突然变大
IMU 姿态异常
碰撞传感器频繁触发
雷达地图变化异常
左右轮速度差异常
滚刷电流过大
边刷电流过大
```

常见情况：

```text
被线缠住
卡在椅子脚
爬门槛失败
陷进地毯
滚刷缠头发
轮子悬空
被小物体顶住
```

脱困动作可能是：

```text
后退
原地旋转
左右试探
降低速度
增大轮子扭矩
停止滚刷
报警提示用户
```

# 10. 它怎么回充？

回充有两层逻辑。

---

## 10.1 知道充电座大概位置

如果有地图，机器人记得：

```text
充电座在地图中的坐标
```

清扫结束或低电量时，它会规划路线回去。

---

## 10.2 精准对接充电座

靠近充电座后，需要精确对准充电触点。

常见方式：

```text
红外信标
视觉识别
激光定位
充电座特征匹配
```

充电座会发出红外信号，机器人根据左右红外接收强度判断方向。

类似：

```text
左边信号强 → 机器人偏右，需要向左修正
右边信号强 → 机器人偏左，需要向右修正
两边差不多 → 对准充电座
```

最后慢速倒车或前进接触充电极片。

# 12. 一个简化的软件状态机

扫地机器人非常适合用状态机设计。

```c
typedef enum
{
    ROBOT_STATE_IDLE = 0,        // 空闲
    ROBOT_STATE_INIT,            // 初始化
    ROBOT_STATE_MAPPING,         // 建图
    ROBOT_STATE_CLEANING,        // 清扫中
    ROBOT_STATE_EDGE_CLEAN,      // 沿边清扫
    ROBOT_STATE_AVOID_OBSTACLE,  // 避障
    ROBOT_STATE_TRAPPED,         // 被困
    ROBOT_STATE_RETURN_HOME,     // 回充
    ROBOT_STATE_CHARGING,        // 充电中
    ROBOT_STATE_ERROR            // 故障
} robot_state_t;
```

状态切换大概是：

```text
IDLE
 ↓ 用户启动
INIT
 ↓
CLEANING
 ↓ 碰到障碍
AVOID_OBSTACLE
 ↓ 避障完成
CLEANING
 ↓ 电量低 / 清扫完成
RETURN_HOME
 ↓ 对接成功
CHARGING
```

# 13. 一个简化控制流程

```c
while (1)
{
    read_sensors();              // 读取传感器

    update_localization();        // 更新自身位置

    update_map();                 // 更新地图

    check_fault();                // 检查故障

    switch (robot_state)
    {
        case ROBOT_STATE_CLEANING:
            plan_clean_path();    // 规划清扫路径
            control_motion();     // 控制左右轮运动
            control_clean_motor(); // 控制风机、滚刷、边刷
            break;

        case ROBOT_STATE_AVOID_OBSTACLE:
            avoid_obstacle();     // 避障
            break;

        case ROBOT_STATE_RETURN_HOME:
            plan_path_to_dock();  // 规划回充路径
            dock_control();       // 对接充电座
            break;

        case ROBOT_STATE_TRAPPED:
            escape_control();     // 脱困
            break;

        default:
            stop_all_motor();
            break;
    }

    vTaskDelay(pdMS_TO_TICKS(10));
}
```

真实产品比这个复杂很多，但大的框架就是这样。

# 14. 扫地机器人的核心难点

## 难点一：定位不能漂

轮子会打滑，IMU 会漂移，雷达会有误差。

所以需要多传感器融合：

```text
编码器 + IMU + 雷达 + 碰撞 + 地图匹配
```

---

## 难点二：覆盖率要高

不是能走就行，而是要尽量：

```text
不漏扫
少重复
少卡困
效率高
路径好看
```

---

| 类型     | 特点          | 原理         |

# 16. 用一句话总结

扫地机器人的本质是：

> **通过传感器感知环境，用 SLAM 知道自己在哪，用路径规划决定怎么扫，用电机控制实现移动，再通过风机、滚刷、边刷完成清洁。**

从嵌入式角度看，它就是一个复杂的实时控制系统：

```text

    ↓
定位建图
    ↓
路径规划
    ↓
电机闭环控制
    ↓
清扫执行
    ↓
故障检测和状态机管理
```

你可以把它看成一个“小型自动驾驶机器人”，只不过它的任务不是开车，而是把地面尽量干净、高效、安全地扫完。

可以，但要先把结论说清楚：

> **如果真的“只有 IMU”，没有编码器、没有碰撞开关、没有红外/ToF、没有沿墙传感器，那基本不能可靠建图、规划、避障。**
> IMU 只能知道“我在转、我倾斜了、我震动了、我可能被撞了”，但它不知道前面有没有墙，也不知道自己准确走了多少距离。

扫地机器人如果没有激光雷达、没有深度相机，一般也不会只靠 IMU，而是靠：


```text
陀螺仪导航
惯性导航
随机碰撞导航
半规划式清扫
```

# 1. 只有 IMU 能得到什么信息？

IMU 一般包括：

```text
三轴陀螺仪：测角速度
三轴加速度计：测加速度/倾斜
```

扫地机器人主要用的是陀螺仪 Z 轴。

机器人在地面上转弯时，相当于绕竖直方向旋转：

```text
Z 轴角速度 wz
```

对角速度积分，可以估算机器人当前朝向角：

```text
角度 = 上一次角度 + 角速度 × 时间
```

比如：

```c
yaw += gyro_z * dt;
```

所以 IMU 可以帮助机器人知道：

```text
我转了多少度
我是不是偏航了
我是不是原地打转
我是不是被撞击震动了
我是不是倾斜/悬空了
```

但是 IMU 不擅长算位置。

因为如果想用加速度积分得到位置：

```text
加速度 -> 积分得到速度 -> 再积分得到位置
```

问题是误差会爆炸。

比如加速度计有一点点零偏：

```text
0.02 m/s² 的误差
```

积分几秒后，位置就会漂很多。扫地机器人这种低成本 IMU，靠加速度积分走位基本不现实。

所以：

```text
IMU 可以估计方向
IMU 很难单独估计位置
IMU 不能直接看见障碍物
IMU 不能单独建可靠地图
```

---

# 2. 没有雷达/深度相机，怎么知道自己走了多远？

靠**左右轮编码器**。

扫地机器人一般是差速轮结构：

```text
左轮电机 + 编码器
右轮电机 + 编码器
```

编码器可以知道轮子转了多少圈。

例如：

```text
轮子直径 = 70 mm
轮子周长 ≈ 219.8 mm
编码器一圈 = 1000 个脉冲
```

如果检测到轮子转了 1000 个脉冲，就认为机器人走了大约 219.8 mm。

左右轮编码器配合，可以估算机器人位姿：

```text
x 坐标
y 坐标
朝向角 yaw
```

这叫：

```text
轮式里程计
Odometry
```

大概流程：

```text
读取左轮编码器
读取右轮编码器
计算左轮走了多少
计算右轮走了多少
计算机器人前进距离
计算机器人转向角度
更新机器人当前位置
```

但是轮子会打滑，所以编码器也会有误差。

所以实际会用：

```text
编码器估计距离
IMU 修正角度
```

也就是：

```text
轮速编码器 + 陀螺仪融合
```

# 3. 没有雷达，怎么建图？

先说重点：

> **没有雷达/摄像头的扫地机器人，建图能力很弱。它通常不是精确建图，而是粗略记录“我大概走过哪里、哪里撞过、哪里可能有边界”。**

它建的不是高精度房间地图，而是类似这种：

```text
已走过区域
碰撞点
疑似墙边
疑似障碍物
回充座大概方向
```

可以用一个二维栅格地图表示：

```text
未知区域 = 0
已清扫区域 = 1
碰撞障碍 = 2
危险区域 = 3
```

例如：

```text
?????????????
?111111??????
?111X11??????
?111111??????
?111111X?????
?????????????
```

其中：

```text
1 = 自己走过
X = 撞到过障碍
? = 不知道
```

这种地图不是靠“看见墙”建立的，而是靠：

```text
我走到这里了
我撞到这里了
我沿着某个方向走过
我某个地方不能通过
```

所以它建图很粗糙。

# 4. 没有雷达，路径规划怎么做？

没有雷达时，通常不会做很高级的全局规划，而是做**行为策略 + 简单覆盖规划**。

常见方案有几种。

---

## 4.1 随机碰撞式清扫

这是最低端方案。

流程：

```text
往前走
撞到东西
后退
随机转一个角度
继续往前走
```

伪代码：

```c
while (cleaning)
{
    move_forward();

    if (bumper_triggered())
    {
        stop();
        move_backward(200);
        turn_random_angle();
    }
}
```

优点：

```text
成本低
算法简单
不需要地图
```

缺点：

```text
效率低
重复清扫多
容易漏扫
路线很乱
用户体验差
```

---

## 4.2 陀螺仪弓字形清扫

稍微高级一点的无雷达扫地机会用 IMU 保持方向，做弓字形清扫。

路径类似：

```text
→ → → → →
        ↓
← ← ← ← ←
↓
→ → → → →
        ↓
← ← ← ← ←
```

这种方案依赖：

```text
IMU 保持直线方向
编码器估计前进距离
碰撞传感器判断边界
```

流程大概是：

```text
设定当前清扫方向为 0°
保持直线前进
如果撞墙/障碍
后退一点
转 90°
横移一段距离
再转 90°
反方向继续清扫
```

伪代码：

```c
clean_dir = get_yaw();

while (cleaning)
{
    move_straight_with_gyro(clean_dir);

    if (hit_obstacle())
    {
        stop();
        move_backward();

        turn_to_angle(clean_dir + 90);
        move_forward(row_spacing);

        clean_dir += 180;
        turn_to_angle(clean_dir);
    }
}
```

这里 IMU 的作用很关键：

```text
让机器人尽量走直线
让转弯角度接近 90°/180°
让弓字形路线不至于歪得太严重
```

但是它仍然不是真正的精确导航。

因为：

```text
轮子打滑会导致位置误差
撞击会改变机器人实际位置
地毯会导致左右轮速度不一致
IMU 会漂移
房间形状复杂时容易乱
```

---

## 4.3 沿墙清扫

没有雷达也可以沿墙，但需要沿墙传感器或者碰撞反馈。

比较常见的是侧边红外/ToF：

```text
检测机器人侧面到墙的距离
```

控制目标：

```text
离墙太远 -> 往墙靠
离墙太近 -> 远离墙
```

如果连沿墙传感器都没有，只靠碰撞传感器，也能做很粗糙的沿边：

```text
轻微碰撞墙体
调整角度
贴着墙慢慢走
```

但效果差，容易磕家具。

---

# 5. 没有雷达，怎么避障？

严格来说，没有距离传感器时，不能叫“提前避障”，只能叫：

> **碰撞后避障 / 接触式避障。**

## 5.1 碰撞避障

前面有保险杠。

撞到东西后：

```text
保险杠触发
机器人停止
后退
转向
绕开
```

流程：

```text
前进
  ↓
撞到障碍物
  ↓
记录碰撞位置
  ↓
后退
  ↓
左转或右转
  ↓
继续前进
```

---

## 5.2 悬崖避障

悬崖传感器非常重要。

否则机器人会从楼梯掉下去。

底部红外检测地面反射：

```text
有地面 -> 红外反射正常
无地面/楼梯 -> 反射突然变弱
```

检测到悬崖后：

```text
立即停止
后退
转向
禁止继续前进
```

---

## 5.3 电机电流检测避障/堵转

如果轮子或者滚刷被卡住，电机电流会上升。

例如：

```text
左轮电流突然变大
右轮编码器速度下降
```

可能说明：

```text
轮子被卡住
机器人顶住障碍物
陷进地毯
被电线缠住
```

处理方式：

```text
停止
后退
反转滚刷
左右摆动
多次失败后报警
```

---

## 5.4 IMU 辅助判断碰撞/卡困

IMU 可以检测：

```text
突然冲击
姿态倾斜
异常振动
原地打转
被抱起
被困住
```

比如：

```text
电机在转
编码器有脉冲
但是 IMU 姿态变化异常
或者机器人长时间没有明显位移
```

就可能判断为卡困。

不过注意：

```text
IMU 不能看见障碍物
只能辅助判断异常状态
```

---

# 6. 只有 IMU 的极限在哪里？

假设真的只有 IMU，没有编码器、没有碰撞、没有红外、没有电流检测。

那机器人最多只能做：

```text
保持方向
检测转动
检测倾斜
检测震动
大概判断被撞
```

但它不能可靠知道：

```text
前面有没有墙
距离墙多远
自己走了多少米
当前位置在哪里
哪个地方扫过
哪个地方没扫
怎么回充
怎么绕过障碍物
```

所以真实产品不可能只靠 IMU 完成可靠导航。

更准确地说：

```text
IMU 是辅助导航传感器，不是完整导航传感器。
```

# 8. 嵌入式软件开发在扫地机器人里负责什么？

这个问题很重要。

扫地机器人里的嵌入式软件，通常不只是写几个外设驱动，而是从底层到业务逻辑都要参与。

---

## 8.1 BSP/驱动开发

负责 MCU 外设驱动，例如：

```text
GPIO
PWM
ADC
I2C
SPI
UART
CAN
Flash
定时器
编码器接口
DMA
看门狗
低功耗
```

扫地机器人具体外设包括：

```text
IMU 驱动
左右轮电机驱动
边刷电机驱动
滚刷电机驱动
风机驱动
碰撞传感器
悬崖传感器
沿墙传感器
电池电压检测
充电座检测
按键
LED
蜂鸣器
尘盒检测
水箱检测
拖布检测
```

---

## 8.2 电机控制

这是很核心的部分。

扫地机器人至少有：

```text
左轮电机
右轮电机
风机电机
滚刷电机
边刷电机
拖布电机/水泵
```

嵌入式要负责：

```text
PWM 输出
电机方向控制
速度闭环
堵转检测
过流保护
软启动
刹车控制
故障恢复
```

左右轮一般需要速度闭环 PID。

例如：

```c
target_speed_left = 200;   // 目标速度
real_speed_left   = encoder_get_speed();

pwm_left = pid_calc(&left_pid, target_speed_left, real_speed_left);

motor_left_set_pwm(pwm_left);
```

---

## 8.3 编码器和里程计

嵌入式要读取编码器，并计算：

```text
左轮速度
右轮速度
左轮里程
右轮里程
机器人前进距离
机器人旋转角度
```

这部分是导航算法的底层基础。

如果编码器数据不准，上层导航全会乱。

---

## 8.4 IMU 数据处理

负责：

```text
IMU 初始化
量程配置
采样率配置
零偏校准
滤波
陀螺仪积分
姿态角估计
异常震动检测
跌倒/倾斜检测
```

比如开机静止时做零偏校准：

```c
gyro_offset_z = average(gyro_z_samples);
```

运行时：

```c
gyro_z_corrected = gyro_z_raw - gyro_offset_z;
yaw += gyro_z_corrected * dt;
```

---

## 8.5 运动控制

嵌入式要把“导航命令”转换成“左右轮速度”。

例如上层给出：

```text
前进
后退
左转 90°
右转 45°
原地旋转
沿墙走
弓字形清扫
```

底层要变成：

```text
左轮目标速度
右轮目标速度
```

差速轮控制大概是：

```text
直走：
左轮 = +V
右轮 = +V

左转：
左轮 = 小速度
右轮 = 大速度

原地左转：
左轮 = -V
右轮 = +V

后退：
左轮 = -V
右轮 = -V
```

---

## 8.6 清扫状态机

扫地机器人强烈依赖状态机。

例如：

```c
typedef enum
{
    ROBOT_IDLE = 0,
    ROBOT_START,
    ROBOT_CLEANING,
    ROBOT_EDGE_CLEAN,
    ROBOT_AVOID,
    ROBOT_ESCAPE,
    ROBOT_RETURN_HOME,
    ROBOT_CHARGING,
    ROBOT_ERROR
} robot_state_t;
```

状态切换：

```text
空闲
 ↓ 用户启动
开始清扫
 ↓
弓字形清扫
 ↓ 碰撞
避障
 ↓
继续清扫
 ↓ 电量低
回充
 ↓
充电
```

嵌入式要保证状态切换可靠，不乱跳，不死机。

---

## 8.7 避障和脱困逻辑

负责处理：

```text
撞墙
撞桌腿
悬崖
轮子悬空
轮子堵转
滚刷缠绕
边刷堵转
被地毯卡住
机身被抱起
尘盒未安装
水箱未安装
电量过低
```

举个脱困逻辑：

```text
检测到左轮堵转
    ↓
停止左右轮
    ↓
后退 10 cm
    ↓
原地右转 30°
    ↓
再次尝试前进
    ↓
失败超过 3 次
    ↓
报警：机器人被困
```

---

## 8.8 电池和充电管理

负责：

```text
电池电压采集
电池电流采集
电量估算
低电量保护
充电检测
充电座对接检测
充电状态显示
过压/欠压/过温保护
```

扫地机器人电池一般是锂电池包，嵌入式要和 BMS 或充电管理芯片配合。

---

## 8.9 回充控制

如果没有雷达，回充会更困难。

常见低成本方案是靠：

```text
红外信标
充电座发射红外信号
机器人左右接收管判断方向
```

嵌入式要实现：

```text
寻找红外信号
根据信号强弱调整方向
慢速靠近
检测充电触点
确认充电成功
```

---

## 8.10 通信、OTA、日志

负责：


# 10. 一个无雷达扫地机器人的简化主流程

```c
while (1)
{
    read_sensors();          // 读取 IMU、编码器、碰撞、悬崖、电流

    update_odometry();       // 根据编码器 + IMU 更新位置和方向

    check_fault();           // 检查堵转、跌落、低电量、被困

    switch (robot_state)
    {
        case ROBOT_CLEANING:
            gyro_straight_clean();   // 陀螺仪辅助直线清扫

            if (bumper_hit())
            {
                robot_state = ROBOT_AVOID;
            }

            if (battery_low())
            {
                robot_state = ROBOT_RETURN_HOME;
            }
            break;

        case ROBOT_AVOID:
            move_backward();
            turn_angle(60);
            robot_state = ROBOT_CLEANING;
            break;

        case ROBOT_RETURN_HOME:
            search_dock_signal();
            dock_align_control();
            break;

        case ROBOT_ERROR:
            stop_all_motor();
            alarm_user();
            break;

        default:
            stop_all_motor();
            break;
    }

    delay_ms(10);
}
```

# 11. 最关键的理解

无雷达扫地机器人不是这样工作的：

```text
看见完整房间
精确建图
精确规划
精确导航
```

更像是这样工作的：

```text
靠编码器估算自己走了多远
靠 IMU 保持方向和转角
靠碰撞/悬崖/电流判断异常
靠规则算法做弓字形或随机清扫
靠状态机不断修正行为
```

所以它的能力边界是：

| 能力       | 无雷达 + IMU/编码器方案 |
| -------- | --------------- |
| 走直线      | 可以，靠 IMU 修正     |
| 转 90°    | 可以，靠陀螺仪积分       |
| 判断前方障碍   | 不行，除非撞上或有红外     |
| 精确建图     | 很难              |
| 记录大概清扫轨迹 | 可以              |
| 弓字形清扫    | 可以，但会漂移         |
| 精准分房间    | 很难              |
| 指哪扫哪     | 很难              |
| 高效回充     | 需要红外信标辅助        |
| 避免小物体    | 基本不行            |
| 防跌落      | 必须靠悬崖传感器        |

# 12. 一句话总结

没有激光雷达、深度相机时，扫地机器人主要靠：

```text
编码器算距离
IMU 算方向
碰撞传感器发现障碍
悬崖传感器防跌落
电机电流判断堵转
状态机和简单算法完成清扫
```

而嵌入式软件主要负责：

```text
传感器驱动
电机控制
编码器/IMU 处理
里程计
清扫状态机
避障脱困
电池充电
通信 OTA
故障保护
日志和产测
```

真正高级的 SLAM 建图、AI 识别、复杂路径规划，通常是算法工程师或者机器人导航工程师负责；但是在小公司里，嵌入式工程师很可能也要参与实现简化版导航逻辑、状态机和运动控制。
