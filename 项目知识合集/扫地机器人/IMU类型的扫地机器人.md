结论先说清楚：**单靠 IMU，扫地机器人几乎做不了真正意义上的“导航避障”**。IMU 只能告诉机器人“自己怎么动了”，不能告诉机器人“前面有什么、自己在哪里”。所以如果一个扫地机器人看起来“只有 IMU”，它大概率其实还依赖这些东西：

1. **轮子编码器 / 电机霍尔**：估算走了多远。
2. **碰撞开关 / 保险杠**：撞到东西才知道有障碍。
3. **沿墙红外 / 悬崖传感器**：检测墙边、台阶。
4. **电机电流变化**：判断卡住、轮子打滑、滚刷堵转。
5. **IMU**：辅助判断方向、姿态、转弯角度、碰撞、打滑。

如果真的**只有 IMU，没有编码器、没有碰撞、没有雷达、没有摄像头、没有红外**，那它只能“盲走”，不能可靠避障，也不能可靠清扫覆盖。

---

## 1. IMU 能提供什么？

扫地机器人常用 IMU 一般是 6 轴：

```c
加速度计：acc_x, acc_y, acc_z
陀螺仪：gyro_x, gyro_y, gyro_z
```

对扫地机器人最有用的是：

```c
gyro_z  -> 估算机器人转了多少角度
acc_x/y -> 粗略判断碰撞、震动、打滑
acc_z   -> 判断倾斜、抬起、跌落异常
```

例如机器人想原地右转 90°，就可以积分陀螺仪 Z 轴：

```c
yaw += gyro_z * dt;
```

当：

```c
yaw >= 90°
```

就认为转够了。

所以 IMU 很适合做：

```text
保持直线
控制转弯角度
检测撞击
检测抬起
检测倾斜
检测异常震动
辅助判断轮子打滑
```

但是它不擅长做：

```text
知道前面有没有障碍物
知道自己在房间哪个位置
知道哪些区域已经扫过
长期精确定位
构建地图
```

---

## 2. 为什么单靠 IMU 不能精确定位？

理论上，加速度积分一次可以得到速度，积分两次可以得到位置：

```text
加速度 -> 速度 -> 位移
```

但实际不行，因为 IMU 有零偏、噪声、震动、安装误差。

例如加速度计有一个很小的误差：

```text
0.02 m/s²
```

积分几秒之后，位置误差就会越来越大。扫地机器人地面震动、轮子打滑、碰撞、地毯阻力都会让误差更大。

所以实际工程里不会单靠加速度计算位置。

真正常用的是：

```text
轮子编码器估算位移
IMU 修正方向
碰撞/红外/雷达/视觉感知环境
```

---

## 3. 低成本扫地机器人是怎么“导航”的？

很多便宜扫地机器人不是激光 SLAM，也不是视觉 SLAM，而是：

```text
随机碰撞 + 陀螺仪辅助 + 沿墙 + 定时覆盖
```

它不是像高端机器人那样画地图，而是靠算法让它“看起来尽量扫完整”。

典型流程是：

```text
启动清扫
  ↓
直线前进
  ↓
如果撞墙/撞家具
  ↓
后退一点
  ↓
随机转一个角度，比如 60°~160°
  ↓
继续直线前进
  ↓
定时切换清扫模式
  ↓
最后回充或者停止
```

这种叫：

```text
随机覆盖清扫
```

优点：

```text
成本低
算法简单
不需要建图
适合小面积房间
```

缺点：

```text
效率低
容易重复清扫
容易漏扫
不能精准分区
不能记住地图
回充能力差
```

---

## 4. IMU 在里面具体怎么用？

### 1）保持直线

两个轮子即使 PWM 一样，实际速度也可能不一样：

```text
左轮略快 -> 机器人往右偏
右轮略快 -> 机器人往左偏
```

IMU 可以检测 yaw 是否偏移。

控制逻辑类似：

```c
target_yaw = 当前方向;

while (前进)
{
    yaw_error = target_yaw - imu_yaw;

    left_pwm  = base_pwm - kp * yaw_error;
    right_pwm = base_pwm + kp * yaw_error;
}
```

这样机器人可以走得更直。

---

### 2）控制转弯角度

没有 IMU 的话，机器人只能靠：

```text
左轮转多少圈
右轮转多少圈
```

来估计转了多少度。但地面打滑会导致误差很大。

有 IMU 之后，可以这样：

```c
yaw_start = imu_yaw;

左轮后退;
右轮前进;

while (abs(imu_yaw - yaw_start) < 90.0f)
{
    继续转;
}

停止;
```

这样 90°、180°、随机角度转弯会更准。

---

### 3）检测碰撞

碰撞时，加速度会突然产生尖峰：

```text
acc_x / acc_y 突然变大
```

比如：

```c
if (abs(acc_x) > COLLISION_THRESHOLD ||
    abs(acc_y) > COLLISION_THRESHOLD)
{
    认为发生碰撞;
}
```

不过这个不如机械碰撞开关可靠。因为地毯、门槛、震动也可能误判。

实际产品通常是：

```text
碰撞开关为主
IMU 碰撞检测为辅
```

---

### 4）检测卡住 / 打滑

比如电机在转，但是 IMU 发现机器人姿态和运动状态异常：

```text
轮子在动，但是 yaw 没变化
轮子在动，但是震动很大
机器人倾斜角异常
长时间方向变化很小
```

就可能是：

```text
轮子悬空
被地毯卡住
被电线缠住
爬上门槛失败
机器被抱起
```

这种时候状态机可以进入：

```text
后退 -> 左右扭动 -> 再尝试 -> 失败报警
```

---

## 5. 避障到底靠什么？

严格来说，IMU 不能提前避障。

它只能在这些情况下“事后判断”：

```text
撞到了
震动异常
角速度异常
姿态异常
电机堵转
```

真正的避障需要外部感知传感器，例如：

| 传感器       | 作用         |
| --------- | ---------- |
| 碰撞开关      | 撞到障碍后触发    |
| 红外测距      | 近距离检测障碍    |
| 超声波       | 检测前方障碍     |
| 激光雷达 LDS  | 建图、定位、规划路径 |
| 摄像头       | 视觉识别环境     |
| 结构光 / ToF | 识别障碍和距离    |
| 悬崖传感器     | 防止跌落楼梯     |
| 沿墙传感器     | 保持贴墙距离     |

所以“单靠 IMU 避障”准确说应该是：

```text
不能主动避障，只能碰撞后反应。
```

---

## 6. 清扫任务是怎么执行的？

低成本扫地机器人一般有几个清扫模式：

```text
自动清扫
沿墙清扫
定点清扫
弓字形清扫
回充
脱困
```

状态机可能类似这样：

```c
typedef enum {
    STATE_IDLE,
    STATE_FORWARD,
    STATE_COLLISION,
    STATE_BACKWARD,
    STATE_TURN,
    STATE_WALL_FOLLOW,
    STATE_SPOT_CLEAN,
    STATE_STUCK,
    STATE_RETURN_HOME,
} robot_state_t;
```

主逻辑大概是：

```c
switch (state)
{
    case STATE_FORWARD:
        保持直线前进;

        if (检测到碰撞)
            state = STATE_COLLISION;

        if (检测到悬崖)
            state = STATE_BACKWARD;

        if (检测到卡住)
            state = STATE_STUCK;

        break;

    case STATE_COLLISION:
        停止;
        后退一点;
        随机选择转弯角度;
        state = STATE_TURN;
        break;

    case STATE_TURN:
        使用 IMU 控制转弯角度;
        转够后 state = STATE_FORWARD;
        break;

    case STATE_STUCK:
        后退;
        左右扭动;
        如果失败，报警;
        break;
}
```

这里 IMU 主要负责：

```text
前进不跑偏
转弯角度准确
判断撞击/倾斜/卡住
```

不是负责“看路”。

---

## 7. 有 IMU 但没有雷达，能不能做弓字形清扫？

可以做“伪弓字形”，但不可靠。

例如：

```text
前进 2 米
右转 90°
前进 20 cm
右转 90°
前进 2 米
左转 90°
前进 20 cm
左转 90°
重复
```

这个逻辑需要：

```text
轮子编码器估算距离
IMU 修正角度
碰撞检测处理异常
```

但是如果遇到：

```text
椅子腿
桌子
地毯
门槛
轮子打滑
障碍物绕行
```

轨迹就乱了。

所以无地图机器人做弓字形，只能说是：

```text
近似覆盖
```

不是高端扫地机那种：

```text
建图 + 定位 + 路径规划
```

---

## 8. 高端扫地机器人怎么做？

高端机器人一般是：

```text
LDS 激光雷达 / 视觉 / ToF
+
轮子编码器
+
IMU
+
SLAM 算法
+
路径规划
```

它会知道：

```text
我在哪里
房间边界在哪里
障碍物在哪里
哪里扫过
哪里没扫
怎么回充
怎么分区
```

这时候 IMU 只是融合定位的一部分。

常见融合方式是：

```text
轮子里程计 + IMU + 激光/视觉 SLAM
```

IMU 的作用是提高短时间姿态估计和运动稳定性。

---

## 9. 对你现在做嵌入式扫地机项目的理解

你可以这样理解：

```text
IMU = 机器人的“内耳”
雷达/摄像头/红外 = 机器人的“眼睛”
轮子编码器 = 机器人的“脚步计数器”
碰撞开关 = 机器人的“触觉”
```

单靠“内耳”，机器人只能知道自己晃没晃、转没转、歪没歪。

它不知道前面有没有桌腿，也不知道房间长什么样。

所以工程上比较靠谱的低成本方案是：

```text
轮子编码器 + IMU + 碰撞开关 + 悬崖传感器 + 沿墙/红外
```

中高端方案是：

```text
轮子编码器 + IMU + LDS/视觉/ToF + SLAM
```

## 10. 一句话总结

**单靠 IMU 的扫地机器人不能真正导航避障，只能做姿态检测、转角控制、直线修正、碰撞/卡住辅助判断。低成本扫地机通常靠“随机碰撞 + IMU 修正 + 编码器估距 + 保险杠/红外传感器”完成清扫任务；高端扫地机则靠激光雷达/视觉 SLAM 建图导航，IMU 只是辅助定位。**

------
**惯性导航**，英文叫 **INS：Inertial Navigation System**，直译就是：

> 靠自身的惯性传感器，估算“我现在的位置、速度、姿态”。

简单说，它不靠 GPS、雷达、摄像头、外部基站，而是靠自己身上的 **IMU** 来推算自己怎么运动。

---

## 1. 惯性导航靠什么传感器？

核心就是 **IMU**：

```text
IMU = 加速度计 + 陀螺仪
```

有些 IMU 还带磁力计，就是 9 轴 IMU：

```text
加速度计：测加速度
陀螺仪：测角速度
磁力计：辅助判断方向，类似电子指南针
```

对扫地机器人来说，最主要的是：

```text
陀螺仪 Z 轴：判断机器人转了多少角度
加速度计 X/Y 轴：判断有没有加速、减速、碰撞、震动
加速度计 Z 轴：判断倾斜、抬起、跌落异常
```

---

## 2. 惯性导航的基本思想

它的核心逻辑是：

```text
角速度 -> 积分 -> 角度
加速度 -> 积分 -> 速度 -> 再积分 -> 位置
```

比如陀螺仪测到机器人正在旋转：

```text
gyro_z = 90 °/s
```

如果持续 1 秒：

```text
转过角度 = 90 °/s × 1s = 90°
```

所以机器人就知道自己大概转了 90 度。

加速度也是类似：

```text
加速度 a -> 积分得到速度 v
速度 v -> 积分得到位移 s
```

例如：

```text
机器人以 1 m/s² 加速 2 秒
速度大概变成 2 m/s
位移大概是 2 米
```

这就是惯性导航的基础。

---

## 3. 更形象一点理解

你可以把惯性导航想成一个人闭着眼走路。

他不能看到外界，但是他可以感觉到：

```text
我刚刚往前加速了
我刚刚左转了
我刚刚停下了
我刚刚被撞了一下
我现在身体倾斜了
```

然后他在脑子里估算：

```text
我应该走了 3 米
我应该向右转了 90 度
我现在应该在原点前方某个位置
```

这就是惯性导航。

但是问题是：**闭着眼走久了，一定会偏。**

---

## 4. 惯性导航为什么会漂移？

因为 IMU 有误差。

假设加速度计有一个很小的零偏：

```text
真实加速度 = 0
传感器读数 = 0.02 m/s²
```

机器人明明没动，但你算法以为它一直在加速。

然后：

```text
0.02 m/s² 积分后变成速度误差
速度误差再积分后变成位置误差
```

时间越久，误差越大。

所以惯性导航有个很大的问题：

```text
短时间还可以
长时间会严重漂移
```

尤其是加速度积分两次得到位置，这个误差会炸得非常快。

---

## 5. 惯性导航能不能单独用？

看场景。

### 飞机、导弹、火箭

可以用高精度惯导，因为它们用的是非常贵的 IMU：

```text
激光陀螺
光纤陀螺
高精度 MEMS IMU
```

这些 IMU 成本高，精度高。

### 手机、扫地机器人、普通 MCU 项目

通常用的是便宜 MEMS IMU，比如：

```text
MPU6050
BMI160
QMI8658
ICM42688
LSM6DS3
```

这种 IMU 做姿态、角度、震动检测还可以。

但是要单靠它算位置，基本不靠谱。

---

## 6. 在扫地机器人里，惯性导航主要用来干啥？

扫地机器人里面的惯性导航一般不是单独完成定位，而是辅助：

```text
1. 保持直线
2. 判断转弯角度
3. 辅助轮子编码器做里程计
4. 检测碰撞
5. 检测打滑
6. 检测倾斜/抬起/卡住
```

例如机器人要右转 90 度：

```c
yaw_start = imu_yaw;

while (abs(imu_yaw - yaw_start) < 90.0f)
{
    left_motor_reverse();
    right_motor_forward();
}

motor_stop();
```

这里就是用陀螺仪积分出来的 yaw 角控制转向。

---

## 7. 惯性导航和轮子编码器的关系

扫地机器人通常不会只靠 IMU，而是：

```text
轮子编码器：估算走了多远
IMU：估算转了多少角度
```

也就是：

```text
编码器负责距离
陀螺仪负责方向
```

比如：

```text
左轮转了多少圈
右轮转了多少圈
```

可以算出机器人前进了多少距离。

IMU 可以修正方向漂移：

```text
本来想直走
但机器人偏右了
IMU 检测到 yaw 变了
于是降低左轮速度/提高右轮速度
把方向拉回来
```

所以低成本机器人常用的是：

```text
轮子里程计 + IMU
```

这也叫：

```text
航位推算 / Dead Reckoning
```

---

## 8. 惯性导航和 SLAM 的区别

这个很重要。

### 惯性导航

```text
只靠自身运动推算位置
```

缺点：

```text
误差会一直累积
不知道外界环境
不能知道前面有没有障碍物
```

### SLAM

```text
边建图，边定位
```

它需要外部传感器：

```text
激光雷达
摄像头
ToF
结构光
深度相机
```

SLAM 可以知道：

```text
我在哪里
墙在哪里
障碍物在哪里
哪些地方扫过
哪些地方没扫
```

所以高端扫地机一般是：

```text
激光雷达/视觉 SLAM + 轮子编码器 + IMU
```

IMU 只是辅助，不是唯一核心。

---

## 9. 对你做扫地机器人的理解

如果你现在用的是 **QMI8658A / BMI160 这种 IMU**，它在扫地机器人里更适合做：

```text
姿态检测
转角控制
直线保持
碰撞辅助检测
抬起检测
跌落/倾斜检测
卡住检测
运动状态判断
```

不适合单独做：

```text
精确定位
建图
路径规划
主动避障
长时间导航
```

你可以这样理解：

```text
IMU 惯性导航 = 短时间知道自己怎么动了
雷达/视觉 SLAM = 长时间知道自己在哪里
碰撞/红外/ToF = 知道前面有没有东西
```

---

## 10. 一句话总结

**惯性导航就是靠 IMU 的加速度计和陀螺仪，通过积分计算机器人的姿态、速度和位置。它短时间有用，适合辅助转向、直线保持、碰撞/倾斜检测；但长期会漂移，单靠它不能可靠完成扫地机器人的地图导航和主动避障。**
