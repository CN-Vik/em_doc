你现在这个命令：

```bat
ssh tiger_vik@192.168.1.100
```

**只适合你电脑和服务器在同一个局域网里**。比如你笔记本也连着公司/办公室同一个路由器，这样可以连。

但是你在家里时，`192.168.1.100` 这个地址就访问不到了，因为它是**内网 IP**，不是公网 IP。家里要登录这台服务器，需要先做远程通道。

我建议你用 **Tailscale**，对新手最简单，也不需要暴露 SSH 到公网。Tailscale 官方说明它可以把设备组成一个私有网络；Linux 端也支持通过 tailnet 安全访问 SSH，不需要把 SSH 暴露到公网。([Tailscale][1])

## 推荐方案：Tailscale 远程登录服务器

### 1. 在服务器 Ubuntu 上开启 SSH

在服务器本机执行：

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

确认本地能 SSH：

```bash
ssh tiger_vik@192.168.1.100
```

如果在同一局域网里能登录，说明 SSH 服务没问题。

### 2. 服务器安装 Tailscale

在服务器 Ubuntu 上执行：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

它会给你一个登录链接，用浏览器登录。

然后查看服务器的 Tailscale IP：

```bash
tailscale ip -4
```

你会看到类似：

```bash
100.80.23.6
```

这个 `100.x.x.x` 才是你在家里要连的地址。

---

### 3. 家里的 Windows 也安装 Tailscale

家里的 Windows 安装并登录同一个 Tailscale 账号。

然后你在 Windows CMD 里这样连：

```bat
ssh tiger_vik@100.80.23.6
```

也就是把原来的：

```bat
ssh tiger_vik@192.168.1.100
```

改成：

```bat
ssh tiger_vik@服务器的Tailscale-IP
```

Windows 里直接用 `ssh 用户名@主机` 这种方式是正常的，微软文档也说明 Windows Terminal/命令行可以这样启动 SSH 会话。([Microsoft Learn][2])

## 不太建议新手直接用公网端口转发

```conf
PermitRootLogin no
```

然后：


## 一、先确认服务器本地 SSH 正常

在服务器本机执行：

```bash
sudo systemctl status ssh
```

如果没装 SSH：

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

在同一个局域网电脑上测试：

```bash
ssh tiger_vik@192.168.1.100
```

这一步必须成功。否则端口转发做了也没用。

---

## 二、给服务器固定内网 IP

你的服务器现在是：

```text
192.168.1.100
```

最好在路由器后台里做一个 **DHCP 静态绑定**：

```text
服务器 MAC 地址  ->  192.168.1.100
```

否则哪天服务器 IP 变成 `192.168.1.101`，端口转发就失效了。

---

## 三、进入路由器后台设置端口转发

浏览器打开路由器管理地址，常见是：

```text
192.168.1.1
192.168.0.1
```

登录后找这些菜单之一：

```text
端口转发
虚拟服务器
NAT 转发
Port Forwarding
Virtual Server
```

添加一条规则：

```text
名称：SSH-Server
外部端口：2222
内部IP：192.168.1.100
内部端口：22
协议：TCP
状态：启用
```

也就是：

```text
公网IP:2222  --->  192.168.1.100:22
```

不要直接把外部端口设成 `22`，建议用 `2222`、`2022` 这种，减少被扫到的概率。

---

## 四、Ubuntu 防火墙放行 SSH

如果你服务器开了 `ufw`，执行：

```bash
sudo ufw status
```

如果是启用状态，放行 SSH：

```bash
sudo ufw allow 22/tcp
```

或者如果你把服务器 SSH 本身也改成了 2222，则放行：

```bash
sudo ufw allow 2222/tcp
```

但按照上面那种路由器转发方式，服务器内部仍然是 `22`，所以放行 `22/tcp` 就行。

## 五、查公网 IP

在服务器所在网络里打开浏览器搜索：

```text
我的公网IP
```

假设查到：

```text
123.123.123.123
```

然后你在家里 Windows CMD 里连接：

```bat
ssh -p 2222 tiger_vik@123.123.123.123
```

注意，不是：

```bat
ssh tiger_vik@192.168.1.100
```

而是：

```bat
ssh -p 2222 tiger_vik@公网IP
```

## 六、非常关键：确认你有没有真正的公网 IP

这是很多人卡住的地方。

你要看路由器后台里的 **WAN IP / Internet IP**，比如：

```text
路由器 WAN IP：123.123.123.123
网页查到公网IP：123.123.123.123
```

如果这两个一样，说明你有公网 IP，端口转发大概率可以用。

但是如果路由器 WAN IP 是这种：

```text
10.x.x.x
100.64.x.x ~ 100.127.x.x
172.16.x.x ~ 172.31.x.x
192.168.x.x
```

那你大概率在运营商 **大内网 / CGNAT** 后面。

这种情况下，你在自己路由器上做端口转发也没用，因为外面访问不到你的路由器。

解决办法有几个：

```text
1. 找运营商要公网 IP
2. 用 Tailscale / ZeroTier
3. 用 frp 内网穿透
4. 用云服务器做反向代理/跳板机
```

## 七、测试端口是否打开

不要在同一个 Wi-Fi 下测试公网 IP，有些路由器不支持 NAT 回环。

你可以用手机开热点，让电脑连手机热点，然后执行：

```bat
ssh -p 2222 tiger_vik@你的公网IP
```

或者手机用流量测试。

如果连上了，说明端口转发成功。

## 八、强烈建议做 SSH 安全加固

公网暴露 SSH 后，会有大量机器人扫端口、爆破密码。建议至少做这些。

### 1. 禁止 root 登录

```bash
sudo nano /etc/ssh/sshd_config
```

找到或添加：

```conf
PermitRootLogin no
```

### 2. 最好关闭密码登录，改用密钥

先在你家里的 Windows 上生成密钥：

```bat
ssh-keygen
```

一路回车即可。

把公钥复制到服务器：

```bat
type %USERPROFILE%\.ssh\id_rsa.pub
```

把输出内容复制到服务器的：

```bash
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
```

粘进去后执行：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

确认密钥登录成功后，再关闭密码登录：

```bash
sudo nano /etc/ssh/sshd_config
```

改成：

```conf
PasswordAuthentication no
PubkeyAuthentication yes
PermitRootLogin no
```

重启 SSH：

```bash
sudo systemctl restart ssh
```

### 3. 安装 fail2ban 防爆破

```bash
sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
```

## 九、如果公网 IP 会变，配置 DDNS

家用宽带公网 IP 可能会变。你可以用 DDNS，比如花生壳、阿里云 DDNS、腾讯云 DDNS、路由器自带 DDNS。

配置后你就不用记公网 IP 了，可以这样登录：

```bat
ssh -p 2222 tiger_vik@你的域名
```

例如：

```bat
ssh -p 2222 tiger_vik@vik-server.example.com
```

```bash
ssh tiger_vik@服务器的Tailscale-IP
```

比如：

# 方案二：frp + 云服务器

如果你想以后像这样访问：

```bash
ssh -p 6000 tiger_vik@你的云服务器公网IP
```

可以用 frp。

原理是：

```text
公司服务器主动连接云服务器
家里电脑连接云服务器的某个端口
云服务器再把连接转回公司服务器
```

结构：

```text
家里 Ubuntu
    |
    | ssh -p 6000 tiger_vik@云服务器IP
    v
云服务器 frps
    |
    | frp 隧道
    v
公司 Ubuntu 服务器 frpc
    |
    v
本地 ssh 22端口
```

你需要一台有公网 IP 的云服务器，比如腾讯云、阿里云、华为云、轻量服务器都行。

---

## 云服务器上配置 frps

下载 frp 后，云服务器配置 `frps.toml`：

```toml
bindPort = 7000
```

启动：

```bash
./frps -c frps.toml
```

云服务器安全组要放行：

```text
7000/tcp
6000/tcp
```

---

## 公司服务器上配置 frpc

公司服务器配置 `frpc.toml`：

```toml
serverAddr = "你的云服务器公网IP"
serverPort = 7000

[[proxies]]
name = "company-ssh"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 6000
```

启动：

```bash
./frpc -c frpc.toml
```

---

## 家里 Ubuntu 登录

```bash
ssh -p 6000 tiger_vik@你的云服务器公网IP
```

这样也不需要配置公司路由器，因为是公司服务器主动连云服务器。

---

# 方案三：SSH 反向隧道

这个也需要一台公网云服务器。

公司服务器执行：

```bash
ssh -N -R 6000:localhost:22 云服务器用户名@云服务器公网IP
```

然后你在家里连接云服务器的 `6000` 端口：

```bash
ssh -p 6000 tiger_vik@云服务器公网IP
```

不过这个方案有坑，云服务器 SSH 配置里可能需要打开：

```conf
GatewayPorts yes
AllowTcpForwarding yes
```

然后重启云服务器 SSH：

```bash
sudo systemctl restart ssh
```

这个方案比 frp 更容易掉线，后续还要配 `autossh` 保活。
