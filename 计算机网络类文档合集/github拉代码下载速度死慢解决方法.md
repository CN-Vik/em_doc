这是因为你使用了 **SSH 协议**（`git@github.com:...`）来克隆仓库。

**原因分析：**
Clash Verge 的“系统代理”默认只接管网页和软件的 **HTTP/HTTPS** 流量，而 **SSH 属于 TCP 协议**，默认根本不走代理！所以就算你开了 Clash，下载速度依然只有可怜的 100 KiB/s。

针对你的情况，有以下 **3 种最快、最有效**的解决办法，推荐你从方法一或方法二开始尝试：

---

### 方法一：开启 Clash Verge 的“TUN 模式”（最省心，一劳永逸 ✨）

TUN 模式（虚拟网卡模式）会在系统层创建一个虚拟网卡，强制接管你电脑上的**所有网络流量**（包括 Git 的 SSH 流量）。

1. 打开 Clash Verge 软件。
2. 在左侧菜单进入 **“设置” (Settings)**。
3. 找到 **“TUN 模式” (Tun Mode)**，点击开关将其**开启**。（注意：Windows 可能会弹窗提示需要管理员权限，同意即可）。
4. 开启后，不需要修改任何 Git 配置，直接重新在 PowerShell 里运行你的 `git clone`，速度直接起飞！

---

### 方法二：换成 HTTPS 链接克隆 + 设置 Git 代理（最经典、稳定）

如果你不想开 TUN 模式，可以改用 HTTPS 方式克隆，并给 Git 单独配置 Clash 代理。

#### 1. 查看你的 Clash Verge 端口

打开 Clash Verge，在界面左下角或主界面上，查看 **Mixed Port（混合端口）** 是多少。

* 默认通常是 **`7890`** 或 **`7897`**（根据软件版本不同会有所变化，以下以 `7890` 为例，如果你的界面显示是 `7897`，请把下面的代码数字改成 `7897`）。

#### 2. 在 PowerShell 中给 Git 设置代理

复制并运行以下两条命令：

```powershell
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

```

#### 3. 使用 HTTPS 链接克隆

将你原来的 `git@github.com:...` 换成 `https://github.com/...`：

```powershell
git clone https://github.com/CN-Vik/vik_diy_bldc_driver.git

```

此时 Git 就会乖乖走你的 Clash 代理，速度立刻拉满。

*(注：如果你以后不需要代理了，可以用 `git config --global --unset http.proxy` 来取消设置)*

---

### 方法三：坚持用 SSH 链接克隆，但给 SSH 配置代理（适合 SSH 爱好者）

如果你就是想用 SSH 秘钥，不想用 HTTPS 输密码，可以给 SSH 配置文件塞一行代理指令。

1. 在键盘上按 `Win + R` 键，输入 `%userprofile%\.ssh` 并回车，打开 SSH 的配置文件夹。
2. 在该文件夹下找一个名为 `config` 的文件（如果没有，就右键新建一个文本文档，命名为 `config`，**不要有 `.txt` 后缀**）。
3. 用记事本打开它，把以下内容粘进去（注意：其中的 `7890` 同样要对应你的 Clash Verge 混合端口）：

```text
Host github.com
    User git
    # Connect 它是 Git for Windows 自带的代理转换工具，直接调用即可
    ProxyCommand connect -S 127.0.0.1:7890 %h %p

```

4. 保存文件。回到 PowerShell 重新 `git clone git@github.com:...` 即可直接走代理极速下载！

# >>>设置 SSH 配置确实管用啊! 为啥啊？？

哈哈，是不是感觉像变魔术一样！速度直接从可怜的 100K 飙升到满速。

这个原理其实非常巧妙，用大白话来说就是：**我们给 SSH 强行指派了一个“快递员”，把本该走不通的包裹，通过 Clash 的专属通道送了出去。**

下面我为你硬核拆解一下这几行代码背后的**网络原理**：

### 1. 为什么之前不用这行代码就那么慢？

之前你用 `git@github.com` 下载时，使用的是 **SSH 协议（走的是 22 号端口，纯 TCP 流量）**。
Windows 系统的那个“代理”开关，默认只管网页流量（HTTP/HTTPS，走 80 或 443 端口）。所以，当你敲下 `git clone` 时，SSH 协议一看：“哦，系统代理不管我”，于是它就**傻傻地尝试直连远在美国的 GitHub 服务器**。由于跨国网络的原因，速度自然就变成了龟速。

### 2. 这几行代码到底施了什么魔法？

我们把最关键的这一行拆开看：
`ProxyCommand connect -S 127.0.0.1:7890 %h %p`

* **`Host github.com`**：这是触发条件。意思是“只要 Git 尝试连接 `github.com`，就执行下面的特殊规则”。
* **`ProxyCommand`**：这是 SSH 的“最高指令”。它告诉 SSH 客户端：“**你别自己去连 GitHub 了，把你产生的数据全部交给后面这个程序来处理。**”
* **`connect`**：这是最大的功臣！它是 Git for Windows 安装时**偷偷自带的一个极简代理转发小工具**（它其实是一个名叫 `connect.exe` 的程序）。
* **`-S 127.0.0.1:7890`**：这是给 `connect` 工具下的命令。意思是：“请你使用 **SOCKS5 代理协议 (`-S`)**，把数据送到我本机的 `7890` 端口（这刚好就是 **Clash Verge 开门接客的端口**）”。
* **`%h %p`**：这是占位符。SSH 运行时会自动把它们替换成目标地址和端口（即 `github.com 22`）。

### ⚙️ 完整的流量运作流程（流水线）：

1. 你在 PowerShell 敲下 `git clone`。
2. Git 发现要连 GitHub，触发了你写的 `config` 规则。
3. Git 停止直连，把原始的下载请求全丢给了小工具 `connect.exe`。
4. `connect.exe` 把这些请求包装成了 Clash 能听懂的 **SOCKS5 格式**，然后从本机的 `7890` 端口塞进了 Clash Verge。
5. **Clash 收到包裹后，立刻走它的加密节点隧道，直接秒连 GitHub。**
6. GitHub 把代码传给 Clash，Clash 传给 `connect.exe`，最后回到你的本地文件夹。

**总结：**
这行代码本质上就是起到了“**强制路由**”的作用，巧妙地利用了 Git 自带的转发工具，把底层不听话的 TCP 流量强行塞进了 Clash 的高速通道里。这就是它能瞬间起飞的奥秘！
