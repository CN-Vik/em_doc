可以。下面我给你一套**初创公司自建 GitLab 服务器的完整落地教程**，按“能正式用”的方式来，不是玩具教程。

我推荐路线：

```text
闲置电脑 / 小主机
→ 安装 Ubuntu Server
→ 安装 GitLab CE Linux Package
→ 配置固定 IP / 域名
→ 配置 HTTPS
→ 创建用户和项目
→ 配置权限
→ 配置备份
→ 后续再接 GitLab Runner
```

GitLab 官方推荐的 Linux Package 安装方式支持用 `EXTERNAL_URL` 一步设置访问地址；GitLab CE 对应用 `gitlab-ce` 包。官方文档也说明，基础 GitLab 安装即使不算仓库数据，也建议至少预留 40GB 磁盘；1000 用户 / 20 RPS 级别参考配置是 8 vCPU 和 16GB 内存，少量用户可以低一些，但公司用建议别太抠。([GitLab 文档][1])

# 一、先定你的部署方案

## 方案 A：公司内网使用，推荐第一步先这样

比如服务器 IP 是：

```text
192.168.1.10
```

GitLab 地址就是：

```text
http://192.168.1.10
```

或者你在局域网 DNS / hosts 里配一个名字：

```text
http://gitlab.company.local
```

这种最简单，适合先跑通。

---

## 方案 B：公网访问，正式公司更常见

比如域名：

```text
gitlab.your-company.com
```

访问地址：

```text
https://gitlab.your-company.com
```

公网版需要：

```text
域名
公网 IP
路由器端口映射
80/443 端口开放
HTTPS 证书
```

GitLab 的 Linux Package 支持 Let’s Encrypt 自动 HTTPS，但前提是 `external_url` 使用 HTTPS，并且 80、443 端口能被 Let’s Encrypt 公网服务器访问。([GitLab 文档][2])

# 二、服务器硬件建议

你说找闲置电脑，可以，但建议最低这样：

```text
CPU：4 核以上
内存：16GB 推荐，8GB 勉强
硬盘：256GB SSD 起步
网卡：千兆有线网
电源：最好配 UPS
系统：Ubuntu Server 22.04 / 24.04
```

不建议：

```text
2 核 4GB
机械硬盘
Windows + Docker Desktop
普通家用宽带直接暴露公网
没有备份
```

GitLab 对磁盘 IO 比较敏感，官方也建议使用 7200 RPM 以上硬盘或 SSD。([GitLab 文档][3])

# 四、设置固定 IP

公司服务器不能让 IP 乱变。

## 推荐方法：路由器里绑定固定 IP

进路由器后台，找到类似：

```text
DHCP 静态分配
地址保留
IP-MAC 绑定
```

把 GitLab 服务器固定成：

```text
192.168.1.10
```

这是最简单、最不容易出错的方式。

---

## 也可以在 Ubuntu 里设置静态 IP

先看网卡名：

```bash
ip link
```

可能叫：

```text
enp3s0
ens33
eth0
```

编辑 netplan：

```bash
sudo nano /etc/netplan/00-installer-config.yaml
```

示例：

```yaml
network:
  version: 2
  ethernets:
    enp3s0:
      dhcp4: no
      addresses:
        - 192.168.1.10/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 223.5.5.5
          - 8.8.8.8
```

应用：

```bash
sudo netplan apply
```

然后测试：

```bash
ping 192.168.1.1
ping baidu.com
```

# 八、安装 GitLab CE

## 1. 添加 GitLab CE 软件源

```bash
curl --location "https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.deb.sh" | sudo bash
```

GitLab 官方 Ubuntu 安装文档里，CE 版本就是通过 `gitlab/gitlab-ce` 软件源安装，然后安装 `gitlab-ce` 包。([GitLab 文档][1])

---

## 2. 选择你的访问地址

### 情况 1：只在公司内网用 IP 访问

```bash
sudo EXTERNAL_URL="http://192.168.1.10" apt install gitlab-ce
```

### 情况 2：公司内网用域名访问

比如你想用：

```text
gitlab.company.local
```

那就：

```bash
sudo EXTERNAL_URL="http://gitlab.company.local" apt install gitlab-ce
```

然后在你自己的 Windows 电脑 hosts 文件里加：

```text
192.168.1.10 gitlab.company.local
```

Windows hosts 文件路径：

```text
C:\Windows\System32\drivers\etc\hosts
```

### 情况 3：公网域名 + HTTPS

比如：

```text
gitlab.your-company.com
```

先确保 DNS A 记录已经指向你的公网 IP，然后路由器映射：

```text
公网 80  → 192.168.1.10:80
公网 443 → 192.168.1.10:443
```

再执行：

```bash
sudo EXTERNAL_URL="https://gitlab.your-company.com" apt install gitlab-ce
```

如果使用 HTTPS 且没有手动证书，GitLab 的 Linux Package 会默认使用 Let’s Encrypt；但 80 和 443 必须能从公网访问。([GitLab 文档][2])

# 十二、配置邮件 SMTP

公司使用一定要配邮件，否则这些功能不好用：

```text

密码找回
Merge Request 通知
Pipeline 通知
账号验证
```

编辑：

```bash
sudo nano /etc/gitlab/gitlab.rb
```

示例，按你的企业邮箱改：

```ruby
gitlab_rails['smtp_enable'] = true

gitlab_rails['smtp_user_name'] = "gitlab@your-company.com"

gitlab_rails['smtp_domain'] = "your-company.com"
gitlab_rails['smtp_authentication'] = "login"
gitlab_rails['smtp_enable_starttls_auto'] = true

gitlab_rails['gitlab_email_from'] = "gitlab@your-company.com"
gitlab_rails['gitlab_email_display_name'] = "Company GitLab"
```

应用：

```bash
sudo gitlab-ctl reconfigure
```

测试邮件：

```bash
sudo gitlab-rails console
```

进入控制台后输入：

```ruby
Notify.test_email('你的邮箱@example.com', 'GitLab test', 'Hello from GitLab').deliver_now
```

退出：

```ruby
exit
```

GitLab 官方 SMTP 文档说明，如果不用 Sendmail/Postfix，可以在 `/etc/gitlab/gitlab.rb` 配置 SMTP，然后执行 `gitlab-ctl reconfigure`。([GitLab 文档][6])

# 二十、备份，这是公司自建最重要的部分

GitLab 备份不能只备份 Git 仓库。还要备份：

```text
数据库
用户
项目
Issue
Merge Request
Wiki
LFS
上传文件
CI 配置
GitLab secrets
配置文件
```

官方文档特别说明，Linux Package 的配置在 `/etc/gitlab`，尤其 `gitlab-secrets.json` 包含数据库加密密钥、2FA、CI/CD 变量等相关密钥；如果丢失，恢复后可能出现 2FA 用户无法登录、CI 变量丢失等问题。([GitLab 文档][7])

---

## 1. 手动创建应用备份

```bash
sudo gitlab-backup create
```

默认备份目录：

```bash
/var/opt/gitlab/backups
```

GitLab 官方说明，应用备份默认会保存到 `/var/opt/gitlab/backups`。([GitLab 文档][7])

查看：

```bash
sudo ls -lh /var/opt/gitlab/backups
```

---

## 2. 手动备份配置和 secrets

```bash
sudo gitlab-ctl backup-etc
```

默认保存到：

```bash
/etc/gitlab/config_backup/
```

官方文档说明，`sudo gitlab-ctl backup-etc` 会把 `/etc/gitlab` 的配置打包到 `/etc/gitlab/config_backup/`。([GitLab 文档][7])

---

## 3. 设置备份保留时间

编辑：

```bash
sudo nano /etc/gitlab/gitlab.rb
```

加入：

```ruby
gitlab_rails['backup_keep_time'] = 604800
```

这个表示保留 7 天：

```text
604800 秒 = 7 天
```

应用：

```bash
sudo gitlab-ctl reconfigure
```

GitLab 官方文档说明，`backup_keep_time` 默认是 0，也就是保留所有备份；设置成 604800 可以限制为 7 天。([GitLab 文档][7])

---

## 4. 每天自动备份

编辑 root 的定时任务：

```bash
sudo crontab -e -u root
```

加入：

```cron
0 2 * * * /opt/gitlab/bin/gitlab-backup create CRON=1
20 2 * * * /opt/gitlab/bin/gitlab-ctl backup-etc
```

意思是：

```text
每天 02:00 备份 GitLab 数据
每天 02:20 备份 GitLab 配置
```

GitLab 官方文档也建议通过 root 的 crontab 配置每日备份。([GitLab 文档][7])

---

## 5. 把备份同步到另一台机器

这一步非常重要。

本机备份不叫真正备份。硬盘坏了，本机备份也没了。

假设你有一台 NAS：

```text
192.168.1.20
```

创建同步脚本：

```bash
sudo nano /usr/local/bin/gitlab_backup_sync.sh
```

写入：

```bash
#!/bin/bash

set -e

REMOTE_USER="backup"
REMOTE_HOST="192.168.1.20"
REMOTE_DIR="/data/backup/gitlab"

rsync -av --delete /var/opt/gitlab/backups/ ${REMOTE_USER}@${REMOTE_HOST}:${REMOTE_DIR}/app/
rsync -av /etc/gitlab/config_backup/ ${REMOTE_USER}@${REMOTE_HOST}:${REMOTE_DIR}/config/
```

授权：

```bash
sudo chmod +x /usr/local/bin/gitlab_backup_sync.sh
```

加入定时任务：

```bash
sudo crontab -e -u root
```

添加：

```cron
40 2 * * * /usr/local/bin/gitlab_backup_sync.sh
```

最终每天流程：

```text
02:00 生成 GitLab 应用备份
02:20 生成 GitLab 配置备份
02:40 同步到 NAS / 另一台服务器
```

# 二十一、恢复演练，必须做

只备份不测试恢复，等于没备份。

GitLab 官方恢复文档要求：恢复目标 GitLab 必须是**同版本、同类型 CE/EE**；恢复时还必须恢复 GitLab secrets。([GitLab 文档][8])

简单恢复流程大概是：

```bash
sudo cp xxx_gitlab_backup.tar /var/opt/gitlab/backups/
sudo chown git:git /var/opt/gitlab/backups/xxx_gitlab_backup.tar

sudo gitlab-ctl stop puma
sudo gitlab-ctl stop sidekiq
sudo gitlab-ctl status

sudo gitlab-backup restore BACKUP=xxx

sudo gitlab-ctl reconfigure
sudo gitlab-ctl start
sudo gitlab-rake gitlab:check SANITIZE=true
```

注意这里的 `BACKUP=xxx` 不带 `_gitlab_backup.tar` 后缀。官方恢复文档也是这样要求的。([GitLab 文档][8])

公司建议：

```text
每个月找一台测试机
用最新备份恢复一次
确认项目、用户、仓库、Issue 都正常
```

# 二十三、如果要公网访问，路由器怎么配？

假设：

```text
GitLab 服务器内网 IP：192.168.1.10
域名：gitlab.your-company.com
```

你需要做：

## 1. DNS 解析

在域名服务商那里添加：

```text
A 记录
主机记录：gitlab
记录值：你的公网 IP
```

最终：

```text
gitlab.your-company.com → 你的公网 IP
```

---

## 2. 路由器端口映射

```text
公网 80  → 192.168.1.10:80
公网 443 → 192.168.1.10:443
公网 22  → 192.168.1.10:22
```

不过我不建议直接把 SSH 22 暴露到公网。

更稳的是：

```text
公网只开 80/443
员工通过 HTTPS 拉代码
管理员通过 VPN 进内网 SSH
```

或者：

```text
使用 WireGuard / Tailscale / ZeroTier
GitLab 不直接暴露公网 SSH
```

# 二十四、公司安全建议

最低限度做这些：

```text
1. root 账号改强密码
2. 管理员账号开启 2FA
3. 禁止公开注册
4. main/master 分支保护
5. 普通开发不要给 Maintainer
6. 外包只给单项目权限
7. 每天备份到另一台机器
8. 每月恢复演练
9. 不要把 GitLab 和大型编译 Runner 混在同一台弱机器上
10. 公网访问必须 HTTPS
```

## 2. 选择你的访问地址

### 情况 1：只在公司内网用 IP 访问

```bash
sudo EXTERNAL_URL="http://192.168.1.10" apt install gitlab-ce
```

### 情况 2：公司内网用域名访问

比如你想用：

```text
gitlab.company.local
```

那就：

```bash

```


```bash

```

如果使用 HTTPS 且没有手动证书，GitLab 的 Linux Package 会默认使用 Let’s Encrypt；但 80 和 443 必须能从公网访问。([GitLab 文档][2])

# 二十、备份，这是公司自建最重要的部分

GitLab 备份不能只备份 Git 仓库。还要备份：

```text
数据库
用户
项目
Issue
```

---

## 1. 手动创建应用备份

```bash
sudo gitlab-backup create
```

默认备份目录：

```bash
/var/opt/gitlab/backups
```

GitLab 官方说明，应用备份默认会保存到 `/var/opt/gitlab/backups`。([GitLab 文档][7])

查看：

```bash
sudo ls -lh /var/opt/gitlab/backups
```

---

## 2. 手动备份配置和 secrets

```bash
sudo gitlab-ctl backup-etc
```

默认保存到：

```bash
/etc/gitlab/config_backup/
```

官方文档说明，`sudo gitlab-ctl backup-etc` 会把 `/etc/gitlab` 的配置打包到 `/etc/gitlab/config_backup/`。([GitLab 文档][7])

---

## 3. 设置备份保留时间

编辑：

```bash
sudo nano /etc/gitlab/gitlab.rb
```

加入：

```ruby
gitlab_rails['backup_keep_time'] = 604800
```

这个表示保留 7 天：

```text
604800 秒 = 7 天
```

应用：

```bash
sudo gitlab-ctl reconfigure
```

GitLab 官方文档说明，`backup_keep_time` 默认是 0，也就是保留所有备份；设置成 604800 可以限制为 7 天。([GitLab 文档][7])

---

## 4. 每天自动备份

编辑 root 的定时任务：

```bash
sudo crontab -e -u root
```

加入：

```cron
0 2 * * * /opt/gitlab/bin/gitlab-backup create CRON=1
20 2 * * * /opt/gitlab/bin/gitlab-ctl backup-etc
```

意思是：

```text
每天 02:00 备份 GitLab 数据
每天 02:20 备份 GitLab 配置
```

GitLab 官方文档也建议通过 root 的 crontab 配置每日备份。([GitLab 文档][7])

---

## 5. 把备份同步到另一台机器

这一步非常重要。

本机备份不叫真正备份。硬盘坏了，本机备份也没了。

假设你有一台 NAS：

```text
192.168.1.20
```

创建同步脚本：

```bash
sudo nano /usr/local/bin/gitlab_backup_sync.sh
```

写入：

```bash
#!/bin/bash

set -e

REMOTE_USER="backup"
REMOTE_HOST="192.168.1.20"
REMOTE_DIR="/data/backup/gitlab"

rsync -av --delete /var/opt/gitlab/backups/ ${REMOTE_USER}@${REMOTE_HOST}:${REMOTE_DIR}/app/
rsync -av /etc/gitlab/config_backup/ ${REMOTE_USER}@${REMOTE_HOST}:${REMOTE_DIR}/config/
```

授权：

```bash
sudo chmod +x /usr/local/bin/gitlab_backup_sync.sh
```

加入定时任务：

```bash
sudo crontab -e -u root
```

添加：

```cron
40 2 * * * /usr/local/bin/gitlab_backup_sync.sh
```

最终每天流程：

```text
02:00 生成 GitLab 应用备份
02:20 生成 GitLab 配置备份
02:40 同步到 NAS / 另一台服务器
```

# 二十一、恢复演练，必须做

只备份不测试恢复，等于没备份。

GitLab 官方恢复文档要求：恢复目标 GitLab 必须是**同版本、同类型 CE/EE**；恢复时还必须恢复 GitLab secrets。([GitLab 文档][8])

简单恢复流程大概是：

```bash
sudo cp xxx_gitlab_backup.tar /var/opt/gitlab/backups/
sudo chown git:git /var/opt/gitlab/backups/xxx_gitlab_backup.tar

sudo gitlab-ctl stop puma
sudo gitlab-ctl stop sidekiq
sudo gitlab-ctl status

sudo gitlab-backup restore BACKUP=xxx

sudo gitlab-ctl reconfigure
sudo gitlab-ctl start
sudo gitlab-rake gitlab:check SANITIZE=true
```

注意这里的 `BACKUP=xxx` 不带 `_gitlab_backup.tar` 后缀。官方恢复文档也是这样要求的。([GitLab 文档][8])

公司建议：

```text
每个月找一台测试机
用最新备份恢复一次
确认项目、用户、仓库、Issue 都正常
```

# 二十三、如果要公网访问，路由器怎么配？

假设：

```text
GitLab 服务器内网 IP：192.168.1.10
域名：gitlab.your-company.com
```

你需要做：

## 1. DNS 解析

在域名服务商那里添加：

```text
A 记录
主机记录：gitlab
记录值：你的公网 IP
```

最终：

```text
gitlab.your-company.com → 你的公网 IP
```

---

## 2. 路由器端口映射

```text
公网 80  → 192.168.1.10:80
公网 443 → 192.168.1.10:443
公网 22  → 192.168.1.10:22
```

不过我不建议直接把 SSH 22 暴露到公网。

更稳的是：

```text
公网只开 80/443
员工通过 HTTPS 拉代码
管理员通过 VPN 进内网 SSH
```

或者：

```text
使用 WireGuard / Tailscale / ZeroTier
GitLab 不直接暴露公网 SSH
```

# 二十六、你现在照这个顺序做

最推荐你第一阶段先做内网版：

```text
1. 闲置电脑装 Ubuntu Server
2. 固定 IP：192.168.1.10
3. 安装 GitLab CE
4. external_url 用 http://192.168.1.10
5. 浏览器登录 root
6. 创建 group
7. 创建项目
8. 本机 git clone / git push 测试
9. 配置每日备份
10. 再考虑公网域名和 HTTPS
```

第一阶段命令汇总：

```bash
sudo apt update
sudo apt upgrade -y

sudo apt install -y curl openssh-server ca-certificates tzdata perl locales vim ufw
sudo locale-gen en_US.UTF-8

sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw enable

curl --location "https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.deb.sh" | sudo bash

sudo EXTERNAL_URL="http://192.168.1.10" apt install gitlab-ce

sudo cat /etc/gitlab/initial_root_password
```

然后浏览器访问：

```text
http://192.168.1.10
```

登录：

```text
用户名：root
密码：/etc/gitlab/initial_root_password 里的 Password
```

跑通以后，再做正式化：

```text
配置域名
配置 HTTPS
配置 SMTP
配置权限
配置备份同步
配置恢复演练
配置 Runner
```

这套走下来，你就有一个真正能给初创公司用的自建 GitLab 服务器了。

# 结论

**可以用闲置电脑，但不建议把它当公司唯一正式代码服务器。**

更稳的方案是：

```text
公司正式代码资产：
优先 云服务器 / 公司机房小主机 / NAS + UPS
不要只靠 家里闲置电脑
```

原因很简单：公司代码是资产，最怕：

```text
硬盘坏了
机器断电
网络断了
系统崩了
备份没做
员工误删仓库
外网暴露被扫
```

GitLab 官方也强调自建 GitLab 要做灾备和定期备份，因为里面有仓库、数据库、用户、CI 产物、Issue、Wiki、附件等关键数据。([GitLab 文档][1])

# 我给你的初创公司推荐方案

## 方案 1：1～5 人，先活下来

推荐：

```text

```

优点：

```text
不用自己维护服务器
不用担心断电
不用管备份
不用管公网和 HTTPS
```

缺点：

```text
代码在第三方平台
部分功能/空间/CI 时间有限制
```

GitLab 当前 Free 方案是 0 美元，但官方定价页也显示 Free 侧重点偏个人项目和开源贡献，Premium 面向扩展中的组织，价格为每用户每月 29 美元且按年计费。([about.gitlab.com][2])

如果你们非常早期，**这其实最省心**。

---

## 方案 2：5～30 人，代码想自己掌控

推荐：

```text
自建 GitLab CE
+
云服务器
+

+
独立 GitLab Runner
```

配置建议：

# 闲置电脑能不能用？

可以，但要满足这些条件。

## 可以用的情况

```text
公司人数少
主要内网使用
机器能 24 小时开机
有 SSD
有 16GB 内存

有每日备份
坏了能接受半天到一天恢复
```

```text

机械硬盘
没有 UPS
没有备份
放在家里宽带下面
直接暴露公网
```

```text
闲置电脑可以当测试服务器、内网备份服务器、GitLab Runner
```

# 初创公司必须做的 8 件事

## 1. 禁止所有人直接推 main/master

设置：

```text
Settings
→ Repository
→ Protected branches
→ protect main/master
```

建议规则：

```text
main/master：只允许 Maintainer merge
普通开发：只能推 feature 分支
所有代码：必须 Merge Request
```

---

## 2. 分支规范

推荐：

```text
main            稳定正式分支
develop         开发主分支
feature/xxx     功能分支
bugfix/xxx      Bug 修复分支
release/v1.0.0  发布分支
hotfix/xxx      紧急修复分支
```

嵌入式项目很适合这样：

```bash
feature/imu-driver
feature/lvgl-ui
bugfix/uart-dma-idle
release/v1.2.0
hotfix/ota-crash
```

---

## 3. 提交信息规范

简单点先这样：

```text
feat: 新功能
fix: 修复 bug
docs: 文档
style: 格式调整
refactor: 重构
test: 测试
build: 构建系统
chore: 杂项
```

例子：

```bash
git commit -m "feat: add imu fifo read driver"
git commit -m "fix: resolve uart dma idle rx length error"
git commit -m "docs: add x2600 build guide"
```

---

## 4. 每天自动备份

至少每天一次：

```bash
sudo gitlab-backup create
```

备份不要只放本机，要同步到另一台机器：

```text
GitLab 本机
    ↓
公司 NAS
    ↓
云对象存储 / 移动硬盘
```

GitLab 备份包含数据库、账号、仓库、LFS、CI/CD 产物、Wiki、附件等很多内容。([GitLab 文档][7])

---

## 5. Runner 单独部署

不要这样：

```text
GitLab 主服务器 + 编译 Linux SDK + 编译 Kernel + 编译 Buildroot
```

这样 GitLab 容易卡死。

推荐：

```text
GitLab 主服务器：代码托管
Runner 机器 1：嵌入式 Linux 编译
Runner 机器 2：MCU 固件编译
Runner 机器 3：测试/打包
```

你的 X2600 SDK 这种大工程，最好 Runner 单独一台高性能机器。

---

## 6. 开启 HTTPS

公网访问必须 HTTPS。

域名类似：

```text
gitlab.your-company.com
```

不要让员工用：

```text
http://公网IP:8929
```

正式公司环境最好用：

```text
https://gitlab.your-company.com
```

---

## 7. 开启 2FA

管理员、技术负责人必须开双因素认证。

尤其是：

```text
root
Owner
Maintainer
```

这些账号权限太大。

---

## 8. 定期演练恢复

很多公司只备份，从不恢复测试。
这很危险。

你至少每个月做一次：

```text
新建一台测试服务器
从备份恢复 GitLab
确认项目、用户、仓库、Issue 都能看到
```

备份文件能恢复，才叫真正有备份。
