/**
 * @file main.c
 * 
 * @author wls
 * 
 * @brief CAN协议介绍：CAN(controller area network)
 *  
 *      CAN 通信时候需要通过CAN收发转换器芯片的，因为CAN电压是0-5V，而32单片机输出电压是3.3V
 *      所以要通过这个CAN收发芯片把这个电压进行个转化，而且CAN的线是双绞线形式连接的，遇到问题了 两根线都受影响，所以也就等同于不受影响    
 *  
 *      通信原理，二进制数据传输原理：与uart iic spi rs232不同，
 *   不是直接一根线单个IO输出高低电平表示数据0和1，
 *   而是差分信号传输的，就是输出靠两根线 输出的压差（电压差）值，来表示二进制数据0和1
 *   比如高速CAN规定，两线压差值为0V表示二进制数据1，当两线压差为2V时表示二进制数据0
 *      这个和USB协议传输原理也一样的，都是靠两线压差 表示和传输二进制数据0或1的
 *      这个两线压差CANH线的电压值-CANHL线的电压值
 *              
 *    一: 数据格式的介绍
 *    注意：CAN协议很奇葩，不想IIC协议中的有主机和从机，那么多的从机，
 *  每个从机都一个固定的IIC设备地址，这样IIC主机和从机通信的时候就方便多了，想和哪个IIC从机要通信直接输入地址找它就行了
 *  但是CAN总线协议中，can设备是没有设备地址的，只有个ID 不过这个ID的意思是设备的优先级的大小
 *  ID值越小 代表这个CAN设备的优先级越高，优先和CAN总线通信
 *       还有个很奇特的地方，这个CAN的ID 还分普通版 和加长版 专业点叫标准数据帧和拓展数据帧
 *      
 *      1.标准格式数据帧
 *    
    | start 1bit| 11bit ID | 1bit RTR:数据帧类型位 |6bit 控制码：数据长度控制位 | 0-8Byte 数据码 | 15bit CRC校验码 |1bit CRC界定符 | 2bit ACK码 | 7bit end|
start (1bit):
    CAN总线协议起始位，1bit，值为0
ID (11bit):
    长度11bit，虽然是ID但不是CAN的设备地址，而是CAN设备的优先级，值越小优先级越高

RTR位 (1bit)：
    1bit，用于区分类型是数据帧还是远程请求帧，数据帧此位为0，远程请求帧为1

控制码（6bit）：
    第0位:IDE位 为0则是标准数据帧格式 CAN ID有 11 bit
                为1则是拓展数据帧格式 CAN ID有 29 bit
    第1位: 空闲位，直接设置为0，啥用没有
    第2-5位：DLC位 数据长度代码，一共四位0000 这四位的十进制值表述数据的长度 单位是字节
                    假设这个DLC位的值 是 0101 十进制就是5 也就是后边数据长度为5Byte
数据码 (0-8Byte):
    长度为0-8Byte,具体多少，受前边儿 6bit控制码中的DLC位控制，DLC位的值为6则这个数据码长度就为6Byte 6*8bit

CRC界定符 (1bit): 
    长度1bit，用来界定CRC的边界 值为1
    
ACK码(2bit):
    长度2bit，第0位 CAN设备应答信号位 发送端为1 接收端为0表示应答，如果接收端是1那就是无应答
    第1位，ACK界定位是1，把后边数据隔开

end(7bit):
    长度为7bit的结束位，规定全为1
 *      
 * 
 *      2.拓展格式数据帧
 *    
    | start 1bit| 29bit ID | 1bit RTR:数据帧类型位 |6bit 控制码：数据长度控制位 | 0-8Byte 数据码 | 15bit CRC校验码 |1bit CRC界定符 | 2bit ACK码 | 7bit end|
start (1bit):
    CAN总线协议起始位，1bit，值为0
ID (29bit):

RTR位 (1bit)：
    1bit，用于区分类型是数据帧还是远程请求帧，数据帧此位为0，远程请求帧为1

控制码（6bit）：
    第0位:IDE位 为0则是标准数据帧格式 CAN ID有 11 bit
                为1则是拓展数据帧格式 CAN ID有 29 bit
    第1位: 空闲位，直接设置为0，啥用没有
    第2-5位：DLC位 数据长度代码，一共四位0000 这四位的十进制值表述数据的长度 单位是字节
                    假设这个DLC位的值 是 0101 十进制就是5 也就是后边数据长度为5Byte
数据码 (0-8Byte):
    长度为0-8Byte,具体多少，受前边儿 6bit控制码中的DLC位控制，DLC位的值为6则这个数据码长度就为6Byte 6*8bit

CRC界定符 (1bit): 
    长度1bit，用来界定CRC的边界 值为1
    
ACK码(2bit):
    长度2bit，第0位 CAN设备应答信号位 发送端为1 接收端为0表示应答，如果接收端是1那就是无应答
    第1位，ACK界定位是1，把后边数据隔开

end(7bit):
    长度为7bit的结束位，规定全为1

• SOF（Start of Frame）：帧起始，表示后面一段波形为传输的数据位
• ID（Identify）：标识符，区分功能，同时决定优先级
• RTR（Remote Transmission Request ）：远程请求位，区分数据帧和遥控帧
• IDE（Identifier Extension）：扩展标志位，区分标准格式和扩展格式
• SRR（Substitute Remote Request）：替代RTR，协议升级时留下的无意义位
• r0/r1（Reserve）：保留位，为后续协议升级留下空间
• DLC（Data Length Code）：数据长度，指示数据段有几个字节
• Data：数据段的1~8个字节有效数据
• CRC（Cyclic Redundancy Check）：循环冗余校验，校验数据是否正确
• ACK（Acknowledgement）：应答位，判断数据有没有被接收方接收
• CRC/ACK界定符：为应答位前后发送方和接收方释放总线留下时间
• EOF（End of Frame ）：帧结束，表示数据位已经传输完毕
