大体结论：**多数九号/小米这类平衡车、独轮车、电动滑板车/电动二轮车，用的是“轮毂无刷电机”，很多是直接驱动，不走外部减速齿轮组。**

## 1. 小米/九号两轮平衡车：一般是轮毂无刷直驱

比如 Ninebot S / mini 这类两轮自平衡车，左右两个轮子各一个电机，官方维修/FAQ里也直接叫 **wheel hub motor，轮毂电机**。Ninebot S Pro 参数也写了双电机、总额定功率 800W、最大扭矩 70Nm。([小米澳大利亚][1])

结构大概是：

```text
电池
  ↓
电机驱动板/FOC控制器
  ↓
三相无刷轮毂电机 × 2
  ↓
左右轮胎直接转动
```

一般不是这样：

```text
电机 → 减速齿轮箱 → 车轮
```

因为平衡车要求：

* 正反转频繁；
* 扭矩响应快；
* 不能有明显齿轮间隙；
* 要能电刹/回充；
* 左右轮独立控制姿态。

所以**直接轮毂电机更合适**。

---

## 2. 独轮平衡车：基本也是大直径轮毂无刷直驱

独轮车更典型，轮子本身就是一个大号外转子无刷电机：

```text
定子：固定在车架中间
转子：外圈和轮毂/轮胎一起转
```

也就是说：

```text
电机外壳 ≈ 轮毂
轮毂 ≈ 车轮
```

独轮车几乎不适合用普通减速齿轮，因为它需要：

* 零速大扭矩；
* 高频正反向微调；
* 很平滑的力矩输出；
* 电机制动；
* 没有齿隙，否则人会感觉车“晃”“虚”“不跟脚”。

电动独轮车拆解资料也能看到它们核心就是大轮毂电机，而不是传统“电机 + 齿轮箱”结构。([Electric Unicycle Forum (euc community)][2])

---

## 3. 九号/电动二轮车：多数是后轮轮毂电机，有些明确是直驱

如果你说的是九号电动自行车、电摩、电动踏板车这类，常见方案是：

```text
电池
  ↓
FOC 控制器
  ↓
后轮轮毂无刷电机
  ↓
后轮直接转
```

九号 E100 的资料里就写了 **high-power direct drive hub motor**，也就是高功率直驱轮毂电机。([Segway][3])

这类车不用链条、不用皮带、不用外部齿轮箱的好处是：

* 结构简单；
* 噪音低；
* 维护少；
* 防水密封好做；
* 电刹/能量回收方便；
* 控制器直接控制轮子扭矩。

不过要注意：**电动二轮车行业里也有例外**。有些电助力自行车、小功率车会用**带行星齿轮减速的轮毂电机**，优点是低速扭矩大、体积小；缺点是有齿轮磨损、噪音、单向离合、反拖/回充受限制等问题。

---

## 4. 为什么不用减速齿轮组？

对平衡车/独轮车来说，减速齿轮最大的问题不是能不能用，而是**体验和控制不适合**。

### 减速齿轮的问题

```text
电机轴 → 齿轮减速 → 轮子
```

会带来：

* 齿轮间隙；
* 响应延迟；
* 机械噪音；
* 磨损；
* 润滑问题；
* 正反转冲击；
* 电刹/回充设计更麻烦。

而平衡车控制是这样的：

```text
IMU检测车身倾角
  ↓
控制器计算需要多少扭矩
  ↓
FOC立刻调节电机电流
  ↓
轮子立刻前后微调
```

这里最怕“中间有虚位”。如果齿轮有间隙，人站上去会感觉车身抖、晃、反应慢。

---

## 5. 那轮毂电机为啥能不减速还扭矩大？

因为它通常是**外转子大直径无刷电机**。

普通小电机：

```text
半径小 → 力臂短 → 扭矩小 → 需要减速箱
```

轮毂电机：

```text
半径大 → 力臂长 → 天生扭矩大
```

扭矩可以粗略理解为：

```text
扭矩 = 力 × 半径
```

轮毂电机半径大，所以即使转速不高，也能直接输出比较大的轮端扭矩。

## 6. 三类车对比

| 类型         | 常见电机方案      | 是否常用减速齿轮 | 原因               |
| ---------- | ----------- | -------: | ---------------- |
| 小米/九号两轮平衡车 | 左右双轮毂无刷电机   |     通常不用 | 需要快速正反转、低齿隙、好控制  |
| 独轮平衡车      | 大直径轮毂无刷电机   |     基本不用 | 平衡控制要求极高，齿轮间隙不合适 |
| 九号电动滑板车    | 前/后轮轮毂电机    |     多数不用 | 结构简单、静音、免维护      |
| 九号电动二轮车/电摩 | 后轮轮毂电机，很多直驱 |     多数不用 | 大扭矩直驱，维护少        |
| 部分电助力自行车   | 齿轮轮毂电机/中置电机 |     有些会用 | 追求小体积、低速助力、爬坡    |

## 1. 扭矩不是只能靠齿轮放大

齿轮减速的作用是：

```text
高速小扭矩电机 → 减速齿轮 → 低速大扭矩输出
```

但轮毂电机走的是另一条路：

```text
低速大直径外转子电机 → 直接输出低速大扭矩
```

也就是说，它不是先高速转再减速，而是电机本身就设计成低速大扭矩。

---

## 2. 轮毂电机为什么扭矩大？

核心原因是：**半径大，力臂长。**

扭矩公式是：

```text
扭矩 = 力 × 半径
```

同样的电磁力，如果作用半径更大，扭矩就更大。

小电机可能这样：

```text
电磁力作用半径：2 cm
```

轮毂电机可能这样：

```text
电磁力作用半径：8 cm、10 cm、甚至更大
```

半径变成 4～5 倍，同样电磁力下，扭矩也能变成 4～5 倍。

---

## 3. 外转子无刷电机天生适合大扭矩

普通内转子电机大概是这样：

```text
外壳固定
中间转子旋转
半径小
转速高
扭矩小
```

轮毂电机一般是外转子：

```text
中间定子固定
外圈磁钢/轮毂旋转
半径大
转速低
扭矩大
```

简化结构：

```text
        轮胎
  ┌────────────────┐
  │  外转子/磁钢    │  ← 跟轮子一起转
  │ ┌────────────┐ │
  │ │ 定子线圈    │ │  ← 固定在车架轴上
  │ └────────────┘ │
  └────────────────┘
```

所以轮毂电机不是“小电机硬撑”，而是**整个轮子就是一个大电机**。

## 4. 举个直观例子：载人需要多少轮端扭矩？

假设一个人加车一共：

```text
总质量 = 100 kg
```

重力大约：

```text
100 kg × 9.8 ≈ 980 N
```

平地匀速走，其实不需要克服全部重力，只需要克服滚动阻力、空气阻力、加速阻力。

真正吃扭矩的是：

```text
起步
爬坡
急加速
平衡修正
过坎
```

比如轮子半径 0.15 m，电机输出 40 N·m 扭矩，那么轮胎接地点能提供的推力大概是：

```text
推力 = 扭矩 ÷ 轮半径
     = 40 ÷ 0.15
     ≈ 267 N
```

267N 的推力已经不小了。

如果左右两个轮子一起：

```text
总推力 ≈ 267 × 2 = 534 N
```

这对平地起步、加速、平衡人是够用的。

## 5. 平衡车为什么感觉力气很大？

因为平衡车不是一直让电机满功率跑，而是**瞬间输出大电流，产生瞬时大扭矩**。

流程是：

```text
人往前倾
  ↓
IMU检测到角度变化
  ↓
控制器判断要往前加速
  ↓
FOC增加q轴电流
  ↓
电机立刻输出更大扭矩
  ↓
轮子往前追人
```

在电机里，扭矩和电流近似成正比：

```text
扭矩 ≈ 扭矩常数 × 电流
```

所以只要电池和控制器能短时间给出大电流，电机就能短时间输出很大扭矩。

## 6. 为什么不会因为没有减速箱就“没劲”？

因为轮毂电机牺牲的是**高转速能力**，换来的是**低速大扭矩**。

普通高速电机：

```text
转速高
扭矩小
需要减速箱
```

轮毂直驱电机：

```text
转速低
扭矩大
不需要减速箱
```

比如平衡车、独轮车、电动车，轮子转速其实不高。

假设轮径 10 英寸，周长大约 0.8 m。

如果车速 20 km/h：

```text
20 km/h = 5.56 m/s
轮子转速 = 5.56 ÷ 0.8 ≈ 6.95 圈/s
          ≈ 417 rpm
```

也就是说，车跑到 20 km/h，轮子也就几百转每分钟。
这种场景正适合**低速大扭矩轮毂电机**。

## 7. 关键不只是电机，还有控制器和电池

能不能载人，不只看电机，还看这一整套：

```text
电池放电能力
  ↓
MOS管/驱动器电流能力
  ↓
FOC算法
  ↓
电机绕组设计
  ↓
散热能力
  ↓
轮胎抓地力
```

平衡车/独轮车起步、爬坡时，经常是几十安培甚至上百安培的相电流。
电流越大，磁场越强，输出扭矩越大。

但是限制也很明显：

```text
电流太大 → MOS发热
电机铜损发热
磁钢退磁风险
电池压降
轮胎打滑
```

所以量产车都会限制峰值电流、温度、最大坡度和最大载重。

## 8. 和“有齿轮减速”的方案对比

| 方案         | 优点                     | 缺点                    |
| ---------- | ---------------------- | --------------------- |
| 直驱轮毂电机     | 安静、结构简单、响应快、无齿隙、适合电刹回充 | 电机体积重，低速大扭矩需要大电流      |
| 齿轮减速电机     | 小电机也能放大扭矩，低速爬坡强        | 有噪音、磨损、齿隙、维护问题，正反转体验差 |
| 中置电机+链条/皮带 | 可利用变速/减速，效率区间好         | 结构复杂，维护多，不适合平衡车快速正反控制 |

对平衡车来说，**无齿隙、响应快**非常重要，所以宁愿用大轮毂电机，也不太愿意用减速齿轮组。

## 6. 为什么汽车不像平衡车那样轮毂直驱？

汽车需要高速行驶，轮子转速并不高，但电机为了功率密度和效率，通常设计成高速电机。

比如车轮直径约 0.7 m，周长约 2.2 m。
车速 120 km/h 时：

```text
120 km/h = 33.3 m/s

车轮转速 ≈ 33.3 ÷ 2.2 × 60
        ≈ 900 rpm
```

但电机最高转速可能是：

```text
15000 rpm
18000 rpm
21000 rpm
22000 rpm
甚至更高
```

所以需要一个固定减速比，比如：

```text
电机 9000 rpm
减速比 9:1
车轮 ≈ 1000 rpm
```

同时扭矩被放大：

```text
电机扭矩 400 N·m
减速比 9:1
理论轮端扭矩 ≈ 3600 N·m
```

实际还要扣掉齿轮效率损耗，但轮端扭矩依然会被明显放大。

## 7. 电动车的“单速”是什么意思？

很多人听到电动车“单速”，会误以为没有齿轮。其实不是。

**单速 = 只有一个固定齿比。**

它不像燃油车：

```text
1挡、2挡、3挡、4挡、5挡、6挡……
```

而是：

```text
永远一个固定减速比
```

# 1. ROS 到底是干啥的？

ROS 全称 Robot Operating System，但它**不是传统意义上的操作系统**，不像 Linux、Windows、FreeRTOS 那样直接管理硬件。

它更像这样：

```text
Linux
  ↓
ROS / ROS2
  ↓
导航、建图、定位、视觉、机械臂控制、传感器驱动
  ↓
你的机器人业务逻辑
```

ROS 主要解决机器人软件里这些问题：

```text
不同模块之间怎么通信？
传感器数据怎么发布？
控制算法怎么订阅数据？
怎么记录数据？
怎么可视化调试？
怎么复用别人写好的导航/SLAM/机械臂代码？
```

---

# 2. 用 ROS 的典型架构

比如一个移动机器人：

```text
激光雷达节点
    ↓ 发布 /scan

IMU 节点
    ↓ 发布 /imu

轮速里程计节点
    ↓ 发布 /odom

SLAM 节点
    ↓ 订阅 /scan /imu /odom
    ↓ 发布 /map

导航节点
    ↓ 订阅 /map /odom /scan
    ↓ 发布 /cmd_vel

底盘控制节点
    ↓ 订阅 /cmd_vel
    ↓ 转成左右轮速度

MCU 电机控制板
    ↓ 执行 PWM / FOC / PID
```

ROS 里面每个功能通常叫一个 **Node，节点**。
节点之间通过 **Topic，话题** 通信。

比如：

```text
/camera/image_raw     摄像头图像
/scan                 激光雷达数据
/imu                  IMU数据
/odom                 里程计
/cmd_vel              速度控制命令
/map                  地图
/tf                   坐标变换关系
```

你可以把 ROS 理解成机器人软件里的“消息总线 + 工具生态”。

# 3. ROS 的优点

## 优点一：模块化，非常适合复杂机器人

不用 ROS 的时候，你可能会写成这样：

```text
main.c / main.cpp
  ├── 读取雷达
  ├── 读取IMU
  ├── 读取相机
  ├── 跑定位算法
  ├── 跑建图算法
  ├── 跑路径规划
  ├── 控制电机
  └── 打印调试
```

最后所有东西耦合在一起，越来越乱。

用 ROS 后可以拆成：

```text
lidar_node
imu_node
camera_node
slam_node
navigation_node
motor_bridge_node
```

每个节点只干一件事，维护起来舒服很多。

---

## 优点二：现成算法和驱动多

ROS 生态里有大量现成东西：

```text
激光雷达驱动
深度相机驱动
IMU驱动
机械臂控制
SLAM建图
AMCL定位
Nav2导航
MoveIt机械臂规划
RViz可视化
Gazebo/Ignition仿真
rosbag数据录制
```

比如你做小车导航，不用 ROS 可能要自己写：

```text
雷达驱动
地图格式
定位算法
路径规划
避障算法
坐标变换
可视化工具
日志录制工具
```

用 ROS 可以直接复用很多成熟模块。

---

## 优点三：调试工具非常强

ROS 很大的价值不是“运行”，而是“调试”。

比如你可以用：

```text
rviz       看地图、雷达点云、机器人位置、路径
rqt_graph  看节点连接关系
rosbag     录制传感器数据，离线回放
tf工具     查看坐标系是否正确
```

这对机器人开发非常有用。

举个例子，你的机器人跑歪了，不用 ROS 只能疯狂打印日志：

```text
printf("imu = xxx")
printf("odom = xxx")
printf("speed = xxx")
```

用 ROS 可以直接可视化：

```text
雷达是不是反了？
IMU方向对不对？
odom坐标跳不跳？
map和base_link关系对不对？
cmd_vel有没有发出来？
```

---

## 优点四：适合多人协作

比如团队里：

```text
A 写底盘驱动
B 写SLAM
C 写导航
D 写视觉识别
E 写上位机
```

大家约定好 Topic、Service、Action 接口，就可以并行开发。

例如：

```text
底盘节点只需要订阅 /cmd_vel
导航节点只需要发布 /cmd_vel
```

中间不用互相知道对方代码细节。

---

## 优点五：ROS2 更适合产品化一点

ROS1 更多是研究/开发生态。
ROS2 相比 ROS1 改进了很多：

```text
支持 DDS 通信
支持多机通信
实时性更好一些
安全性更好一些
支持生命周期节点
支持 QoS
更适合嵌入式 Linux 和产品化
```

但注意：**ROS2 也不是万能实时系统**，底层电机控制还是不能完全依赖它。

# 4. ROS 的缺点

## 缺点一：学习成本高

ROS 不是一个小库，而是一套体系。

你需要理解：

```text
Node
Topic
Service
Action
Message
Launch
Package
Workspace
tf坐标树
参数系统
rosbag
rviz
colcon/catkin
```

对嵌入式新手来说，一开始会觉得很绕。

---

## 缺点二：资源占用高

ROS 通常跑在 Linux 上，比如：

```text
Ubuntu + ROS2
```

不适合直接跑在普通 MCU 上。

比如这些芯片一般不直接跑完整 ROS：

```text
STM32
GD32
普通 ESP32
nRF52
普通 Cortex-M MCU
```

它们更适合干：

```text
电机PWM
FOC
编码器采样
IMU读取
PID控制
安全保护
CAN/UART通信
```

而 ROS 跑在上位机：

```text
RK3568
RK3588
Jetson
树莓派
x86工控机
高通/瑞芯微平台
```

---

## 缺点三：实时性不是最强

机器人底层控制经常要求很稳定的周期：

```text
电流环：10kHz ~ 40kHz
速度环：1kHz
姿态环：200Hz ~ 1kHz
底盘控制：50Hz ~ 200Hz
```

ROS/Linux 层不适合直接做高频强实时控制。

正确结构通常是：

```text
ROS/Linux 上位机：
  负责导航、建图、视觉、任务逻辑

MCU/实时控制器：
  负责电机FOC、PID、传感器采样、安全保护
```

不要这样：

```text
ROS节点直接输出PWM控制电机
```

更推荐这样：

```text
ROS发布 /cmd_vel
  ↓
串口/CAN/以太网
  ↓
MCU接收速度目标
  ↓
MCU本地跑PID/FOC
```

---

## 缺点四：工程复杂度会上升

如果只是一个简单小车：

```text
按键控制前进后退
超声波避障
蓝牙遥控
两路电机PWM
```

你上 ROS 反而变复杂：

```text
Ubuntu环境
ROS安装
包依赖
节点通信
launch文件
消息定义
调试工具
```

小项目可能变成“大炮打蚊子”。

---

## 缺点五：产品化需要谨慎

ROS 很适合研发和原型验证，但量产产品要考虑：

```text
启动速度
稳定性
系统裁剪
依赖包版本
异常恢复
安全机制
升级维护
实时控制
内存占用
开源协议
```

很多公司会：

```text
研发阶段用 ROS 快速验证
  ↓
产品阶段保留部分 ROS2
或者把核心算法移植到自研框架
```

现在新项目建议优先 ROS2。

| 项目    | ROS1       | ROS2           |
| ----- | ---------- | -------------- |

| 通信    | ROS Master | DDS，无中心化       |
| 实时性   | 较弱         | 比 ROS1 好       |

# 12. 一句话总结

**做机器人不必须用 ROS。**

如果你做的是：

```text
电机控制、平衡车、简单机器人、MCU底盘
```

不用 ROS 更简单、更实时。

如果你做的是：

```text
SLAM、自主导航、机械臂、视觉、多传感器融合
```

ROS/ROS2 很有价值。

最实用的方案是：

```text
MCU/RTOS：负责实时控制
Linux/ROS2：负责感知、导航、规划、上层逻辑
```

也就是：

```text
底层不用 ROS 控电机
上层可以用 ROS 做智能
```

-------
---------
------
可以，这个方案非常合理，而且是现在机器人常见架构：

```text
MCU：负责平衡、电机、IMU、编码器、安全保护
SoC：负责相机、Wi-Fi传图、音频识别、语音交互、避障、上层决策
```

你这个项目不要把“平衡控制”放到 Linux SoC 上做。**平衡环、电机闭环、刹车保护必须放 MCU**，SoC 只发“目标速度/目标转向/模式命令”。

### SoC 选择

#### 低成本版：RK3568

RK3568 是四核 Cortex-A55，常见板子支持 Linux、MIPI CSI、USB、以太网、显示、硬件编解码等；官方/资料中也能看到它有 4K 解码、1080p 编码、8MP ISP、Mali-G52 GPU 等多媒体能力。([Rock Chips][1])

适合：

```text
基础图传
普通摄像头采集
简单避障
轻量语音识别
简单目标检测
遥控车/平衡车原型
```

缺点是：AI算力一般，跑复杂视觉识别、深度学习模型会吃力。

---

#### 性能版：RK3588

如果你要做：

```text
双目/深度相机
本地AI识别
目标检测
语音识别
多路视频
更复杂避障
```

那更推荐 RK3588。它的 CPU、GPU、NPU、视频编解码能力都比 RK3568 强很多。很多 RK3588 方案主打 6TOPS NPU、8K 视频编解码、多路 MIPI/USB 摄像头能力；这类能力更适合机器人上位机。

我个人建议：**预算允许直接 RK3588，不要 RK3568。**

---

#### AI 强版：Jetson Orin Nano

如果你重点是 AI 视觉、深度学习、目标检测、语音大模型边缘推理，Jetson Orin Nano 更舒服。NVIDIA 官方 Jetson Orin Nano Super 开发套件标称 67 INT8 TOPS，8GB LPDDR5，102GB/s 内存带宽，功耗 7W–25W。([nvidia.com][2])

适合：

```text
YOLO目标检测
深度相机
人体/车辆/障碍物识别
视觉导航
机器人AI实验
```

缺点：

```text
贵一些
功耗高一些
生态偏NVIDIA
做产品成本压力大
```

# 3. 我不建议你用 ESP32-P4 当主 SoC

ESP32-P4 很适合做 HMI、图像采集、LCD、轻量视觉处理，但它不是 Linux SoC，也没有内置 Wi-Fi/蓝牙，需要外接无线芯片。乐鑫官方 ESP32 系列中，传统 ESP32 是集成 Wi-Fi 和蓝牙的 SoC；而 ESP32-P4 的定位更偏高性能 MCU/多媒体 MCU，不适合承担你说的完整“相机 + Wi-Fi图传 + 音频识别分析 + 避障规划”上位机任务。([Espressif Systems][3])

ESP32-P4 可以做：

```text
相机采集
LCD显示
简单图像处理
辅助控制
边缘小模块
```

但不太适合做：

```text
完整机器人主控
复杂音频识别
深度相机避障
多任务Linux应用
ROS2导航
复杂AI推理
```

所以你的主控 SoC，我更建议：

```text
RK3588 > Jetson Orin Nano > RK3568 > ESP32-P4
```

如果追求学习和成本：

```text
RK3568 / RK3588 更适合你
```

如果追求 AI 视觉效果：

```text
Jetson Orin Nano 更适合
```

# 4. MCU 推荐

你的 MCU 板要做的是“保命层”。
只要 SoC 卡死、Linux 死机、Wi-Fi 断开，MCU 也要能让车安全停下来。

## 推荐 MCU

### 方案 1：STM32G4

适合做电机控制，带高性能 ADC、定时器、运放/比较器资源，适合 FOC。

```text
优点：
- 很适合电机控制
- FOC资料多
- ADC/定时器强
- 成本适中
```

### 方案 2：STM32H7

适合你想把控制、传感器融合、通信都做得比较复杂。

```text
优点：
- 性能强
- RAM大
- 外设多
- 可以跑复杂控制算法
```

### 方案 3：GD32F4 / GD32H7

你熟 GD32，也可以用 GD32F4 先做。
但是如果要做高性能 FOC，STM32G4 / H7 的生态会更舒服。

### 方案 4：TI C2000

如果你非常认真做电机驱动，C2000 是专业电机控制方向。
但学习成本比 STM32/GD32 高。

# 5. 通信方式推荐

SoC 和 MCU 之间，建议优先级：

```text
CAN > UART > RS485 > Ethernet
```

## 最推荐：CAN

平衡车/机器人底盘，我建议用 CAN。

原因：

```text
抗干扰强
适合电机控制
多节点方便
实时性比普通TCP更可控
线束简单
工业/车载常用
```

结构：

```text
SoC
  ↓ USB-CAN / SPI-CAN / 原生CAN
MCU
  ↓
电机驱动板
```

命令帧可以这样设计：

```c
typedef struct {
    int16_t target_speed_mm_s;   // 前进/后退速度，单位 mm/s
    int16_t target_yaw_rate_dps; // 转向角速度，单位 deg/s
    uint8_t mode;                // 模式：遥控/语音/避障/急停
    uint8_t enable;              // 使能
    uint16_t crc;                // 校验
} chassis_cmd_t;
```

MCU 上传状态：

```c
typedef struct {
    int16_t pitch_deg_x100;      // 俯仰角
    int16_t speed_mm_s;          // 当前速度
    int16_t battery_mv;          // 电池电压
    int16_t motor_current_ma;    // 电机电流
    uint8_t fault_code;          // 故障码
    uint8_t state;               // 平衡/倒地/刹车/待机
} chassis_state_t;
```

---

## UART 也可以，但要做好协议

如果你一开始开发，UART 最快：

```text
SoC UART ↔ MCU UART
```

但要注意：

```text
必须有帧头
必须有长度
必须有命令字
必须有CRC
必须有超时保护
不能用纯字符串乱发
```

比如：

```text
帧头    长度   命令   数据       CRC
AA 55   08     01    xx xx xx    xx xx
```

MCU 必须做 watchdog：

```text
超过 200ms 没收到 SoC 控制帧 → 自动减速/刹车
超过 500ms 没收到 → 进入安全停车
```

# 6. 平衡车底层控制建议

你的平衡车 MCU 控制不能只接收：

```text
前进
后退
左转
右转
```

更好的方式是 SoC 发：

```text
目标线速度 v
目标角速度 w
```

也就是类似机器人常用的 `/cmd_vel` 思路：

```text
v > 0：前进
v < 0：后退
w > 0：左转
w < 0：右转
```

比如：

```text
v = 0.5 m/s, w = 0       前进
v = 0,     w = 30°/s     原地左转
v = 0.3,   w = -20°/s    边前进边右转
```

MCU 内部再变成左右轮速度：

```text
left_speed  = v - w * wheel_base / 2
right_speed = v + w * wheel_base / 2
```

然后再叠加平衡控制。

平衡车 MCU 内部控制大概是：

```text
IMU姿态角
  ↓
平衡环：让车身保持直立
  ↓
速度环：控制前进/后退速度
  ↓
转向环：控制左右轮差速
  ↓
电流环/FOC/PWM
  ↓
电机
```

# 14. 最关键的安全设计

平衡车载人/载物，安全非常重要。MCU 必须有这些保护：

```text
SoC通信超时 → 自动停车
倾角过大 → 断开动力/刹车
电池欠压 → 限速/停车
电机过流 → 限流
MOS过温 → 降功率
IMU异常 → 停车
编码器异常 → 停车
遥控丢失 → 停车
急停按钮 → 最高优先级
```

而且 SoC 发来的命令不能直接相信，MCU 要限幅：

```text
最大速度限制
最大加速度限制
最大转向角速度限制
最大倾角限制
最大电流限制
```

也就是说：

```text
SoC 可以说“快跑”
MCU 必须判断“现在能不能快跑”
```

# 1. 全志 T153 大概是什么定位？

从目前公开资料看，T153 属于偏工业/机器人/网关类的低功耗嵌入式处理器。资料里常见配置是：

```text
CPU：四核 Arm Cortex-A7，最高约 1.6GHz
协处理器：单核 RISC-V / 玄铁 E907，约 600MHz
内存：支持 DDR3 / DDR3L / DDR4
接口：多路以太网、CAN-FD、PWM、I2C/TWI、GPADC、LocalBus 等
应用：PLC、HMI、机器人、工业网关
```

一些开发板/核心板资料提到 T153 有四核 Cortex-A7、RISC-V E907 协处理器，并支持多个千兆以太网、CAN-FD、LocalBus 等接口，定位也明确偏工业自动化、机器人、网关。([cnblogs.com][1])

所以它的优势不是“AI算力很强”，而是：

```text
接口丰富
功耗低
工业控制友好
以太网/CAN资源好
适合做网关、控制主机、轻量机器人主控
```

# 2. T153 能不能跑 ROS？

**能跑，但建议跑轻量 ROS2，不要指望它像 RK3588 / Jetson 那样跑重型机器人算法。**

T153 是 Cortex-A7，属于 ARMv7 32 位平台。ROS/ROS2 在这种平台上不是完全不行，但会遇到几个问题：

```text
CPU性能有限
内存带宽有限
很多 ROS2 包更偏向 64 位 ARM / x86 环境
编译时间长
复杂依赖容易折腾
视觉/AI类包压力大
```

# 6. PoE 模块是干啥的？

PoE 全称是：

```text
Power over Ethernet
```

中文叫：

```text
以太网供电
```

意思是：**一根网线同时传数据和供电。**

普通网口：

```text
网线只传数据
电源线单独供电
```

PoE：

```text
一根网线 = 网络数据 + 电源
```

---

# 7. PoE 在机器人上有什么用？

比如你的机器人上有：

```text
网络摄像头
激光雷达
深度相机
边缘计算模块
远程网关
工业相机
```

如果这些设备支持 PoE，那么只需要一根网线：

```text
PoE交换机 / PoE供电模块
        ↓ 一根网线
摄像头 / 雷达 / 模块
```

不用再单独拉：

```text
电源线 + 网线
```

所以 PoE 的好处是：

```text
布线简单
接口可靠
远距离传输方便
工业设备常用
一根线同时供电和通信
```

---

# 8. PoE 模块在你的车上可能有两种角色

## 角色一：PoE 受电模块，PD

PD 是 Powered Device，受电设备。

比如：

```text
PoE网线进来
  ↓
PoE PD模块
  ↓
输出 12V / 5V
  ↓
给 T153 板子、摄像头、雷达供电
```

这种是“从网线取电”。

---

## 角色二：PoE 供电模块，PSE

PSE 是 Power Sourcing Equipment，供电设备。

比如你的机器人电池是 24V，然后你想给一个 PoE 摄像头供电：

```text
机器人电池 24V
  ↓
PoE PSE模块
  ↓
网线
  ↓
PoE摄像头
```

这种是“通过网线给外设供电”。

---

# 9. PoE 常见电压关系

标准 PoE 在线缆上通常是较高电压，比如 48V 左右，然后设备端再降压。

大概链路是：

```text
电池/适配器
  ↓
PoE供电模块
  ↓
网线中传输约 48V
  ↓
PoE受电模块
  ↓
降压成 12V / 5V / 3.3V
```

所以 PoE 模块不是普通 DC-DC，它还涉及：

```text
供电检测
握手识别
限流保护
隔离/非隔离电源
以太网磁性器件
数据和电源耦合/分离
```

```text id="frds6u"
网线 = 网络数据

```


优点：

```text id="mgds1a"
少一根电源线
布线简单
网络稳定
供电距离远
适合摄像头、雷达、工业设备
```
