# FOC、Clarke/Park 变换与电角度理解笔记

## 1. FOC 的本质

FOC，全称 Field Oriented Control，中文常叫：

> 磁场定向控制 / 矢量控制

FOC 的核心不是简单控制三相电流 `Ia / Ib / Ic`，而是控制：

> 定子电流产生的磁场方向，让它以合适的角度拉着转子永磁体旋转。

对于 PMSM / BLDC 电机来说，真正产生转矩的不是某一相电流本身，而是：

> 三相电流合成出来的定子旋转磁场。

FOC 的目标是把复杂的三相交流电机控制，转换成类似直流电机一样的控制方式：

```c
Id = 控制磁链 / 励磁
Iq = 控制转矩
````

对于常见表贴式 PMSM，通常希望：

```c
Id_ref = 0;
Iq_ref = 需要的转矩电流;
```

也就是说：

> FOC 的核心目标是精准控制 Iq，让电机精准输出力矩。

---

## 2. 为什么不能直接控制三相电流？

三相电流一般是正弦变化的：

```text
Ia = 正弦波
Ib = 相差 -120°
Ic = 相差 +120°
```

如果直接控制 `Ia / Ib / Ic`，目标电流本身一直在变化。

比如：

```text
这一瞬间 Ia_ref = 3A
下一瞬间 Ia_ref = 2.5A
再下一瞬间 Ia_ref = 1A
再下一瞬间 Ia_ref = -1A
```

PI 控制器最擅长控制的是稳定的直流量，例如：

```text
目标 = 3A
实际 = 2.8A
误差 = 0.2A
```

但是三相电流是交流量，目标一直变化，PI 控制器很难直接控制。

所以 FOC 要做一件事：

> 把旋转变化的交流量，转换到跟着转子一起旋转的坐标系里，使它变成近似直流量。

这就是 Clarke 变换和 Park 变换存在的根本原因。

---

## 3. Clarke 变换：三相 abc → 二维 αβ

三相电机中，通常满足：

```text
Ia + Ib + Ic = 0
```

因此只要知道两相电流，第三相就能算出来：

```text
Ic = -Ia - Ib
```

所以三相电流虽然有三个变量，但本质上只有两个自由度。

Clarke 变换的作用是：

> 把三相 abc 坐标系，转换成二维静止 αβ 坐标系。

可以理解为：

```text
Ia / Ib / Ic
    ↓ Clarke
Iα / Iβ
```

也就是：

> 把三相绕组产生的磁场，合成为一个二维平面上的电流矢量。

### 直观理解

三相绕组在空间上相差 120°：

```text
A 相：0°
B 相：-120°
C 相：+120°
```

每一相通电都会产生一个方向固定、大小变化的磁场。

三个磁场叠加后，可以得到一个总磁场，这个总磁场可以用一个二维箭头表示：

```text
Iα：电流矢量在 α 轴上的分量
Iβ：电流矢量在 β 轴上的分量
```

所以 Clarke 变换不是魔法，它只是：

> 把三相线圈产生的合成磁场，用二维坐标表示出来。

---

## 4. Park 变换：静止 αβ → 旋转 dq

Clarke 变换后得到的是：

```text
Iα
Iβ
```

但是 αβ 坐标系是固定在定子上的，也就是：

```text
α 轴固定不动
β 轴固定不动
```

而转子在旋转，所以从 αβ 坐标系看，电流矢量仍然是旋转变化的。

这时还需要 Park 变换。

Park 变换的作用是：

> 把静止的 αβ 坐标系，旋转到跟着转子一起转的 dq 坐标系。

可以理解为：

```text
αβ：站在电机外壳上看磁场
dq：站在转子磁铁上看磁场
```

如果你站在电机外壳上看，磁场一直在转。

如果你站在转子上一起转，磁场相对你就接近静止。

所以 Park 变换的核心作用是：

> 把旋转变化的交流量，变成 dq 坐标系下近似不变的直流量。

---

## 5. dq 坐标系的意义

dq 坐标系有两个轴：

```text
d 轴：direct axis，直轴，和转子磁链方向对齐
q 轴：quadrature axis，交轴，和转子磁链垂直
```

可以这样理解：

```text
              q轴
              ↑
              |
              |
转子磁链方向 → +----------→ d轴
```

### Id 的作用

`Id` 是沿着转子磁场方向的电流分量。

它主要影响磁链，也可以理解为励磁电流。

对于表贴式 PMSM，一般希望：

```c
Id_ref = 0;
```

因为永磁体已经提供磁场，额外增加 Id 意义不大，反而可能增加铜耗。

### Iq 的作用

`Iq` 是垂直于转子磁场方向的电流分量。

它主要产生转矩。

```text
Iq 越大，电机输出力矩越大
Iq 改变正负，电机力矩方向改变
```

所以：

```text
Id：控制磁链
Iq：控制转矩
```

FOC 就是把交流电机控制成类似直流电机的感觉。

---

## 6. Clarke 和 Park 一句话理解

### Clarke 变换

```text
三相电流 → 一个二维磁场箭头
```

也就是：

```text
abc → αβ
```

### Park 变换

```text
静止坐标系 → 转子坐标系
```

也就是：

```text
αβ → dq
```

更通俗地说：

```text
Clarke：把三相线圈产生的磁场合成一个箭头
Park：站到转子身上，看这个箭头相对转子是往哪拉
```

---

## 7. Park 变换为什么能把交流变直流？

假设定子电流矢量在 αβ 平面旋转：

```text
Iα = I * cosθ
Iβ = I * sinθ
```

Park 变换公式：

```text
Id =  Iα * cosθ + Iβ * sinθ
Iq = -Iα * sinθ + Iβ * cosθ
```

代入后：

```text
Id = I * cosθ * cosθ + I * sinθ * sinθ
Id = I * (cos²θ + sin²θ)
Id = I
```

而：

```text
Iq = -I * cosθ * sinθ + I * sinθ * cosθ
Iq = 0
```

所以：

```text
原来在 αβ 坐标系里旋转变化的量，
到了 dq 坐标系里变成了稳定的直流量。
```

实际 FOC 中通常希望：

```text
Id ≈ 0
Iq ≈ 常数
```

这样 PI 控制器就非常好控制。

---

## 8. FOC 为什么必须知道电角度？

Park 变换需要知道转子当前转到哪里了，也就是：

```text
电角度 θ
```

因为要把 αβ 坐标系旋转到 dq 坐标系，必须知道旋转多少角度。

```text
Iα / Iβ 通过 θ 旋转 → Id / Iq
```

如果角度错了，dq 坐标系就无法对准转子磁场。

后果可能包括：

```text
Id / Iq 计算错误
转矩变小
电流变大
发热严重
抖动
噪声
效率下降
启动困难
甚至失步
```

所以 FOC 的核心之一是：

> 准确知道转子电角度。

---

## 9. 机械角度和电角度

### 机械角度

机械角度表示：

> 电机轴物理上真实转了多少角度。

例如：

```text
电机轴转一圈：机械角度 = 360°
电机轴转半圈：机械角度 = 180°
```

### 电角度

电角度表示：

> 转子磁场相对于定子三相绕组的电磁周期位置。

FOC 使用的是电角度，不是普通机械角度。

---

## 10. 极对数是什么？

极对数就是电机转子上 N/S 磁极的对数。

例如：

```text
1 个 N 极 + 1 个 S 极
= 2 极电机
= 1 对极
= 极对数 1
```

```text
2 个 N 极 + 2 个 S 极
= 4 极电机
= 2 对极
= 极对数 2
```

```text
7 个 N 极 + 7 个 S 极
= 14 极电机
= 7 对极
= 极对数 7
```

---

## 11. 电角度和机械角度的关系

核心公式：

```text
电角度 = 机械角度 × 极对数
```

代码中通常写成：

```c
theta_e = theta_m * pole_pairs;
theta_e = normalize_0_to_2pi(theta_e);
```

如果用角度制：

```c
electrical_angle = mechanical_angle * pole_pairs;
electrical_angle = fmod(electrical_angle, 360.0f);
```

如果用弧度制：

```c
theta_e = theta_m * pole_pairs;
theta_e = normalize_0_to_2pi(theta_e);
```

---

## 12. 为什么机械转一圈，电角度可能转好几圈？

关键在于：

> 转子机械转一圈时，定子线圈会看到多少次 N/S 磁场变化。

如果是 1 对极电机：

```text
机械转一圈
磁场周期变化 1 次
电角度转 1 圈
```

如果是 7 对极电机：

```text
机械转一圈
磁场周期变化 7 次
电角度转 7 圈
```

所以：

```text
机械角度描述的是轴的位置
电角度描述的是磁场周期的位置
```

### 7 对极示例

```text
机械角度 0°      → 电角度 0°
机械角度 10°     → 电角度 70°
机械角度 20°     → 电角度 140°
机械角度 30°     → 电角度 210°
机械角度 40°     → 电角度 280°
机械角度 51.4°   → 电角度 360°
机械角度 360°    → 电角度 2520°
```

因为：

```text
360° × 7 = 2520°
```

实际控制中会把电角度归一化到：

```text
0° ~ 360°
```

或者：

```text
0 ~ 2π
```

---

## 13. 电角度不能表示机械绝对位置

对于 7 对极电机：

```text
机械 0°      → 电角 0°
机械 51.4°   → 电角 0°
机械 102.8°  → 电角 0°
机械 154.2°  → 电角 0°
```

可以看到，不同机械位置可能对应同一个电角度。

所以：

```text
机械角度：适合表示轴的实际位置
电角度：适合表示当前电磁周期位置
```

FOC 主要关心的是：

> 当前定子磁场应该如何推/拉转子磁场。

因此 FOC 用的是电角度。

---

## 14. 编码器读到的是机械角度还是电角度？

大多数编码器或磁编码器读到的是机械角度，例如：

```text
AS5600
MT6701
TLE5012
ABI 编码器
```

它们测的是电机轴的实际位置，也就是机械角度。

FOC 里面需要转换成电角度：

```c
theta_e = theta_m * pole_pairs + offset;
theta_e = normalize_0_to_2pi(theta_e);
```

其中：

```text
theta_m：机械角度
theta_e：电角度
pole_pairs：极对数
offset：电角度零点偏移
```

---

## 15. 为什么需要 offset？

因为编码器的 0° 不一定等于电机电角度的 0°。

也就是说：

```text
编码器机械零点 ≠ 电机 d 轴零点
```

所以需要做一次电角度零点校准。

常见叫法：

```text
电角度零点校准
encoder alignment
electrical zero offset calibration
```

最终代码可能是：

```c
theta_e = theta_m * pole_pairs + theta_offset;
```

也可能是：

```c
theta_e = theta_m * pole_pairs - theta_offset;
```

具体加还是减，取决于坐标定义和电机旋转方向。

---

## 16. offset 不对会怎样？

如果电角度零点偏移不对，会导致 dq 坐标系没有对准转子磁场。

常见现象：

```text
启动抖动
电流大
发热严重
转矩小
噪声大
速度上不去
正反转不一致
FOC 控制异常
```

本质原因是：

```text
你以为自己在控制 Iq，
但实际一部分电流跑到了 Id 上。
```

---

## 17. 电角度方向也很重要

除了 offset，角度方向也很重要。

如果编码器角度方向和电机电角度方向相反，例如：

```text
电机正转时，真实电角度增加
编码器读数却减少
```

那么 FOC 也会异常。

常见修正方法：

```c
theta_m = -theta_m;
```

或者：

```c
theta_e = -theta_m * pole_pairs + offset;
```

方向错时常见现象：

```text
一给电就抖
电机吸住不转
反向冲一下
电流暴涨
闭环失败
```

## 18. 电角度、电频率、机械转速的关系

机械频率：

```text
机械频率 Hz = RPM / 60
```

电频率：

```text
电频率 Hz = 机械频率 × 极对数
```

也就是：

```text
电频率 Hz = RPM / 60 × pole_pairs
```

例如：

```text
电机转速 = 3000 RPM
极对数 = 7
```

机械频率：

```text
3000 / 60 = 50 Hz
```

电频率：

```text
50 × 7 = 350 Hz
```

也就是说：

```text
电机轴每秒转 50 圈，
但是电磁正弦周期每秒变化 350 次。
```

## 19. 电角度在 Park 变换中的作用

Park 变换公式：

```c
Id =  Ialpha * cos(theta_e) + Ibeta * sin(theta_e);
Iq = -Ialpha * sin(theta_e) + Ibeta * cos(theta_e);
```

这里的 `theta_e` 必须是电角度。

它表示：

> 当前转子磁场坐标系相对于定子 αβ 坐标系转了多少电角度。

所以电角度是否准确，直接决定 Id/Iq 是否准确。

## 20. FOC 完整控制流程

完整 FOC 流程如下：

```text
采样三相电流
Ia, Ib, Ic
    ↓
Clarke 变换
Iα, Iβ
    ↓
Park 变换，需要转子电角度 θe
Id, Iq
    ↓
和目标值比较
Id_ref - Id
Iq_ref - Iq
    ↓
PI 控制器
Vd, Vq
    ↓
反 Park 变换
Vα, Vβ
    ↓
SVPWM
三相 PWM 占空比
    ↓
驱动逆变器
    ↓
控制电机三相电流
```

其中：

```text
Clarke / Park：
用于测量并理解当前电流

PI 控制器：
用于控制 Id / Iq

反 Park / SVPWM：
用于把控制结果重新变成三相电压 / PWM 去驱动电机
```

## 21. 为什么电流环不用 PI 直接控制 Ia/Ib/Ic？

因为 `Ia / Ib / Ic` 是高速变化的交流量。

而 `Id / Iq` 在转子坐标系下接近直流量。

PI 控制器控制直流量更简单：

```text
Id_ref = 0
Iq_ref = 3A

实际：
Id = 0.1A
Iq = 2.7A

误差：
Id_error = -0.1A
Iq_error = 0.3A
```

然后 PI 输出：

```text
Vd
Vq
```

这样控制逻辑非常清晰。

如果直接控制三相电流：

```text
Ia_ref = 正弦波
Ib_ref = 正弦波
Ic_ref = 正弦波
```

控制器需要不断追随变化目标，控制难度高，动态效果差。

## 22. FOC 在平衡车中的理解

平衡车最关心的不是电机转速，而是：

> 当前需要多大的力矩把车身扶起来。

控制流程可以理解为：

```text
车身倾倒
    ↓
姿态控制器计算需要的力矩
    ↓
转换成 Iq_ref
    ↓
FOC 电流环控制 Iq
    ↓
电机输出对应力矩
    ↓
车身被扶起来
```

平衡车中通常：

```c
Id_ref = 0;
Iq_ref = 姿态控制器输出的目标转矩电流;
```

所以 FOC 在平衡车中的核心价值是：

> 把电机变成一个可以快速、精准控制力矩的执行器。

---

## 23. 六步换相、正弦波控制和 FOC 的区别

理论上，不用 FOC 也可以让电机转，例如：

```text
六步换相
正弦波控制
SPWM 控制
```

但是这些方法不一定精确关心：

> 定子磁场和转子磁场之间的角度关系。

FOC 更高级的地方在于：

```text
实时知道转子电角度
实时把电流拆成 Id / Iq
精确控制产生转矩的那部分电流
```

FOC 的优点：

```text
低速力矩更好
效率更高
噪声更低
响应更快
转矩控制更准
动态性能更好
```

| 机械角度      | 电机轴真实转过的角度         | 位置控制、机械位置判断      |

## 25. 代码示例：机械角度转电角度

```c
#define PI 3.1415926f

float normalize_0_2pi(float angle)
{
    while (angle >= 2.0f * PI)
    {
        angle -= 2.0f * PI;
    }

    while (angle < 0.0f)
    {
        angle += 2.0f * PI;
    }

    return angle;
}

float get_electrical_angle(float theta_m, int pole_pairs, float offset)
{
    float theta_e;

    // 机械角度 × 极对数 + 零点偏移
    theta_e = theta_m * pole_pairs + offset;

    // 归一化到 0 ~ 2π
    theta_e = normalize_0_2pi(theta_e);

    return theta_e;
}
```

## 26. 最核心总结

FOC 里面为什么要做 Clarke 和 Park 变换？

因为：

> 电机本质上是靠定子磁场矢量拉着转子磁场转。三相电流只是产生这个磁场的手段。

所以需要：

```text
Clarke 变换：
把三相电流合成为一个二维磁场矢量。

Park 变换：
把这个磁场矢量放到转子坐标系下，拆成 Id 和 Iq。

Id：
控制磁链。

Iq：
控制转矩。
```

最终目的：

> 把不好控制的三相交流量，变成好控制的磁链电流 Id 和转矩电流 Iq。

````markdown
# FOC、Clarke/Park 变换与电角度总结

## 1. FOC 的核心思想

FOC，全称 Field Oriented Control，中文通常叫 **磁场定向控制**。

它的本质不是直接控制三相电流 `Ia / Ib / Ic`，而是控制：

> 定子磁场和转子磁场之间的关系。

电机真正产生转矩的关键，不是某一相电流本身，而是：

> 定子电流产生的旋转磁场，去拉着转子永磁体旋转。

FOC 的目标是让定子磁场始终以合适的角度拉动转子磁场，从而高效地产生转矩。

---

## 2. 为什么不直接控制三相电流？

三相电流是交流量：

```c
Ia = 正弦波
Ib = 相差 -120°
Ic = 相差 +120°
````

它们会随着电机转动不断变化。

如果直接控制 `Ia / Ib / Ic`，控制目标本身就是高速变化的正弦波，PI 控制器很难稳定控制。

而 PI 控制器更适合控制类似下面这种直流量：

```c
目标 = 3A
实际 = 2.8A
误差 = 0.2A
```

所以 FOC 要做的事情就是：

> 把不好控制的三相交流量，变成好控制的直流量。

---

## 3. Clarke 变换：三相变二维

三相电流为：

```c
Ia
Ib
Ic
```

但三相电机通常满足：

```c
Ia + Ib + Ic = 0
```

所以三相电流本质上只有两个自由度。

Clarke 变换的作用是：

> 把三相 `abc` 坐标，转换成二维静止坐标 `αβ`。

可以理解为：

```text
Ia, Ib, Ic
    ↓ Clarke 变换
Iα, Iβ
```

也就是：

> 把三相绕组产生的磁场，合成为一个二维平面上的电流矢量。

简单记忆：

```text
Clarke 变换 = 三相电流 → 一个磁场箭头
```

---

## 4. Park 变换：静止坐标变转子坐标

Clarke 变换之后得到的是：

```c
Ialpha
Ibeta
```

但是 `αβ` 坐标系是固定在定子上的，而转子在旋转。

所以在 `αβ` 坐标系里看，电流矢量仍然是旋转的。

Park 变换的作用是：

> 把静止的 `αβ` 坐标系，旋转到跟转子一起转的 `dq` 坐标系。

可以理解为：

```text
Iα, Iβ
    ↓ Park 变换
Id, Iq
```

其中：

| 变量   | 含义            |
| ---- | ------------- |
| `Id` | d 轴电流，控制磁链/励磁 |
| `Iq` | q 轴电流，控制转矩    |

简单记忆：

```text
Park 变换 = 站到转子身上，看磁场箭头相对转子往哪拉
```

---

## 5. Id 和 Iq 的含义

`dq` 坐标系有两个轴：

```text
d 轴：和转子磁链方向对齐
q 轴：和转子磁链垂直
```

### Id：磁链电流

`Id` 沿着转子磁场方向。

它主要影响磁链。

对于常见表贴式 PMSM，通常希望：

```c
Id_ref = 0;
```

因为永磁体本身已经提供磁场了，额外加 `Id` 通常意义不大，还会增加损耗。

---

### Iq：转矩电流

`Iq` 和转子磁场垂直。

它主要产生转矩。

```text
Iq 越大，电机输出力矩越大
Iq 改变正负，电机力矩方向改变
```

所以 FOC 最常见的控制目标是：

```c
Id_ref = 0;
Iq_ref = 目标转矩电流;
```

---

## 6. FOC 为什么像直流电机控制？

直流电机里可以理解为：

```text
励磁电流 → 控制磁场
电枢电流 → 控制转矩
```

FOC 里对应为：

```text
Id → 控制磁链
Iq → 控制转矩
```

所以 FOC 的核心价值是：

> 把复杂的三相交流电机，控制成类似直流电机那样简单。

---

## 7. FOC 完整控制流程

完整 FOC 流程如下：

```text
采样三相电流
Ia, Ib, Ic
    ↓
Clarke 变换
Iα, Iβ
    ↓
Park 变换，需要转子电角度 θ
Id, Iq
    ↓
与目标值比较
Id_ref - Id
Iq_ref - Iq
    ↓
PI 控制器
Vd, Vq
    ↓
反 Park 变换
Vα, Vβ
    ↓
SVPWM
三相 PWM 占空比
    ↓
驱动逆变器
    ↓
控制电机三相电流
```

其中：

```text
Clarke / Park：
用于理解当前电流状态，把三相电流变成 Id / Iq。

反 Park / SVPWM：
用于把控制器输出重新变成三相 PWM，驱动电机。
```

---

## 8. Park 变换为什么能把交流变直流？

假设电流矢量在 `αβ` 坐标系中旋转：

```c
Ialpha = I * cos(theta)
Ibeta  = I * sin(theta)
```

Park 变换为：

```c
Id =  Ialpha * cos(theta) + Ibeta * sin(theta);
Iq = -Ialpha * sin(theta) + Ibeta * cos(theta);
```

代入后：

```c
Id = I
Iq = 0
```

也就是说：

> 原来在静止坐标系里旋转变化的交流量，到了跟着转子旋转的坐标系里，就变成了接近不变的直流量。

这就是 FOC 可以用 PI 控制器稳定控制电流环的原因。

---

## 9. 为什么 FOC 必须知道电角度？

Park 变换需要知道转子磁场当前的位置，也就是：

```text
电角度 theta_e
```

因为 Park 变换要把 `αβ` 坐标系旋转到 `dq` 坐标系。

如果角度错了，`d` 轴和 `q` 轴就对不准转子磁场。

后果包括：

```text
Id / Iq 计算错误
转矩变小
电流变大
发热严重
电机抖动
噪声变大
效率下降
启动困难
甚至失步
```

所以 FOC 的核心之一就是：

> 准确知道转子电角度。

---

## 10. 机械角度和电角度

### 机械角度

机械角度表示：

> 电机轴物理上转了多少度。

例如：

```text
电机轴转一圈 = 机械角度 360°
电机轴转半圈 = 机械角度 180°
```

---

### 电角度

电角度表示：

> 转子磁场在电磁周期中转到了哪里。

它不是看轴转了多少，而是看：

```text
N/S 磁极周期相对于定子绕组变化到了哪个相位。
```

---

## 11. 极对数

极对数是电机转子上 N/S 磁极的对数。

例如：

| 电机磁极          | 极对数  |
| ------------- | ---- |
| 1 个 N + 1 个 S | 1 对极 |
| 2 个 N + 2 个 S | 2 对极 |
| 7 个 N + 7 个 S | 7 对极 |

极对数越多，机械转一圈时，定子绕组看到的磁场周期就越多。

---

## 12. 电角度和机械角度的关系

公式：

```c
电角度 = 机械角度 × 极对数
```

如果用弧度：

```c
theta_e = theta_m * pole_pairs;
```

实际代码里通常还要加零点偏移：

```c
theta_e = theta_m * pole_pairs + offset;
theta_e = normalize_0_2pi(theta_e);
```

---

## 13. 举例理解电角度

### 1 对极电机

```text
极对数 = 1
机械转一圈 = 360°
电角度转一圈 = 360°
```

所以：

```text
机械角度 = 电角度
```

---

### 7 对极电机

```text
极对数 = 7
机械转一圈 = 360°
电角度转 7 圈 = 2520°
```

也就是说：

```text
机械转 360°
电磁周期重复 7 次
```

如果机械角度为 `20°`：

```c
theta_e = 20° × 7 = 140°
```

如果机械角度为 `51.4°`：

```c
theta_e = 51.4° × 7 ≈ 360°
```

所以 7 对极电机里：

> 机械只转了约 51.4°，电角度已经完成一整圈。

---

## 14. 为什么电角度可能转很多圈？

因为转子上一圈可能有很多组 N/S 磁极。

比如 7 对极电机：

```text
机械一圈 360°
|------------------------------------------------|

电角度周期：
|---360°---|---360°---|---360°---|---360°---|---360°---|---360°---|---360°---|
第1对极     第2对极     第3对极     第4对极     第5对极     第6对极     第7对极
```

所以：

```text
机械角度：看轴实际转了多少
电角度：看磁场周期走到了哪里
```

一句话理解：

> 机械角度看的是轴，电角度看的是磁场周期。

---

## 15. 电角度不能代表绝对机械位置

以 7 对极电机为例：

```text
机械 0°      → 电角度 0°
机械 51.4°   → 电角度 360° → 取模后 0°
机械 102.8°  → 电角度 720° → 取模后 0°
```

所以很多不同的机械位置，可能对应同一个电角度。

因此：

```text
机械角度：适合做位置控制、机械位置判断
电角度：适合做 FOC、电流控制、Park 变换、SVPWM
```

---

## 16. 编码器读到的是机械角度还是电角度？

大多数编码器、磁编码器读到的是机械角度，例如：

```text
AS5600
MT6701
TLE5012
ABI 编码器
```

FOC 里需要转换成电角度：

```c
theta_e = theta_m * pole_pairs + offset;
theta_e = normalize_0_2pi(theta_e);
```

其中 `offset` 是电角度零点偏移。

---

## 17. 为什么需要 offset？

因为编码器的机械 0° 不一定等于电机电角度 0°。

也就是说：

```text
编码器 0° 不一定刚好对应转子 d 轴对准 A 相的位置。
```

所以需要做零点校准，也叫：

```text
电角度零点校准
encoder alignment
electrical zero offset calibration
```

如果 offset 不准，会导致：

```text
启动抖动
电流大
发热
转矩小
噪声大
速度上不去
正反转不一致
FOC 控制异常
```

---

## 18. 电角度方向也很重要

如果编码器方向和电机电角度方向相反，也会导致 FOC 异常。

常见修正方式：

```c
theta_e = -theta_m * pole_pairs + offset;
```

方向错误时常见现象：

```text
一给电就抖
电机吸住不转
反向冲一下
电流暴涨
闭环失败
```

---

## 19. 平衡车中 FOC 的意义

平衡车最关心的不是电机速度，而是：

> 当前需要多大的力矩把车身扶起来。

控制流程可以理解为：

```text
车身倾倒
    ↓
姿态控制器计算需要的力矩
    ↓
转换成 Iq_ref
    ↓
FOC 电流环控制 Iq
    ↓
电机输出对应力矩
    ↓
车身被扶起来
```

所以在平衡车里，FOC 的核心价值是：

> 把电机变成一个可以快速、精准控制力矩的执行器。

---

## 20. FOC 相比普通控制方式的优势

普通六步换相、正弦波控制、SPWM 也能让电机转。

但它们通常没有像 FOC 这样精确地控制：

```text
定子磁场和转子磁场之间的角度关系
```

FOC 的优势包括：

```text
低速力矩更好
效率更高
噪声更低
响应更快
转矩控制更准
动态性能更好
```

对于平衡车、电动车、伺服电机等需要快速调节转矩的场景，FOC 很适合。
