可以把 **Q31 定点** 和 **标幺化（Per-Unit，PU）** 理解成 FOC 里非常常见的两套“数据表示方法”。

一句话先记住：

> **标幺化：把真实物理量变成“相对于基准值的比例”。**
> **Q31：把这个比例用整数来存，避免 MCU 上大量使用浮点数。**

两者经常是**配套使用**的。

---

# 1. 先说标幺化到底是什么

假设你的电机：

* 母线电压：12 V
* 最大允许电流：5 A
* 最大转速：10000 RPM

实际 FOC 里，如果全部直接用：

```text
电压：12V
电流：5A
速度：10000RPM
角度：0~360°
```

不同量纲混在一起，计算和调参都比较麻烦。

所以我们给每个物理量规定一个“基准值”。

例如：

```text
Vbase = 12V
Ibase = 5A
ωbase = 10000RPM
```

然后：

$$
V_{pu}=\frac{V}{V_{base}}
$$

例如实际输出：

$$
V=6V
$$

那么：

$$
V_{pu}=\frac{6}{12}=0.5
$$

也就是说：

> **6V = 0.5 pu**

---

# 2. 电流也是一样

假设：

$$
I_{base}=5A
$$

实际测到：

$$
I=2A
$$

那么：

$$
I_{pu}=\frac{2}{5}=0.4
$$

所以：

```text
2A = 0.4 pu
```

---

# 3. 速度也可以标幺化

比如：

$$
RPM_{base}=10000
$$

实际：

$$
RPM=3000
$$

那么：

$$
RPM_{pu}=0.3
$$

所以：

```text
3000 RPM = 0.3 pu
```

---

# 4. 为什么 FOC 特别喜欢标幺化？

因为 FOC 里面各种东西很多：

```text
Ia Ib Ic
Iα Iβ
Id Iq
Uα Uβ
Ud Uq
ω
θ
Rs
Ls
ψf
Kp
Ki
...
```

如果全部使用真实单位：

```text
A
V
rad/s
Wb
H
Ω
```

参数范围可能差别巨大。

例如：

```text
电流       0 ~ 10 A
电压       0 ~ 48 V
电感       0.001 H
磁链       0.005 Wb
角速度     0 ~ 3000 rad/s
```

标幺化以后很多量都被压缩到：

```text
-1 ~ +1
```

附近。

这对 MCU 的定点运算特别友好。

---

# 5. 然后就是 Q31

这时候问题来了：

假设我们已经把：

```text
电流  → 0.4 pu
电压  → 0.5 pu
```

但是 MCU 还是要存这个 `0.4`、`0.5`。

如果不用浮点，而用整数怎么办？

这就是 **Q31**。

---

# 6. Q31 是什么？

Q31 本质上就是：

> **用一个 32 位整数来表示一个小数。**

对于常见的有符号 Q31：

```text
32 bit
┌───┬───────────────────────────────┐
│ S │           31 bit              │
└───┴───────────────────────────────┘
```

它实际上把：

$$
[-1,1)
$$

映射到：

$$
[-2^{31},2^{31}-1]
$$

也就是：

```text
-1.0        → -2147483648
 0          → 0
+1.0        → 2147483647
```

---

# 7. 举个最直观的例子

假设：

```text
Id = 0.5 pu
```

转换成 Q31：

$$
0.5\times2^{31}
$$

得到：

$$
1073741824
$$

所以：

```c
float:
0.5

Q31:
1073741824
```

它们表达的是**同一个东西**。

---

# 8. 再比如 0.25

$$
0.25\times2^{31}
$$

得到：

$$
536870912
$$

所以：

```text
0.25 pu
=
536870912 Q31
```

---

# 9. 为什么叫 Q31？

这里的：

```text
Q31
```

可以简单理解成：

> **小数点固定在 31 位的位置。**

比如一个整数：

```text
1073741824
```

在普通整数眼里，它就是十亿。

但是在 Q31 眼里：

```text
1073741824 / 2^31 = 0.5
```

所以：

```text
1073741824(Q31) = 0.5
```

---

# 10. 于是你就能理解“标幺化 + Q31”的关系了

例如你的电机实际电流：

```text
I = 2A
```

假设：

```text
Ibase = 5A
```

第一步：**标幺化**

$$
I_{pu}=\frac{2}{5}=0.4
$$

第二步：**Q31**

$$
I_{Q31}=0.4\times2^{31}
$$

得到：

$$
858993459
$$

于是：

```text
真实世界：

2 A

        ↓ 标幺化

0.4 pu

        ↓ Q31

858993459
```

反过来也一样：

```text
858993459
        ↓ / 2^31
0.4 pu
        ↓ × 5A
2 A
```

---

# 11. 这对 FOC 有什么实际意义？

比如你做 Clarke：

$$
I_\alpha=I_a
$$

$$
I_\beta=\frac{I_a+2I_b}{\sqrt3}
$$

如果使用浮点：

```c
float ia;
float ib;
float ialpha;
float ibeta;

ibeta = (ia + 2.0f * ib) * 0.577350269f;
```

如果使用 Q31：

```text
ia
ib
```

本身都是 Q31。

然后：

```text
Q31 × Q31
```

产生更宽的结果，再通过右移恢复 Q31。

这样整个 FOC 数据链都可以使用整数。

---

# 12. 为什么以前 STM32 / DSP 很喜欢这么干？

尤其是早期 MCU/DSP：

```text
没有 FPU
```

或者 FPU 性能比较有限。

做这种：

```text
sin()
cos()
sqrt()
乘法
除法
PI
Clarke
Park
SVPWM
```

大量浮点运算会比较吃 CPU。

于是工程师喜欢：

```text
物理量
 ↓
标幺化
 ↓
Q15 / Q31
 ↓
整数运算
 ↓
非常快
```

例如：

```text
STM32F1
TI C2000 某些场景
DSP
老式电机控制器
```

都非常常见。

---

# 13. Q15 和 Q31 又是什么？

原理一样。

### Q15

通常用 16 bit 表示：

$$
[-1,1)
$$

对应：

```text
-32768 ~ +32767
```

例如：

```text
0.5 pu

→ 0.5 × 32768

→ 16384
```

---

### Q31

32 bit：

```text
-2147483648 ~ +2147483647
```

例如：

```text
0.5 pu

→ 1073741824
```

所以：

```text
Q15
精度较低
占 16 bit

Q31
精度更高
占 32 bit
```

---

# 14. 为什么不用 Q31 表示真实的 12V？

注意一个非常重要的点：

**Q31 通常不是直接表示 12V。**

而是：

```text
12V
 ↓
标幺化
 ↓
1.0 pu
 ↓
Q31
 ↓
2147483647
```

例如：

```text
6V
 ↓
6 / 12
 ↓
0.5 pu
 ↓
Q31
 ↓
1073741824
```

所以：

> **Q31解决的是“怎么存小数”。**
> **标幺化解决的是“物理量怎么归一化”。**

这两个概念千万别混。

# 15. 放到你的 FOC 里就非常直观了

你现在做的 FOC 大概是：

```text
ADC
 ↓
Ia/Ib/Ic
 ↓
Clarke
 ↓
Iα/Iβ
 ↓
Park
 ↓
Id/Iq
 ↓
PI
 ↓
Ud/Uq
 ↓
反Park
 ↓
Uα/Uβ
 ↓
SVPWM
```

如果全部使用浮点：

```text
Ia = 0.82 A
Ib = -0.37 A

Id = 0.15 A
Iq = 0.76 A

Uq = 3.2 V
```

如果使用标幺：

```text
Ia = 0.164 pu
Ib = -0.074 pu

Id = 0.030 pu
Iq = 0.152 pu

Uq = 0.267 pu
```

再使用 Q31：

```text
Ia → Q31
Ib → Q31

Id → Q31
Iq → Q31

Uq → Q31
```

于是整个控制链都可以在：

```text
-1 ~ +1
```

这个范围附近工作。

# 16. 但是你现在的 ESP32 FOC，其实没必要强行 Q31

这个对你特别重要。

你现在用的是：

**ESP32 + ESP-IDF + 20kHz FOC + 浮点计算**

ESP32 有硬件浮点能力，现代 MCU 做 FOC 使用 `float` 是非常正常的。

所以你完全可以：

```c
float ia;
float ib;
float id;
float iq;

float ud;
float uq;

float theta;
float omega;
```

直接干。

没必要为了“专业”硬上 Q31。

# 18. 最后给你一个特别好记的关系

把它想象成“人民币”。

假设：

```text
100 元 = 1 个基准单位
```

那么：

```text
50 元 = 0.5 个基准单位
```

这就是：

**标幺化**

然后为了方便存储，我们规定：

```text
1.0 = 2147483648
```

那么：

```text
0.5 = 1073741824
```

这就是：

**Q31**

所以：

> **标幺化 = 改单位。**
> **Q31 = 改存储方式。**

在 FOC 中经常就是：

```text
        真实物理量
            │
            ▼
      标幺化 / PU
            │
            ▼
       -1 ~ +1
            │
            ▼
       Q31 定点化
            │
            ▼
       MCU整数运算
            │
            ▼
        FOC算法
```

**你如果正在看某套 FOC 源码里的 Q31/PU，我也可以直接拿“电流采样 → Clarke → Park → PI → SVPWM”这条链，给你逐个解释每一个 Q31 数字到底代表多少安、多少伏。**
