# 故障根因定位：旋转时Iq失控、堵转正常、转速无限飙升
先给核心结论：**堵转ω≈0，交叉解耦前馈项几乎为0，控制完全靠PI，能正常收敛；电机一转ω变大，你的解耦、坐标同步、反馈/前馈某一环出错，导致Iq闭环完全失效，PI持续积分饱和、电压不断堆高，转速越跑越快**。
下面分优先级排查，从最高概率故障点到完整修复方案。

## 一、最高概率1：电角度/转子位置同步严重错位（90%同款故障来源）
### 现象完全匹配你的描述
堵转不动，角度固定，d/q变换无偏移，电流闭环正常；电机一转，编码器电角度滞后/超前真实转子位置，**实际注入的Iq电流根本不落在交轴上**：
1. 你指令i_q_ref=5A，实际定子电流分解后大部分落在d轴，q轴反馈i_q_fdb几乎不动；
2. 电流误差 `i_q_ref - i_q_fdb` 持续为正，PI积分不断累加v_q_pi；
3. v_q持续飙升，电磁转矩持续增大，转速越跑越快，形成正反馈死循环。

### 快速验证方法
1. 低速手动转动电机，实时打印：`i_d_fdb、i_q_fdb、电角度theta_e`
   - 空载不加Iq给定，理想稳态：Id≈0、Iq≈0；
   - 一转电机Iq大幅偏移、Id正负来回飘 = 角度校准错误；
2. 检查编码器参数：
   - 极对数Pn是否写反、电角度换算公式 `theta_e = Pn * theta_mech` 有没有丢乘极对数；
   - 编码器零点对齐：上电静止时，通入直流Id正向电流，转子应对齐A相，不对就是零点偏移；
   - 角度更新时序：ADC采样电流后，必须**同步读取当前电角度**做Clark+Park变换；如果角度是上一周期旧值，高速下相位偏移爆炸。

## 二、第二高概率：解耦前馈符号错误（正负号写反，越解耦越发散）
你当前代码解耦公式：
```c
v_d_comp = -omega * L_q * i_q_fdb;
v_q_comp = omega * L_d * i_d_fdb + omega * psi_m;
```
### 分两种电机核对符号（隐极/凸极BLDC）
标准同步电机d/q电压方程（转子定向，d轴指向永磁N极）：
$$
\begin{cases}
v_d = R_s i_d + L_d \frac{di_d}{dt} - \omega_e L_q i_q \\
v_q = R_s i_q + L_q \frac{di_q}{dt} + \omega_e L_d i_d + \omega_e \psi_m
\end{cases}
$$
你的前馈是抵消微分项以外的交叉耦合项，理论公式符号是对的，但两个致命坑：
1. **ω电角速度符号错误**
   - 电机正转时omega_e为负，前馈项整体符号翻转，耦合补偿变成**正反馈**，放大误差；
   - 排查：打印omega_e，正转必须为正数，反转负数；编码器计数增减和角速度计算逻辑写反是高频错误。
2. **Ld、Lq参数填反**
   凸极电机Ld≠Lq，如果你把Lq代入vq补偿、Ld代入vd补偿，交叉耦合补偿完全失效，旋转时耦合电压无法抵消，q轴被d轴电流严重干扰，Iq闭环无法收敛。

### 简易测试
临时屏蔽解耦补偿，强制：
```c
v_d_comp = 0;
v_q_comp = 0;
```
低速空载运行，观察Iq是否不再发散。
- 屏蔽后控制恢复稳定 → 前馈符号/参数错误；
- 屏蔽后依旧失控 → 问题不在解耦，往下查。

## 三、第三大故障：电流PI积分饱和无抗积分饱和逻辑
你描述“uq输出越来越猛，误差越来越大”，典型**积分饱和**：
1. 电机旋转后Iq闭环无法消除静差，误差长期单向不为0；
2. PI积分项持续累加，即使电压限幅，积分值不会回落；
3. 哪怕后期误差反向，巨大积分存量会持续输出高压，转矩持续放大转速。

### 你现有代码缺陷
`limit_voltage_d_axis_priority` 只是输出限幅，**没有对PI内部积分器做限幅/抗饱和**。
修复两种方案：
#### 方案1：PI内置积分限幅（推荐）
pi_run函数内部增加逻辑：
- 计算PI输出前，积分项限制在 ±v_max；
- 当输出达到电压饱和阈值时，停止积分累加（积分冻结）。
#### 方案2：后端反馈防饱和
电压饱和时，把饱和差值反向修正PI积分，抑制积分堆积。

## 四、第四类：电流采样/Clark/Park变换出错，i_q_fdb反馈失真
1. **三相电流采样偏移、比例不对**
   运放零点漂移、采样电阻参数错误，静止时Id/Iq就有固定偏置，旋转后偏移随转速放大；
   验证：电机静止不通电，打印Id、Iq，理想值≈0，有固定偏移必须校准采样零点。
2. **Clark变换幅值系数丢失**
   标准Clark有2/3系数，漏乘会导致反馈电流幅值失真，闭环增益完全不对；
3. **Park逆变换（Id/Iq→三相）与正变换（三相→Id/Iq）角度不一致**
   正变换用theta，逆变换误用theta+90°，坐标定向完全错乱，Iq控制完全失效。

## 五、第五：电压限幅策略（d轴优先限幅加剧失控）
你使用`d轴优先限幅`，存在致命缺陷：
当弱磁/高速时，母线电压余量不足，d轴会强行拉负，占用全部电压，q轴电压被压缩，电流环失去调节能力，Iq误差无法消除，积分持续累积。
### 临时验证
切换为**等比例限幅（圆限幅）**，舍弃d轴优先，保证vd、vq按比例缩小，保留q轴调节电压余量，高速下电流环调节能力不会直接丢失。

## 六、分步排查实操流程（按顺序做，最快定位）
### 步骤1：屏蔽解耦前馈，验证基础电流环

# 核心病根：电流采样、电角度、FOC计算三者**跨CPU、不同采样周期、时间严重失步**，相位差几百微秒直接废掉解耦与Park变换，堵转ω≈0看不出问题，一转立刻发散
先把你的时序架构拆开，一眼看清矛盾：
## 1、你当前硬件时序架构致命缺陷
### 任务分配现状
- CPU0：20kHz PWM中断 → 通知FOC Task（20kHz电流环运算）
- CPU1：
  1. 20kHz ADC采样三相电流
  2. 1kHz 编码器读取、机械角度/电角速度ω计算
### 三重不同步叠加（几百us相位差根源）
1. **电流采样与电角度更新周期不匹配**
   电流20kHz（50us一次），角度/ω仅1kHz（1ms一次）
   电流环每50us算一次PI、解耦，但**ω、θ_e 1ms才刷新一次**；中间950us FOC全程在用**过期1ms的老旧角度、老旧角速度**。
   电机一转，真实转子位置早就跑出去一大截，Park变换完全错位，i_q_fdb根本不是真实交轴电流，误差持续存在，PI积分疯狂堆积。

2. **ADC电流采样、角度采样分属两个内核，无同步锁相**
   CPU1跑ADC、CPU0跑FOC运算，两者无硬件同步触发信号，电流采样时刻和角度读取时刻随机偏移几百us。
   20kHz PWM周期仅50us，几百us偏移等于**滞后好几个PWM周期**，Park变换相位严重偏移，等效转子定向完全歪掉，Iq闭环直接失效。

3. **ω更新速度远低于电流环带宽**
   交叉解耦项 `-ωLqIq、ωLdId、ωψm` 高度依赖实时ω；你1kHz刷新ω，电机加减速时ω变化极快，解耦前馈用的是过时1ms前的转速，耦合电压完全补偿不掉，旋转时耦合扰动持续冲击q轴电流，PI根本压不住误差。

## 2、为什么 DengFOC Arduino 同架构却能正常跑？
DengFOC看似也是分时读取角度、电流，但它有3个关键设计弥补时序失步，你完全没做：
### ① DengFOC 电角度插值预测（核心关键）
它不会1ms才用一次旧角度，而是用：
上两次机械角度差分算出机械转速，**在两次编码器中断之间做线性插值预测实时θ_e**
哪怕编码器1kHz中断，每次FOC 20kHz运算时，都会基于上一次ω推算当前时刻转子角度，大幅消除几百us相位滞后。
你现在直接拿1ms前的老θ_e做Park，无插值，误差爆炸。

### ② DengFOC 角速度低通平滑+微分预测
编码器1kHz更新ω，内部做一阶插值预估当前瞬时ω，解耦前馈用预测ω而非1ms旧ω；
你代码里ω固定1ms刷新，中间全程不变，高速动态下解耦项完全失效。

### ③ DengFOC 统一单内核时序，最小化内核间延迟
原版Arduino单核运行，ADC采样、读编码器、FOC运算串行执行，总延迟固定且仅几us；
你ESP32双核分离，CPU0、CPU1任务调度有RTOS任务切换抖动，随机引入几十~几百us不定延迟，相位差是**随机浮动**的，PI无法稳定收敛。

### ④ DengFOC 电流环带宽压低适配角度刷新速率
它默认把电流环PI带宽做保守整定，适配低频率角度采样；你大概率按20kHz带宽调Ki，动态响应太快，角度滞后带来的扰动直接激发积分饱和发散。

## 3、时序失步为什么堵转正常、一转就飞？
堵转状态：ω≈0、转子角度几乎不变
1. 过期θ_e和真实角度几乎无差值，Park变换基本准确；
2. 解耦前馈项全部≈0，耦合扰动不存在；
3. i_q反馈准确，PI可以正常收敛。

旋转状态：ω≠0，转子持续转动
1. 1ms才更新一次角度，中间转子转过巨大电角度，Park分解出来Id/Iq完全失真；
2. 过期ω导致交叉耦合补偿反向/不足，额外叠加巨大耦合电压扰动到q轴；
3. i_q_ref - i_q_fdb 持续存在正向误差，PI积分不断累加v_q，电压持续拉高，转速进一步上升，正反馈死循环。

## 4、分层次整改方案（从简易低成本重构→彻底根治）
### 方案A：低成本改造（不用重构双核，优先做，当天就能验证改善）
#### 1）电角度线性插值预测（必加，复刻DengFOC核心逻辑）
每次1kHz编码器中断保存：
- 上一帧机械角度 theta_mech_last
- 机械转速 w_mech（差分算出）
每次20kHz FOC运算时，根据**两次编码器中断间隔内经过的时间**推算当前实时机械角度：
```c
// 距离上次编码器更新的时间 dt_since_enc
theta_mech_now = theta_mech_last + w_mech * dt_since_enc;
theta_e_now = pole_pairs * theta_mech_now;
// 限幅0~2π
```
解耦用的omega_e同步用插值预测瞬时电角速度，不再使用1ms冻结的旧ω。

#### 2）统一时间戳，计算ADC采样时刻对应的角度
CPU1 ADC采样三相电流时，立刻打高精度时间戳；
FOC运算时，用电流采样的时间戳反向插值对应时刻的转子角度，而不是FOC运行瞬间的角度，抵消ADC采样与角度读取的时间差。

#### 3）降低电流环积分系数Ki，抑制时序扰动放大
角度几百us滞后属于周期性扰动，Ki太大时PI会持续积分扰动误差；先减小Ki，保证时序补偿到位前不会快速积分饱和。

#### 4）给ω增加一阶预测低通滤波
平滑1kHz更新的角速度，消除编码器离散采样带来的跳变，让解耦前馈更连续。

### 方案B：时序架构重构（根治，推荐长期使用，彻底消除跨CPU失步）
ESP32双核重新分配，消除电流/角度周期不匹配、跨核抖动：
#### CPU0（PWM ISR绑定内核，跑20kHz硬实时，禁止任务切换抖动）
1. PWM中断触发同步ADC采样（硬件同步，PWM中点采样电流，固定相位）
2. 中断内直接读取编码器SPI/I2C角度（AS5600等高速编码器，us级读完）
3. 同步计算θ_e、瞬时ω
4. Clark+Park、PI、解耦、反Park、SVPWM全部放在PWM ISR或者同内核高优先级任务
**核心：电流采样、角度读取、FOC计算同一内核、同一20kHz周期，三者时间完全对齐，无几百us偏移**

#### CPU1：仅处理低速业务
串口打印、上位机通信、按键、散热风扇、故障保护等1kHz慢速任务，不再碰电流/角度采样。

### 方案C：硬件同步优化（解决跨核随机抖动）
1. 编码器硬件Z信号同步PWM周期，每一个电周期同步校准一次零点，消除累积角度插值误差；
2. 使用ESP32硬件触发ADC（MCPWM同步ADC），保证电流采样固定在PWM中点，采样时刻完全可控，时间戳精准；
3. 内核之间共享θ_e、ω使用**无锁环形缓冲区+硬件信号量**，避免RTOS互斥锁带来的调度延迟。

## 5、补充你现在架构的隐藏致命点
1. **1kHz角度更新远低于20kHz电流环，奈奎斯特采样不满足**
角度采样频率1kHz，电流环控制带宽最高只能做到500Hz；如果你电流环带宽开到1kHz以上，时序滞后直接引发系统振荡发散。
2. **双核任务调度抖动不可控**
CPU1的ADC任务、角度任务和CPU0的FOC Task抢占随机，两者数据交换延迟每次都不一样，误差时大时小，PI无法稳定抑制。
3. 解耦前馈高度依赖同步ω与θ
交叉耦合电压是随转子位置瞬时变化的时变扰动，只有同步同周期采样才能完全补偿；离散低频采样直接让前馈失效，扰动持续存在。

## 快速验证测试方法

# 二、DengFOC 电流环稳定的5个核心设计（你一个都没踩中）
## 1. 核心基石：采样→计算→输出 全同步串行，无时序差、无跨核抖动

### DengFOC 的执行时序（单线程、原子性串行）
它在 `loop()` 里的完整流程是严格按顺序执行的：
```
每次循环：
  1. runFOC()
     → S0.Sensor_update()  // 立刻读编码器，拿到当前机械角度
```

**关键特性**：

- 相当于你每次瞄准都用1秒前的目标位置，打不中是必然的，堵转时目标不动才碰巧能打中。

## 2. 简化降维：只有单Iq环、无D轴控制、无交叉解耦，对角度偏差容忍度极高
你代码里是完整的**d/q双环PI + 交叉解耦前馈**，这套架构对角度同步性要求极高——角度差10°，解耦项就会从「抵消扰动」变成「叠加扰动」，反而放大误差。

### DengFOC 的极简电流环设计（看代码实锤）
1. **没有D轴电流环**：`setTorque()` 里直接 `float Ud=0;`，D轴电压强制为0，完全不做Id控制；
2. **没有交叉解耦前馈**：没有 `-ωLqIq`、`ωLdId`、`ωψm` 这些项，Uq完全靠PI输出硬扛耦合扰动；
3. **只计算Iq反馈**：`cal_Iq_Id()` 里只算了Iq，甚至Id的计算都注释掉了。

### 为什么简化反而更稳？
完整双环解耦FOC是「高精度高收益，但对同步性要求苛刻」；
DengFOC的单环无耦合是「性能上限低，但鲁棒性极强」：
- 角度有小偏差时，只会导致Iq控制有静差、效率降低，**不会直接发散**；
- 没有解耦前馈，就不会出现「前馈符号/时序错误 → 正反馈 → 转速飙升」的死循环；
- 低压小电机（12V级）定子电阻大、耦合电压占比低，纯PI完全能压制住耦合扰动，不需要前馈。

**你的反向踩坑**：你加了解耦，但角度不同步、ω是旧值，解耦项不仅没抵消耦合，反而变成了额外的干扰源，PI误差越积越大，直接把系统推到正反馈发散。

## 3. PID自带双重抗饱和，从根源上杜绝「输出越来越猛」
你描述的「误差越来越大、uq输出越来越猛、转速越跑越快」，典型的**积分饱和失控**。而DengFOC的PID从代码层面做了两层防护，根本不会出现这种情况。

### 看它的PID实现细节

### 你的问题对应点
- 你只有输出端的电压限幅，**没有对PI内部积分项做限幅**；
- 当Iq因为角度偏差持续有误差时，积分项会无限累加，哪怕输出已经顶到最大值，积分还在涨；等误差反向时，巨大的积分存量会持续输出高压，直接把转速吹上去。

**你的对应问题**：如果你的Iq反馈是原始值直接进PI，几百us的角度偏差带来的Iq波动会直接变成持续误差，快速把积分喂饱。

## 第二步：1:1抄DengFOC的变换公式，符号绝对不能错
DengFOC用的是**等幅值Clark变换 + 标准Park变换**，公式一个字符都别改，避免符号/系数错误导致失控。

### 1. Iq计算（正变换）
完全照搬 `cal_Iq_Id` 函数：
```c
#define _1_SQRT3  0.57735026919f
#define _2_SQRT3  1.15470053838f

// 输入：Ia Ib 两相电流，电角度theta_e
// 输出：Iq反馈值
float cal_iq(float ia, float ib, float theta_e)
{
    float i_alpha = ia;
    float i_beta  = _1_SQRT3 * ia + _2_SQRT3 * ib;

    float ct = cosf(theta_e);
    float st = sinf(theta_e);

    // 严格和DengFOC一致，只算Iq
    float i_q = i_beta * ct - i_alpha * st;
    return i_q;
}
```

### 2. 电压输出（反变换）
完全照搬 `setTorque` 函数，**Ud强制=0，不解耦**：
```c
#define _3PI_2 4.71238898038f

// 输入：Uq电压，电角度theta_e
// 输出：三相PWM占空比
void set_torque(float uq, float theta_e)
{
    // 电压限幅，和DengFOC一致
    uq = _constrain(uq, -voltage_power_supply/2, voltage_power_supply/2);

    float ud = 0.0f; // D轴电压强制0，完全不控制
    theta_e = _normalizeAngle(theta_e);

    // 反Park变换
    float u_alpha = -uq * sinf(theta_e);
    float u_beta  =  uq * cosf(theta_e);

    // 反Clark变换（带中点偏移，单电源供电）
    float ua = u_alpha + voltage_power_supply / 2;
    float ub = (sqrtf(3)*u_beta - u_alpha) / 2 + voltage_power_supply / 2;
    float uc = (-u_alpha - sqrtf(3)*u_beta) / 2 + voltage_power_supply / 2;

    // 输出PWM
    set_pwm(ua, ub, uc);
}

{
    float a = fmodf(angle, 2 * PI);
    return a >= 0 ? a : (a + 2 * PI);
}
```

## 第三步：PI控制器照搬DengFOC，必须带积分限幅
你之前失控的核心原因之一就是PI没有积分限幅，误差一持续就积分饱和飞转。直接抄DengFOC的PID实现，只保留PI，去掉D项。

### PI控制器完整实现
```c
typedef struct {
    float P;
    float I;
    float limit;       // 输出/积分限幅值
    float integral_prev;
    float error_prev;
    float output_prev;
    uint32_t timestamp_prev;
} PI_T;

void pi_init(PI_T *pi, float p, float i, float limit)
{
    pi->P = p;
    pi->I = i;
    pi->limit = limit;
    pi->integral_prev = 0;
    pi->error_prev = 0;
    pi->output_prev = 0;
    pi->timestamp_prev = esp_timer_get_time(); // 微秒时间戳
}

float pi_run(PI_T *pi, float error)
{
    uint32_t now = esp_timer_get_time();
    float Ts = (now - pi->timestamp_prev) * 1e-6f;
    if(Ts <= 0 || Ts > 0.5f) Ts = 1e-3f; // 异常保护

    // 比例项
    float proportional = pi->P * error;

    // 梯形积分（Tustin）+ 积分硬限幅
    float integral = pi->integral_prev + pi->I * Ts * 0.5f * (error + pi->error_prev);
    integral = _constrain(integral, -pi->limit, pi->limit); // 核心：积分不会无限堆

    // PI输出 + 输出限幅
    float output = proportional + integral;
    output = _constrain(output, -pi->limit, pi->limit);

    // 保存历史值
    pi->integral_prev = integral;
    pi->error_prev = error;
    pi->output_prev = output;
    pi->timestamp_prev = now;

    return output;
}
```

## 一、先纠正一个误区：“同步”≠“同时采到”，而是“每次配对关系固定”

### 两种延迟的本质区别
| 延迟类型 | 对FOC的影响 | 对应场景 |
| :--- | :--- | :--- |

- 第1个电流周期用的是0μs前的角度，第20个用的是950μs前的角度；

你用的是「完整双环+交叉解耦」的高性能FOC架构，这套架构对相位误差极其敏感；而DengFOC走的是「单Iq环+无解耦+Ud强制为0」的极简路线，**主动降低了性能上限，换来了极高的相位容错率**。

### 1. 没有交叉解耦，就不会“补偿变干扰”
交叉解耦项（`-ωLqIq`、`ωLdId`）是一把双刃剑：
- 角度同步精准时，它能抵消耦合扰动，大幅提升电流环带宽；
- 角度有偏差时，它本身就会变成一个错误的前馈电压，反而给系统注入额外扰动，甚至形成正反馈。

DengFOC直接砍掉了解耦，Uq完全靠PI硬扛耦合电压。
- 好处：角度有偏差时，只会导致Iq静差变大、电机效率变低，**绝对不会直接发散**；
- 代价：动态响应慢、高速性能差，但低速小功率场景完全够用。

你之前的问题，很大程度上是“强行上了解耦，但时序配不上”，解耦项不仅没干活，反而成了失控的放大器。

### 2. 砍掉D轴闭环，消除轴间串扰的放大效应
完整双环FOC里，d轴和q轴是强耦合的：角度偏了，q轴的电流会串到d轴，d轴PI输出又会反过来影响q轴，两个环互相拉扯，误差被二次放大。

DengFOC直接`Ud = 0`，完全不控制d轴，从根源上杜绝了轴间串扰。
- 哪怕角度偏了，也只有Iq一个环在工作，误差不会被d轴放大；
- 系统自由度从2阶降到1阶，稳定性天然高一个等级，对相位偏差的容忍度大幅提升。

---

## 三、低控制带宽，天然抵消了相位滞后的影响
从控制理论上讲，**系统带宽越低，对相位滞后的容忍度就越高**。DengFOC的实际控制带宽很低，刚好匹配它的时序水平。

### 算一笔账：DengFOC的实际带宽有多低
Arduino单循环里，读一次AS5600 I2C约100μs，读两路ADC约几十μs，加上三角函数计算，一圈下来至少几百微秒；再加上它的Iq反馈带了5ms时间常数的低通滤波：
- 实际控制频率：约1~2kHz
- 实际电流环带宽：仅几百Hz

几百Hz的带宽，意味着几百微秒的相位滞后占比非常小，对相位裕度的影响微乎其微，系统完全可以稳定。

打个通俗的比方：
- 你慢走的时候，眼睛看到路，大脑反应，脚迈出去，延迟几百毫秒也不会摔；
- 你跑百米冲刺的时候，延迟几十毫秒都可能踩空摔倒。

你之前的做法，相当于用20kHz的控制频率、往高带宽去调PI参数，却配了一个1kHz的角度采样，相当于“用百米冲刺的速度跑，却戴着延迟半秒的VR眼镜”，不摔才怪。

---

## 四、单核串行无抢占，消除了“随机抖动”这个最大杀手
FOC控制系统最怕的不是“固定延迟”，而是**随机抖动**。

### DengFOC的时序确定性
Arduino是单核单线程，没有RTOS任务抢占，没有内核间通信：
- 每次循环的执行时间基本固定，抖动只有微秒级；
- 角度和电流的采样间隔永远一致，相位差恒定；
- PI控制器面对的是一个确定性的系统，参数整定一次就一直有效。

### 你之前架构的时序随机性
ESP32双核+FreeRTOS，ADC任务在CPU1，FOC任务在CPU0：
- 任务调度优先级、上下文切换、信号量等待，都会引入几十~几百微秒的随机延迟；
- 这次电流和角度差100μs，下次可能差500μs，相位差是跳变的；
- 这种随机扰动会持续冲击PI，积分项来回波动，很容易触发饱和和振荡。

固定的偏差永远可以通过校准、滤波、PI补偿掉；随机的偏差无迹可寻，是控制系统的噩梦。

---

## 五、最后一道保险：PI积分限幅，让“不准”不会变成“失控”
就算角度有偏差、Iq有持续静差，DengFOC的PID也有两道保险：
1. **积分项硬限幅**：积分最多累到输出限幅值，不会无限堆积；
2. **输出电压限幅**：Uq最大就是母线电压的一半，不会无限升高。

所以哪怕角度不准、电流控制精度差，最坏结果也就是“电流没到给定值、电机力气小一点”，绝对不会出现“输出越来越猛、转速无限飙升”的恶性死循环。

而你之前只有输出限幅、没有积分限幅，一旦误差持续存在，积分就会像滚雪球一样越堆越大，最终把系统彻底推到正反馈里。

---

## 总结：为什么它行你不行
### DengFOC的成功公式
**极简低要求的控制架构 + 同频固定的串行时序 + 低带宽鲁棒设计 + 完整的限幅保护**
= 牺牲了高速性能和控制精度，换来了极强的容错性和稳定性，小功率低速场景完全够用。

### 你的失败公式
**高要求的双环解耦架构 + 异频随机的跨核时序 + 高带宽PI参数 + 缺失的积分限幅**
= 性能目标定得很高，但底层时序完全配不上，所有设计互相冲突，最终从根上失控。

### 一句话说透
不是“单循环违背了FOC同步原理”，而是**它用极简设计主动降低了同步门槛**，让“不够完美的同步”也足以稳定工作；而你上了全套高性能配置，却没配上对应的同步时序，自然一跑就炸。
