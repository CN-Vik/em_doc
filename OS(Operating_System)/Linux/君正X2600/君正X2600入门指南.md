刚上手君正 X2600，**不要一开始就啃全部源码**。你要把它当成一个“小型嵌入式 Linux 平台 + 实时控制小核”的系统，而不是传统单片机工程。

X2600 官方描述里，核心结构是 **XBurst2 计算核心 + Victory0 RISC-V 控制核心 + XBurst0**，其中 XBurst2 更偏 Linux 应用/系统计算，Victory0 更偏实时控制；芯片还集成 DDR3、显示、摄像头、SDIO/SPI 等外设接口。([君正][1])

## 1. 先建立正确认识：X2600 不是普通 MCU

你之前做 MCU，通常是：

```text
main.c
  ↓
编译成一个固件
  ↓
烧进 Flash
  ↓
CPU 从 Reset_Handler 开始跑
```

但 X2600 这类芯片更像：

```text
BootROM
  ↓
U-Boot / Bootloader
  ↓
Linux Kernel
  ↓
RootFS 文件系统
  ↓
应用程序 / 服务 / 驱动
```

如果还用小核/RTOS，则可能还有：

```text
Linux 大核负责应用、文件系统、网络、显示
实时小核负责电机、传感器、低延迟控制、功耗控制
```

所以你上手时，先别想着“我加个 .c 文件就能跑”。你要先搞清楚：

```text
我现在改的是 bootloader？
还是 kernel？
还是 rootfs？
还是 app？
还是 libmcu/小核固件？
```

## 2. 你当前 SDK 目录可以这样理解

你之前的目录大概是：

```text
x2600/
├── bootloader
├── build
├── buildroot
├── kernel
├── libmcu
├── module_driver
├── package
├── tools
├── demos
├── wireless
...
```

建议你先按这个方式理解：

| 目录              | 新手理解                           |
| --------------- | ------------------------------ |
| `bootloader`    | 类似 MCU 的启动代码，但更复杂，负责加载 Linux   |
| `kernel`        | Linux 内核，驱动、设备树、调度、文件系统等核心     |
| `buildroot`     | 用来生成 rootfs，也就是板子上的 Linux 文件系统 |
| `build`         | 总控构建目录，通常有配置、Makefile、产品选择     |
| `tools`         | 交叉编译器、烧录工具、打包工具                |
| `libmcu`        | 很可能是给 X2600 的实时小核/MCU 子系统用的    |
| `module_driver` | 独立内核模块或外设驱动                    |
| `demos`         | 示例应用，新手最应该先跑这里                 |
| `package`       | 应用/库/服务的打包配置                   |

你现在最应该先搞懂的是：

```text
build 目录怎么选板子、怎么编译、怎么生成固件
tools 目录里面有哪些交叉编译器
kernel 里面设备树和驱动怎么对应硬件
buildroot 怎么把应用放进文件系统
libmcu 是不是给实时小核单独编译的
```

## 4. 第二阶段：搞懂“编译出来的东西是什么”

X2600 的完整固件通常不是一个 `.bin` 就完事，可能会包含：

```text
bootloader 镜像
kernel 镜像
dtb 设备树
rootfs 文件系统
应用程序
小核固件
整体升级包
```

你要学会找编译产物：

```bash
find . -name "*.bin"
find . -name "*.img"
find . -name "*.dtb"
find . -name "uImage" -o -name "zImage" -o -name "vmlinux"
```

看到这些东西后，你要这样理解：

| 文件                                 | 作用            |
| ---------------------------------- | ------------- |
| `u-boot.bin` / `bootloader.bin`    | 启动 Linux 前用   |
| `uImage` / `zImage` / `vmlinuz`    | Linux 内核      |
| `.dtb`                             | 设备树，描述板子硬件    |
| `rootfs.ext4` / `squashfs` / `ubi` | Linux 根文件系统   |
| `.img`                             | 可能是厂家打包后的整体固件 |

## 6. 第四阶段：先跑 demo，不要直接改 kernel

新手最容易犯的错是：一上来就改 kernel、改驱动、改设备树。

推荐顺序是：

```text
1. 跑官方 demo
2. 编译一个 hello world
3. 放进 rootfs
4. 板子上运行
5. 再学驱动
6. 最后再改 kernel/device tree
```

比如先写一个最简单应用：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello X2600!\n");
    return 0;
}
```

用交叉编译器编译：

```bash

```

然后放到板子上运行。可以用：

```bash
scp hello root@板子IP:/tmp/
```

或者通过 U 盘、TF 卡、NFS、ADB、串口传输，具体看 SDK/板子支持什么。

板子上执行：

```bash
chmod +x /tmp/hello
/tmp/hello
```

如果能打印：

```text
Hello X2600!
```

说明你已经迈过很关键的一步：**能自己编译用户态程序并在板子上跑起来。**

## 7. 第五阶段：搞懂应用、驱动、设备树三者关系

嵌入式 Linux 里经常是这样：

```text
应用程序
  ↓ open/read/write/ioctl
/dev/xxx 设备节点
  ↓
Linux 驱动
  ↓
设备树描述硬件资源
  ↓
真实硬件寄存器
```

比如一个 GPIO 按键，在 Linux 里可能是：

```text
设备树里描述 GPIO 引脚
  ↓
kernel 中 gpio-keys 驱动匹配
  ↓
生成 input 设备
  ↓
应用读取 /dev/input/eventX
```

这和 MCU 完全不同。

MCU 里你可能直接：

```c
gpio_input_bit_get(GPIOA, GPIO_PIN_0);
```

Linux 里更多是：

```c
fd = open("/dev/input/event0", O_RDONLY);
read(fd, &event, sizeof(event));
```

所以你要慢慢接受这个变化：

```text
MCU：应用直接控制寄存器
Linux：应用通常不直接碰寄存器，而是通过驱动/设备节点访问硬件
```

## 8. 第六阶段：弄清楚 X2600 的大核和小核分工

X2600 官方页面提到 XBurst2 是 MIPS compute core，Victory0 是 RISC-V control core。([君正][1])

你可以先按这个思路理解：

```text
XBurst2 / Linux 大核：
- UI
- 网络
- 文件系统
- 摄像头
- 显示
- 多媒体
- 上层应用
- 复杂算法

RISC-V / 实时控制小核：
- 传感器实时采样
- 电机控制
- 低功耗管理
- 快速中断响应
- 一些安全/控制任务
```

但是具体项目怎么用，要看厂家的 SDK。你的 `libmcu` 很可能就和小核相关。

你可以重点查：

```bash
tree -L 2 libmcu
find libmcu -iname "*readme*" -o -iname "*.md"
find libmcu -iname "*riscv*" -o -iname "*mcu*" -o -iname "*rtos*"
```

# 二、最简单：编译一个 Linux 应用程序运行

## 1. 进入 SDK 目录

```bash
cd ~/project/x2600
```

## 2. 找交叉编译器

你之前已经有这个路径：

```bash
~/project/x2600/tools/toolchains/mips-xburst2-gcc720-glibc238/bin
```

先看看里面有什么：

```bash
ls tools/toolchains/mips-xburst2-gcc720-glibc238/bin | grep gcc
```

你可能会看到类似：

```text
mips-linux-gnu-gcc
mipsel-linux-gnu-gcc
mips-linux-uclibc-gnu-gcc
```

具体名字以你电脑显示为准。

---

## 3. 把工具链加入 PATH

```bash
export PATH=$PWD/tools/toolchains/mips-xburst2-gcc720-glibc238/bin:$PATH
```

这句话的意思是：

```text
告诉 Linux：
以后输入 gcc 类命令时，优先去君正 SDK 的工具链目录里找。
```

然后检查：

```bash
which mips-linux-gnu-gcc
```

如果你的工具链名字不是 `mips-linux-gnu-gcc`，就换成你 `ls` 看到的那个。

---

## 4. 写一个测试程序

```bash
mkdir -p ~/project/x2600/my_app
cd ~/project/x2600/my_app
vim hello.c
```

写入：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello X2600!\n");
    return 0;
}
```

---

## 5. 交叉编译

假设你的工具链叫：

```bash
mips-linux-gnu-gcc
```

那就执行：

```bash
mips-linux-gnu-gcc hello.c -o hello
```

如果你不确定板子 rootfs 里面有没有对应动态库，可以先静态编译：

```bash
mips-linux-gnu-gcc hello.c -o hello -static
```

编译完检查文件类型：

```bash
file hello
```

你应该看到类似：

```text
ELF 32-bit LSB executable, MIPS
```

这就说明它是给 X2600 这种 MIPS 平台跑的，不是给你 PC 跑的。

```bash
scp hello root@板子IP:/tmp/
```

比如：

```bash
scp hello root@192.168.1.100:/tmp/
```

然后登录板子：

```bash
ssh root@192.168.1.100
```

在板子上运行：

看到：

```text
Hello X2600!
```

# 三、如果你要编译整个 SDK 固件

这个就是完整系统编译，通常会编译：

```text
u-boot / bootloader
```

然后在类似 `out/product/板级/image/` 目录下生成烧录文件。君正文档里也有类似流程：先 `source build/envsetup.sh`，再 `lunch` 选择开发板，然后 `make`，最后在 `out/product/.../image/` 下面生成烧录需要的 `system`、`uboot`、`kernel` 等文件。([ingenic.com.cn][1])

```text
├── README
├── buildall.sh

...
```

所以你这个工程更可能这样操作：

```bash
cd ~/project/x2600/build
cat README
```

再看支持什么命令：

```bash
./buildall.sh -h
```

或者：

```bash
make help
```

如果 `buildall.sh` 是总编译脚本，常见形式可能是：

```bash
./buildall.sh
```

如果是 Makefile 控制，也可能是：

```bash
make 2>&1 | tee build.log
```

# 五、X2600 烧录一般用什么工具？

君正 X 系列一般用 **USBCloner / cloner** 这类 USB 烧录工具。君正 X2600 Linux V2.0 发布说明里提到：工程默认不下载烧录工具，需要单独下载，烧录工具版本更新到 `cloner-2.5.37-ubuntu_alpha`。([ingenic.com.cn][2])

早期君正 USB Cloner 说明里也提到，它包含 `cloner.exe` 图形界面、`core.exe` 核心程序等，烧录固件基于标准 U-Boot。([ingenic.com.cn][3])

所以你要在 SDK 或资料包里找这些东西：

```bash
find ~/project/x2600 -iname "*cloner*"
find ~/project/x2600 -iname "*burn*"
find ~/project/x2600 -iname "*usb*"
find ~/project/x2600 -iname "*flash*"
```

如果 SDK 里没有，就说明烧录工具可能要单独下载。

# 六、烧录的大概流程

不同板子按键不一样，但流程通常是：

```text
1. 编译生成烧录镜像
2. 打开 USBCloner / cloner
3. 选择板级配置
4. 选择要烧录的镜像文件
5. 板子进入 USB 烧录模式
6. PC 识别到 USB 设备
7. 点击 Start / Run 开始烧录
8. 烧录完成后重启板子
9. 串口查看启动日志
```

板子进入烧录模式通常需要：

```text
按住 BOOT 键 / USB_BOOT 键
插 USB
再松开
```

也有板子是拨码开关选择 USB Boot。

你需要找板子的说明书确认具体按键。

# 七、烧录前必须接串口

烧录成功不代表系统启动成功。你一定要接串口看日志。

常见串口参数：

```text
波特率：115200
数据位：8
停止位：1
校验：无
流控：无
```

Ubuntu 下可以用：

```bash
sudo apt install minicom
sudo minicom -D /dev/ttyUSB0 -b 115200
```

或者：

```bash
sudo apt install picocom
sudo picocom -b 115200 /dev/ttyUSB0
```

如果没有权限：

```bash
sudo usermod -aG dialout $USER
```

然后重新登录系统。

# 1. MCU 工程和嵌入式 Linux 最大区别

你以前做 MCU，大概是这样：

```text
main.c
  ↓
编译
  ↓
生成一个 .hex / .bin
  ↓
烧进 Flash
  ↓
CPU 复位后从 Reset_Handler 跑
  ↓
进入 main()
```

所以 MCU 工程核心是：

```text
启动文件 + 外设驱动 + main函数 + RTOS可选
```

但是嵌入式 Linux 是这样：

```text
BootROM
  ↓
Bootloader，比如 U-Boot
  ↓
Linux Kernel
  ↓
设备树 DTB
  ↓
RootFS 根文件系统
  ↓
应用程序 / 后台服务 / Shell
```

所以嵌入式 Linux 不是一个单独的 `main.c`，而是很多部分组合起来。

---

# 2. 嵌入式 Linux 系统整体组成

可以先记这张图：

```text
┌────────────────────────────┐
│        应用层 App           │
│  你的业务程序、UI、网络服务  │
└─────────────▲──────────────┘
              │ open/read/write/ioctl
┌─────────────┴──────────────┐
│        RootFS 根文件系统     │
│ /bin /lib /etc /dev /proc   │
└─────────────▲──────────────┘
              │
┌─────────────┴──────────────┐
│        Linux Kernel         │
│  进程调度、内存、驱动、文件系统 │
└─────────────▲──────────────┘
              │
┌─────────────┴──────────────┐
│        Device Tree 设备树    │
│  描述板子硬件：GPIO/I2C/SPI等 │
└─────────────▲──────────────┘
              │
┌─────────────┴──────────────┐
│        Bootloader           │
│  初始化DDR，加载kernel/rootfs │
└─────────────▲──────────────┘
              │
┌─────────────┴──────────────┐
│        BootROM              │
│  芯片内部固化启动程序         │
└────────────────────────────┘
```

每一层都有自己的作用。

---

# 3. BootROM 是什么？

BootROM 是芯片内部固化的一小段程序。

这个东西在芯片出厂时就写死了，用户一般不能改。

它的作用类似：

```text
芯片上电
  ↓
内部 BootROM 开始运行
  ↓
判断从哪里启动
  ↓
从 NAND / NOR / eMMC / SD卡 / USB 加载下一阶段程序
```

在 MCU 里你可能也见过类似东西，比如 STM32 的系统 Bootloader，可以通过串口/USB 下载程序。

对 X2600 这类芯片来说，BootROM 的作用就是把第一个可执行启动程序加载起来。

这个第一个程序通常就是：

```text
U-Boot / Bootloader
```

---

# 4. Bootloader 是什么？

Bootloader 可以理解成 Linux 系统的“启动管家”。

它负责：

```text
初始化 DDR
初始化基础时钟
初始化 Flash / eMMC / NAND
加载 Linux Kernel
加载设备树 DTB
传递启动参数
启动 Linux 内核
```

在 MCU 里，Bootloader 可能只是负责 OTA 或跳转 APP。

但在嵌入式 Linux 里，Bootloader 重要得多。因为 Linux 内核运行前，DDR、Flash、启动参数这些都要准备好。

常见 Bootloader 是：

```text
U-Boot
```

启动过程大概是：

```text
BootROM
  ↓
U-Boot
  ↓
读取 kernel
  ↓
读取 dtb
  ↓
传递 bootargs
  ↓
跳转到 Linux Kernel
```

---

# 5. Linux Kernel 是什么？

Kernel 就是 Linux 内核。

你可以把它理解为整个系统的“大脑和管理者”。

它负责：

```text
任务调度
内存管理
中断管理
驱动管理
文件系统
网络协议栈
进程管理
权限管理
设备抽象
```

在 MCU 中，很多东西是你自己直接控制：

```c
GPIO_SetBits();
USART_SendData();
SPI_Transmit();
```

但在 Linux 里，普通应用一般不直接操作寄存器，而是通过内核提供的接口访问硬件。

例如：

```text
应用程序
  ↓
open("/dev/ttyS0")
  ↓
Linux 串口驱动
  ↓
UART 控制器寄存器
```

也就是说：

```text
MCU：应用直接操作硬件
Linux：应用通过驱动间接操作硬件
```

---

# 6. Device Tree 设备树是什么？

设备树是新手最容易懵的地方。

你可以这样理解：

**Linux Kernel 是通用代码，Device Tree 是板子的硬件说明书。**

比如同样一个 X2600 芯片，不同厂家板子的硬件可能不一样：

```text
板子A：
I2C0 接触摸芯片
UART1 接调试串口
GPIOA5 接按键
LCD 用某个屏幕

板子B：
I2C1 接触摸芯片
UART2 接调试串口
GPIOB3 接按键
LCD 用另一个屏幕
```

Linux 内核代码不能为每个板子都写死一份，所以用设备树描述硬件。

设备树里面会描述：

```text
这个外设是否启用
使用哪些 GPIO
中断号是多少
时钟源是什么
I2C 地址是多少
SPI 片选是哪一个
LCD 分辨率是多少
Flash 分区怎么划分
```

设备树源码通常是：

```text
.dts
.dtsi
```

编译后变成：

```text
.dtb
```

关系是：

```text
xxx.dts / xxx.dtsi
  ↓ 编译
xxx.dtb
  ↓
Bootloader 加载给 Linux Kernel
  ↓
Kernel 根据 dtb 匹配驱动
```

简单理解：

```text
Kernel：我有很多驱动
Device Tree：告诉 Kernel 当前板子上有哪些硬件
```

---

# 7. RootFS 根文件系统是什么？

RootFS 全称是 Root File System，根文件系统。

它就是 Linux 启动后看到的 `/` 目录。

比如你登录板子之后看到：

```text
/
├── bin
├── sbin
├── etc
├── lib
├── usr
├── dev
├── proc
├── sys
├── tmp
```

这些都属于 rootfs。

它里面放的是：

```text
Linux 命令
动态库
配置文件
启动脚本
应用程序
设备节点
系统服务
```

比如：

| 目录      | 作用                 |
| ------- | ------------------ |
| `/bin`  | 常用命令，比如 `ls`、`cat` |
| `/sbin` | 系统管理命令             |
| `/etc`  | 配置文件               |
| `/lib`  | 动态库                |
| `/dev`  | 设备节点               |
| `/proc` | 内核运行信息             |
| `/sys`  | 设备和驱动信息            |
| `/usr`  | 用户程序和库             |
| `/tmp`  | 临时文件               |

在 MCU 里通常没有完整文件系统，最多是 Flash 分区、FATFS、LittleFS。

但 Linux 一定需要 rootfs。

没有 rootfs，Linux Kernel 即使启动了，也不知道接下来运行什么程序。

Linux 启动后通常会运行：

```text
/sbin/init
```

或者：

```text
linuxrc
init
systemd
busybox init
```

这些就是用户态第一个进程。

---

# 8. BusyBox 是什么？

很多嵌入式 Linux 系统都会用 BusyBox。

它可以理解为一个“命令大礼包”。

正常桌面 Linux 里，`ls`、`cat`、`cp`、`mount`、`ifconfig` 这些命令都是独立程序。

但嵌入式设备空间有限，所以 BusyBox 把很多命令打包成一个小程序。

比如：

```text
/bin/ls      -> busybox
/bin/cat     -> busybox
/bin/sh      -> busybox
/bin/mount   -> busybox
```

所以很多嵌入式板子的 shell、基本命令，都是 BusyBox 提供的。

---

# 9. 应用程序是什么？

应用程序就是你最终写业务逻辑的地方。

比如：

```text
摄像头采集程序
屏幕显示程序
网络通信程序
音频播放程序
OTA 升级程序
传感器数据处理程序
工厂测试程序
守护进程
```

应用程序运行在 Linux 用户态。

它一般不直接操作寄存器，而是通过这些方式访问硬件：

```text
/dev/xxx
/sys/xxx
/proc/xxx
socket
ioctl
read/write
mmap
```

比如：

```text
串口：/dev/ttyS0
I2C：/dev/i2c-0
SPI：/dev/spidev0.0
输入设备：/dev/input/event0
Framebuffer：/dev/fb0
音频：/dev/snd/xxx
```

所以 Linux 应用开发和 MCU 最大区别是：

```text
MCU 程序：直接控制外设
Linux 应用：调用系统接口，让驱动控制外设
```

---

# 10. 驱动是什么？

驱动是 Linux 内核里直接操作硬件的代码。

它负责把硬件抽象成 Linux 标准接口。

比如：

```text
UART 驱动
I2C 驱动
SPI 驱动
GPIO 驱动
LCD 驱动
Camera 驱动
Audio 驱动
MMC/SDIO 驱动
WiFi 驱动
NAND/eMMC 驱动
```

驱动和应用之间通常通过设备节点通信：

```text
应用程序
  ↓ open/read/write/ioctl
/dev/xxx
  ↓
Linux 驱动
  ↓
硬件寄存器
```

比如你要控制一个 LED：

在 MCU 里可能是：

```c
gpio_bit_set(GPIOA, GPIO_PIN_5);
```

在 Linux 里可能变成：

```text
应用写 /sys/class/gpio/xxx
  ↓
Linux GPIO 子系统
  ↓
GPIO 控制器驱动
  ↓
真实 GPIO 寄存器
```

# 11. Buildroot 是什么？

你的 X2600 SDK 里有 `buildroot`。

Buildroot 是一个“嵌入式 Linux 系统生成工具”。

它可以帮你生成：

```text
交叉编译工具链
第三方库
BusyBox
rootfs
应用程序包
系统镜像
```

你可以理解为：

```text
Buildroot = 用来制作嵌入式 Linux rootfs 的工具
```

比如你需要系统里支持：

```text
openssl
curl
alsa
wifi 工具
busybox
dropbear ssh
sqlite
```

这些都可以通过 Buildroot 配置进去。

最后 Buildroot 会生成 rootfs，例如：

```text
rootfs.ext4
rootfs.squashfs
rootfs.tar
rootfs.ubi
system.img
```

# 12. 交叉编译工具链是什么？

这是嵌入式 Linux 的核心概念。

你的电脑 CPU 是 x86_64。

X2600 主核可能是 MIPS/XBurst 架构。

所以你不能用电脑上的普通 `gcc` 编译程序给板子跑。

普通 gcc 编译出来的是：

```text
x86_64 程序，只能在 PC 上跑
```

交叉编译器编译出来的是：

```text
MIPS/XBurst 程序，可以在 X2600 上跑
```

关系是：

```text
PC Ubuntu
  ↓ 使用交叉编译器
生成 X2600 可执行程序
  ↓
放到板子上运行
```

所以你会看到 SDK 里面有：

```text
tools/toolchains/xxx
```

这个目录就是工具链。

---

# 13. 编译整个嵌入式 Linux，到底是在编译什么？

编译整个系统，不是只编译一个东西，而是编译很多东西。

大概包括：

```text
1. Bootloader
2. Linux Kernel
3. Device Tree
4. Kernel Modules
5. RootFS
6. BusyBox
7. 第三方库
8. 应用程序
9. 小核固件，如果有
10. 最终烧录镜像
```

可以这样理解：

```text
完整 SDK 编译
  ├── 编译 bootloader
  ├── 编译 kernel
  ├── 编译 dts 生成 dtb
  ├── 编译驱动模块
  ├── 编译 rootfs
  ├── 编译应用程序
  ├── 打包分区镜像
  └── 生成烧录文件
```

所以编译时间会比 MCU 长很多。

MCU 编译可能几十秒，嵌入式 Linux 首次编译可能几十分钟甚至更久。

---

# 14. 编译后会生成哪些东西？

一般会有这些产物：

```text
uboot
kernel
dtb
rootfs
system
recovery
userdata
整体 img
```

不同厂家的命名不一样。

你可以先按这个理解：

| 产物                             | 作用                     |
| ------------------------------ | ---------------------- |
| `uboot` / `u-boot.bin`         | 启动 Linux 前的 bootloader |
| `kernel` / `uImage` / `zImage` | Linux 内核               |
| `xxx.dtb`                      | 板级硬件描述                 |
| `rootfs.*`                     | 根文件系统                  |
| `system.*`                     | 系统分区镜像                 |
| `userdata.*`                   | 用户数据分区                 |
| `recovery.*`                   | 恢复模式镜像                 |
| `*.img`                        | 打包后的烧录镜像               |

你可以把它类比成手机刷机包：

```text
bootloader 分区
kernel 分区
system 分区
rootfs 分区
data 分区
```

不是一个 `.hex` 文件烧到底。

# 15. 烧录到底是在烧什么？

烧录整个嵌入式 Linux 系统，本质是把这些镜像写入板子的 Flash/eMMC/NAND 对应分区。

比如：

```text
Flash / eMMC / NAND
├── bootloader 分区
├── kernel 分区
├── dtb 分区
├── rootfs/system 分区
├── userdata 分区
└── config 分区
```

烧录工具要做的事情是：

```text
连接板子
  ↓
让板子进入下载模式
  ↓
把 bootloader 写到 bootloader 分区
  ↓
把 kernel 写到 kernel 分区
  ↓
把 rootfs/system 写到系统分区
  ↓
写入分区表/配置
  ↓
重启板子
```

这和 MCU 烧录最大的区别是：

```text
MCU：通常烧一个固件到固定 Flash 地址
Linux：通常烧多个镜像到多个分区
```

# 16. 为什么需要 cloner / USBCloner 这种工具？

因为嵌入式 Linux 不是简单烧一个 bin。

烧录工具需要知道：

```text
芯片型号
Flash 类型
分区表
每个镜像烧到哪个分区
DDR 初始化参数
启动方式
NAND/eMMC/SPI NOR 参数
```

所以厂商通常会提供专用烧录工具。

对于君正平台，这类工具通常叫：

```text
cloner
USBCloner
```

它的作用类似：

```text
J-Link + 烧录算法 + 分区烧录工具 + 下载模式工具
```

MCU 你可能用：

```text
J-Link
ST-Link
DAP-Link
串口 ISP
```

X2600 这种 Linux 芯片通常用厂商 USB 烧录工具。

# 17. 烧录完成后为什么还要看串口？

因为烧录成功，只代表镜像写进 Flash 了。

但是系统能不能启动，还要看：

```text
Bootloader 有没有起来
Kernel 有没有起来
设备树对不对
rootfs 能不能挂载
init 能不能运行
驱动有没有报错
应用有没有启动
```

所以烧录后必须看串口日志。

串口日志大概分阶段：

```text
第一阶段：BootROM / USB boot 信息
第二阶段：U-Boot 启动信息
第三阶段：Linux Kernel 启动信息
第四阶段：RootFS/init 启动信息
第五阶段：应用启动信息
```

如果卡住，你要判断卡在哪一层。

比如：

```text
没有任何串口输出：
可能电源、串口、BootROM、bootloader 问题

只有 U-Boot，没有 Kernel：
可能 kernel 镜像、启动参数、Flash 分区问题

Kernel 启动后 panic：
可能设备树、rootfs、驱动问题

进入 shell 但应用没跑：
可能 init 脚本、应用路径、权限、库依赖问题
```

# 18. X2600 这种 SDK 大概怎么组织？

你之前的目录是类似：

```text
x2600/
├── bootloader
├── build
├── buildroot
├── kernel
├── libmcu
├── module_driver
├── package
├── tools
├── demos
├── wireless
└── ...
```

可以这样理解：

| 目录              | 作用                 |
| --------------- | ------------------ |
| `bootloader`    | U-Boot / 启动相关      |
| `kernel`        | Linux 内核和驱动        |
| `buildroot`     | 生成 rootfs          |
| `build`         | 总编译控制系统            |
| `tools`         | 交叉编译器、打包工具、烧录相关工具  |
| `package`       | 应用包、库包、系统组件        |
| `module_driver` | 外部内核模块             |
| `libmcu`        | 小核/实时核相关代码，具体看 SDK |
| `demos`         | 示例程序               |
| `wireless`      | WiFi/蓝牙相关组件        |

所以你编译整个系统时，实际上是总控 `build` 去调用：

```text
bootloader 编译
kernel 编译
buildroot 编译
package 编译
镜像打包
```

# 19. “编译”和“烧录”的关系

这两个不要混在一起。

## 编译

编译发生在你的开发电脑上。

作用是：

```text
源码
  ↓
交叉编译
  ↓
生成适合 X2600 运行的二进制文件和镜像
```

比如生成：

```text
uboot
kernel
dtb
rootfs
system.img
```

## 烧录

烧录是把编译出来的镜像写到板子的存储器里。

作用是：

```text
镜像文件
  ↓
cloner / USB 烧录工具
  ↓
写入板子的 NAND/eMMC/NOR
```

所以流程是：

```text
先编译
后烧录
再启动
再看日志
```

---

# 20. 以后你改不同东西，对应的编译烧录影响不同

这个很重要。

| 你修改的内容      | 影响          | 是否需要整机烧录        |
| ----------- | ----------- | --------------- |
| 普通应用程序      | 只影响用户态程序    | 不一定，可以直接拷到板子    |
| rootfs 里的配置 | 影响系统文件      | 通常要重打 rootfs    |
| kernel 驱动   | 影响内核        | 要重新编 kernel     |
| 设备树 dts     | 影响硬件描述      | 要重新生成 dtb       |
| bootloader  | 影响启动阶段      | 要重新烧 bootloader |
| 分区表         | 影响 Flash 布局 | 风险较高，要谨慎        |
| 小核固件        | 影响实时核       | 看 SDK 如何打包      |

刚开始你要特别小心：

```text
不要随便改 bootloader
不要随便改分区表
不要随便改 DDR 参数
```

这些改错，可能板子直接起不来。

# 22. 你现在应该先建立这几个概念

你先把这几个词理解透：

```text
BootROM：芯片内部固化启动程序
Bootloader：加载 Linux 的启动程序
Kernel：Linux 内核
Device Tree：板级硬件描述文件
RootFS：Linux 根文件系统
Buildroot：制作 rootfs 的工具
Toolchain：交叉编译工具链
Image：编译出来的镜像文件
Partition：Flash/eMMC/NAND 分区
Cloner：厂商烧录工具
Serial log：串口启动日志
```

只要这些概念通了，后面你看 X2600 SDK 就不会迷糊。

# 23. 最后用 MCU 方式类比一下

| MCU 世界            | 嵌入式 Linux 世界                  |
| ----------------- | ----------------------------- |
| startup.s         | BootROM + Bootloader          |
| main.c            | init 进程 + 应用程序                |
| 外设初始化代码           | Device Tree + Driver          |
| HAL 库             | Linux 驱动子系统                   |
| Flash 地址表         | 分区表                           |
| `.hex` / `.bin`   | uboot/kernel/rootfs/system 镜像 |
| J-Link/ST-Link 下载 | cloner/USBCloner 烧录           |
| printf 串口调试       | U-Boot/kernel/rootfs 串口日志     |
| RTOS 任务           | Linux 进程/线程                   |
| FATFS             | RootFS                        |
| 中断服务函数            | Linux IRQ handler / driver    |

```text
嵌入式 Linux = Bootloader + Kernel + Device Tree + RootFS + App + 烧录分区
```

```text
一个 main.c 编译成一个 bin
```

# 12. 新手最容易错的地方

第一，**板级选错**。
X2600 要选 `halley7` 相关，X2600E 才是普通 `halley`。官方文档里 X2600 对应 `RD_X2600_HALLEY7_BASEBOARD_V1.0`。([ingenic.com.cn][1])

第二，**在 WSL 里烧录**。
编译可以在 WSL/Ubuntu 里做，但 USB 烧录建议用：

```text
原生 Ubuntu
或者 Windows 版 cloner
```

WSL 访问 USB 设备比较麻烦，容易识别不到板子。

第三，**只看烧录成功，不看串口**。
烧录成功只是 Flash 写进去了，不代表 kernel/rootfs 正常启动。最终要以串口日志为准。

第四，**改了 kernel/rootfs 但没重新 make**。
改完代码后至少重新：

```bash
make -j4
```

再烧录新的 `out/product/板级/image/` 文件。
